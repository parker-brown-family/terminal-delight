⎇ feat/copy-affordance
Planned

▼ ELI5 — tl;dr
💬 comment
💡 Plain English
When an agent prints a long command, the terminal wraps it across several rows. Selecting and copying that gives you a command broken at the seam, which then fails when pasted. This adds a bordered box with a copy button around the line under your cursor, and copying gives you the whole command as one unbroken line. Done looks like: hover a wrapped command, click ⎘, paste, and it runs first try.
▼ The failure, with evidence
💬 comment
⚠️ Four consecutive failures, 2026-08-31
This is not a hunch. In one session, four attempts to move a command from an agent pane into a shell failed, and none of them failed for the same reason twice:
#What was attemptedWhat happened
1Select + paste a jq --slurpfile one-linerPaste broke between automode-env.json and '.autoMode.environment…' — the wrap seam landed mid-argument. Command never ran.
2Agent staged the same command as a shell script to dodge wrappingWorked, but cost an extra file on disk purely to make a paste survivable.
3Operator pasted an illustrative command containing a literal …Could not open /tmp/…/automode-env.json: No such file or directory
4Same paste, retriedIdentical failure. The elided example read as authoritative because nothing marked it as non-runnable.
💬 comment
🔎 What the evidence actually says
Every one of these was a single logical line that the terminal wrapped. Not one was a multi-line code block. That matters enormously for scope: the fix is line reconstruction, not block detection. Failure #3 adds a second, independent requirement — a copy affordance must refuse text that was never meant to run.
▼ Why the obvious approach dies
💬 comment
🚫 Backtick fences are not in the grid
The web-shaped instinct is “find the fenced code block and draw a border round it.” Measured against the live pane via the terminal-delight MCP: the only ``` sequences on screen were ones typed inline inside prose. Claude Code strips fence markers before rendering. A fence detector would fire on cat‘d markdown and never on the agent output that actually needs copying.
💬 comment
🧪 The runner-up, and why it also loses
Next candidate: detect runs of rows sharing a non-default cell background, or carrying multiple syntax-highlight foreground colours. Workable in principle — the grid walk in link_under already holds indexed.cell and reads .flags, so reading .bg/.fg is free. Rejected because it needs an empirical probe to learn what Claude Code paints (TD has no raw-stream dump; TD_KEYDEBUG/TD_HITDEBUG are input-side), and it couples TD's behaviour to one vendor's renderer. Any Claude Code restyle silently breaks it.
💬 comment
📍 And OSC-133 does not help here
Shell integration is item #6 on the competitive roadmap, ranked high value. It is still the wrong tool for this: OSC-133 marks shell prompt / command / output zones. A command printed inside an agent's rendered output sits in one undifferentiated output zone. Worth building; will not fix this.
▼ The design — the detector already exists
💬 comment
✅ Reuse reflow_wrapped_copy as the region detector
reflow_wrapped_copy (app/src/pane.rs:509) already merges rows broken purely by width back into one logical line. Its own doc comment names the case: “TUI agents like Claude Code wrap their own prose and commands to the pane width and emit real line breaks.” It refuses to merge indented, fenced and rule rows, applies a width test so text wrapped at a narrower column is left alone, and it is pure and unit-tested.

The rows it merges into one output line are the copyable region. The boundary detector is already written, already trusted for drag-select copy, and already shipping. It is simply unreachable without a mouse drag.
💬 comment
🔧 What actually has to change
The function returns joined text and discards which rows each line came from. Add a variant that also reports spans. WrapJoin::Break already marks every boundary, so spans fall out of the existing out.push() sites — no new logic, just bookkeeping. 
// app/src/pane.rs — beside its existing pure neighbours

/// One reconstructed logical line and the inclusive grid-row span it
/// was assembled from. The span is what the hover border is drawn around.
struct LogicalLine {
    text: String,
    rows: std::ops::RangeInclusive<usize>,
}

fn reflow_wrapped_copy_spans(rows: &[String], cols: usize) -> Vec<LogicalLine>;

// The existing signature stays, as a thin wrapper, so every current
// caller keeps byte-identical behaviour:
fn reflow_wrapped_copy(text: &str, cols: usize) -> String {
    reflow_wrapped_copy_spans(&split_rows(text), cols)
        .into_iter().map(|l| l.text).collect::<Vec<_>>().join("\n")
}
💬 comment
💣 The one trap that will silently ruin this
link_under builds its grid as vec![vec![' '; cols]; rows] — every row space-padded to full width. Feed that straight into the reflow and row_len reads cols for every row, so the width test passes universally and the entire screen glues into one line. Trim trailing padding per row before reflowing. A drag-selection arrives pre-trimmed, which is why the existing caller never hit this.
💬 comment
🔁 End-to-end path
on_mouse_move (already wired, pane.rs:3834) → viewport_cell → paint_row_to_grid_row → build rows from renderable_content() → trim → reflow_wrapped_copy_spans → find the span containing the hovered row → gate on copyability → paint. Every step but the reflow variant and the gate already exists in link_under.
▼ UX and edge states
💬 comment
🖱️ Hover tints; dwell arms
A naive “show the chip on hover” flattens the CRT warp every time the pointer crosses a command, because the chip is a click target floating over curved glass and must suppress the warp to hit-test honestly. That would strobe the whole screen during ordinary mousing.

So: hover paints a flat tint on the span only — no click target, no suppression, warp stays alive. Dwell (~250 ms) arms the affordance: border plus ⎘ chip appear, warp flattens exactly as it does for any menu. Moving off disarms.
💬 comment
🌀 Register in Pane::popup_open() or repeat this morning's bug
The armed chip must be added to Pane::popup_open() (pane.rs:1909), the predicate Workspace::render folds into warp::set_suppressed. Skipping it reproduces exactly the defect fixed in PR #207: the affordance bows with the barrel warp while gpui hit-tests its flat layout box, so the chip is not where it looks. The hover tint deliberately does not register — it has no click target, so it can bend harmlessly.
💬 comment
🛑 Never offer to copy an elided command
Failure #3 above is its own requirement. A line containing … (U+2026) or a bare …-suffixed path is an illustration, not a command. Offering a copy chip on it manufactures confident failure. Such lines get no chip at all — not a warning, not a disabled state. Silence is the correct affordance for something that should not be copied.
💬 comment
🧵 Remaining edge states
  • Span partially scrolled off — copy the full logical line from the grid, but draw the border only over visible rows.
  • Active drag-selection — suppress the affordance entirely; selection wins.
  • Alt-screen apps (vim, htop) — disabled. Reflow assumes flowed output, and a TUI's rows are a layout, not a wrapped line.
  • Blank / single-row lines — still offered when they pass the copyability gate; a short unwrapped command is a legitimate copy target.
  • Copy target — write to both the system clipboard and X11 PRIMARY, matching copy_selection, so middle-click paste works too.

T-004
Copyability gate, including the elision guard
high

Touches: app/src/pane.rs, pure and unit-tested alongside link_at, which already makes exactly this class of judgement for URLs and paths.

▼ Testing and acceptance
💬 comment
🧪 Where the tests live
Nearly all of this is testable without a live grid, because the interesting logic sits in the pure layer that stitch_wrapped_line, wrap_join and link_at already occupy. That is the reason for the design: the span variant, the padding trim and the copyability gate are all pure functions over Vec<String>.
  • Regression net: every existing reflow_wrapped_copy test passes unmodified.
  • Merge-blob test: full-width padded rows must not collapse into one region.
  • Gate table: real captured lines — prose, commands, prompts, git output, and all four evidence failures.
  • The headline test: the exact jq --slurpfile line that failed four times reconstructs byte-for-byte.
💬 comment
🏁 Done when
Hover a wrapped agent command, dwell, click ⎘, paste into a shell, and it runs first time — with the glass flat while the chip is up and curved the moment it disarms. Plus: cargo test --release, clippy --all-targets and fmt --check all clean.
▼ Deliberately out of scope
💬 comment
✂️ Considered and cut
  • A ▶ run button. Cut by operator decision. Executing agent-printed text with no confirmation step is not a starting point, however tempting the friction saving. The PTY write path exists (notify() at pane.rs:3658) and can be revisited once copy is trusted.
  • Multi-line block regions. The reflow emits a genuine block as several lines separated by Break; grouping consecutive spans is a natural v2. Every observed failure was single-line, so v1 stays single-line.
  • Cell-attribute detection. Needs a probe and couples TD to one vendor's renderer.
  • OSC-133 shell integration. Genuinely valuable, separately tracked, does not address agent-rendered output.
  • Keyboard hint-select. Kitty-style labels are faster once learned but less discoverable, and the ask was explicitly for a visible affordance.

▼ Decisions — questions closed 2026-08-31
💬 comment
✅ D1 — Alt is the gesture. Dwell is dead.
Hold Alt reveals the chip on the copyable line under the pointer; Alt + left click copies it. This is strictly better than the dwell proposal and it deletes work rather than adding it:
  • No dwell timer, no hover-tint stage, no arm/disarm state machine.
  • No per-frame grid recompute during ordinary mousing — the pipeline only runs while Alt is down.
  • It cannot fire by accident, so the “restless pane” risk disappears entirely.
T-005 shrinks from a timer-driven state machine to reading ev.modifiers.alt off the events already arriving.
💬 comment
✅ D2 — Commands only. Strict gate.
Less permissive wins. v1 offers a chip on command-shaped lines only. JSON is explicitly not a target — it carries real line breaks, so the reflow leaves it alone anyway and there is nothing to reconstruct. Prose block copy (an email body, a blog paragraph) is noted as a stretch goal, deliberately not built now: it needs the multi-line region grouping that v1 also defers.
💬 comment
✅ D3 — Warp: flatten while Alt is held. No easing.
D1 answers this by itself. Suppression now follows a deliberate, held modifier rather than a pointer drift, which is the same contract every existing overlay already uses — so it needs no ease-in and no special casing. Glass flattens on Alt-down, returns on Alt-up. Keep it simple.
💬 comment
⚠️ One consequence to handle
Alt is already a live mouse modifier: pane.rs:4684 encodes it into the SGR mouse report sent to the running app. So Alt+click must be intercepted only when a chip is actually showing (Alt held over a line that passes the gate), and otherwise fall through to the app unchanged. Alt+arrows keep owning directional pane nav from PR #200 — untouched, different event path.
