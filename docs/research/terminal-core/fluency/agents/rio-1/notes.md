# rio-vt 0.5.28 probe: notes, in the order I hit them

1. Test input, not the library: icat.bin sends the picture by file path (`a=T,t=f,f=100`). The path it names is `/tmp/claude-1000/.../scratchpad/test.png`, which is outside the workspace, so the result depends on that file still existing on this machine. It did exist (a 640x400 16-bit RGBA PNG). Of its three `a=q` probes, i=1 sends its bytes directly (answered OK). i=2 and i=3 point at a `/dev/shm` temp file and a shm object that do not exist, so their ENOENT replies are correct.
2. My own mistake: I ran `cargo search` and `cargo info` before setting a workspace-local CARGO_HOME, so those two commands updated the index under ~/.cargo. Every command after that used `.cargo-home/` and `target/` inside the workspace.
3. Environment, not the library: this machine's shell guard blocks `source`, custom wrapper scripts and `time`. I passed the environment with `env CARGO_HOME=… CARGO_TARGET_DIR=… cargo …` and timed builds with `date` stamps.
4. `cargo search rio-vt` also lists `librio-vt` (0.5.0-alpha.4, "PTY, VT state, render-state pull API"), a lookalike with a similar description. It is easy to pick the wrong one.
5. README mismatch: the feature table says the default is "(none) … Lean core". Cargo.toml actually has `default = ["pty"]`, which pulls in corcovado and teletypewriter. The table never mentions `pty` or `graphics`.
6. The biggest trap: PNG (`f=100`) decoding needs the undocumented `graphics` feature. Without it, `create_graphic_data` returns InvalidData and the picture is silently dropped. I verified this by building without the feature: zero placements, zero stored images, the cursor stays on row 1, and nothing is logged. I found the requirement only by reading `ansi/kitty_graphics_protocol.rs`.
7. README mismatch: "Receiving events" says `event()` is the only required method of `EventListener` and shows `fn event(&self) -> (Option<RioEvent>, bool)`. The 0.5.28 trait has no `event()` method at all, and all four methods are defaulted, so the README snippet will not compile. The shipped `examples/kitty_image.rs` is correct.
8. README points at `../librio/src/lib.rs` and `../librio/src/render_state.rs` for the full PTY and pull-render setup. Those files are not in the published crate, so they only resolve in the upstream monorepo.
9. Trap I read about in the source but did not hit: the README quickstart's `CrosswordsSize::new(cols, rows)` sets the cell size to 0, and `place_kitty_overlay` returns early without a word when the cell size is 0. You need `CrosswordsSize::new_with_dimensions(cols, rows, w_px, h_px, cell_w, cell_h)` to get any kitty placement.
10. Pleasant surprise: rio-vt turns on parking_lot's `nightly` feature, and I expected that to fail on stable. It built without complaint on stable 1.98.
11. No accessor API for pictures: placements come from the public field `term.graphics.kitty_placements` (a HashMap keyed by (image_id, placement_id)). `dest_row` is stored as an absolute, scrollback-aware row (lines evicted + history + screen row), so I had to convert it to a screen row myself.
12. There is no public per-row text reader. `line_to_string` is private, and `format(FormatOptions::plain())` joins wrapped rows, so I called `bounds_to_string` once per visible row.
13. icat sent `a=T` without `i=`, so rio-vt gave the picture id and placement id 0x80000000 (2147483648). That matches the source comments and the spec, but the number looks surprising in the output.
14. Replies arrive as `RioEvent::PtyWrite(route, String)` through the listener: a String, not bytes. Colour and text-area-size queries arrive as callback events that a frontend has to format. None occurred in this recording, but a harness that only watches PtyWrite would miss them.
15. First successful build: `cargo build --release` took 62 s wall (cargo reported "1m 02s"), from a cold target directory with dependencies already fetched. The probe compiled first try with no errors or warnings. From opening the workspace to that first good build was about 9 minutes, most of it spent reading source.
16. Results: one placement (image 2147483648, row 0, column 0, 64x19 cells, 640x400 px); cursor at row 19, column 0; four replies (kitty OK, two ENOENT, DA1 `ESC[?62;4;6;22;52c`); no visible text. text.bin leaves 10,040 rows held (10,000 history + 40 visible).
