# libghostty-vt 0.2.1 — notes, in the order I hit them

1. crates.io has several lookalike crates (`libghostty` 0.0.0, `mnml-libghostty-vt`, `khostty-vt`, `gpui-libghostty`). I picked `libghostty-vt` 0.2.1 (uzaaft/libghostty-rs), the one the task named.
2. Neither the `libghostty-vt` README nor its crate docs mention that building needs Zig. Only the `-sys` crate README says so, and its build.rs also git-clones Ghostty at a pinned commit, so the build needs network access too.
3. build.rs passes `--global-cache-dir` to Zig only when `GHOSTTY_ZIG_SYSTEM_DIR` is set. Without it, Zig puts its package and build cache (424 MB here) in `~/.cache/zig`. I set `ZIG_GLOBAL_CACHE_DIR` and `ZIG_LOCAL_CACHE_DIR` through `[env]` in `.cargo/config.toml` to keep it in the workspace. Zig also has to be on PATH, because build.rs runs a bare `zig`.
4. My own harness, not the crate: my shell allowlist blocked `time`, so the first build attempt never ran. I retried with `date` timestamps.
5. First successful build (`cargo build --release`, cold, including crate downloads, the Ghostty clone and Zig's ReleaseFast build): 3 min 31 s (212 s wall). Later rebuilds took 2–3 s.
6. `TerminalOptions` has only cols, rows and max_scrollback, with no cell pixel size. The only way to set 10×22 px is to call `resize(120, 40, 10, 22)` straight after `new`. The `resize` doc says "If the dimensions are unchanged, this is a no-op", which suggests the pixel size would be ignored. The Zig source sets it anyway. I found the trick in the kitty-graphics module example, not in the Terminal docs.
7. The crate's own `RustPngDecoder` (behind the `png` feature) cannot be used. It has a private field and no constructor or `Default`, and its doc example calls `RustPngDecoder::new()` and `use ghostty::…`, neither of which exists. Reading its source, the decode step looks broken too: it calls `reserve()` but never sets the length, so `next_frame` gets an empty buffer. I wrote my own 40-line `DecodePng` on the `png` crate.
8. The PNG decoder is a process-global (thread-local) hook, `set_png_decoder`, not a per-terminal setting.
9. icat.bin does not carry the picture inline. It sends `a=T,t=f`, a file path to a 640×400 PNG outside the workspace, and libghostty reads that file while the bytes are fed. The library allows only the direct medium by default, so I had to call `set_kitty_image_from_file_allowed(true)`. The result depends on that file still existing.
10. kitten's temp-file (`t=t`) and shared-memory (`t=s`) probe queries got `EINVAL: unsupported medium`, because I left those two mediums at the library default (off).
11. I never registered `on_device_attributes`, yet the terminal still answered `CSI c` with `ESC[?62;22c`. The Terminal docs list device-attributes queries among the things ignored by default. In practice any `on_pty_write` handler is enough to get a default DA1 reply.
12. kitten sent no `i=`, so the stored image got a terminal-assigned id of 2147483647 (i32::MAX), not 0 or 1.
13. The Rust docs have copy-paste and find-replace slips: `grid_size` is documented as "Compute the rendered pixel size", `placement_id` as "The image ID this placement belongs to", and `rect` repeats the `source_rect` text. A 0→"inner" substitution gives "(inner-indexed)" on `cursor_x`/`cursor_y`, "X1inner" and "OSC inner/2".
14. Once written, the code compiled on the first try. The placement iterator, grid_ref/graphemes and on_pty_write behaved as documented.
15. Biggest surprise: `max_scrollback` is documented in both the Rust docs and the upstream C header (`vt/terminal.h`) as "Maximum number of lines to keep in scrollback history", but the implementation treats it as bytes (Screen.zig: "The maximum size of scrollback in bytes"). With 10_000, text.bin left only 580 history rows (620 total), because the budget is rounded up to a two-page minimum.
16. No setting takes a line count. As a workaround I bisected a byte budget on synthetic text: 10,838,016 bytes keeps at least 10,000 lines. On text.bin that gives 10,255 history rows (10,295 total). History is pruned in whole pages, so exactly 10,000 lines is not possible.
17. Minor doc mismatch found in the source (it did not bite me): the kitty module docs say graphics must be "enabled" by setting a non-zero storage limit, but the library's default limit is already 10 MB.
