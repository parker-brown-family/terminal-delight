Wave Terminal — terminal, web and preview blocks✅ complete
what_it_is Wave Terminal is an open-source, AI-integrated desktop terminal (Electron front end, Go backend) whose tabs are tiled 'blocks'. Each block holds one widget: an xterm.js terminal, a file/directory preview, a code editor, a web browser, sysinfo, or Wave AI. The `wsh` CLI, available in every terminal block, opens previews (`wsh view`), editors (`wsh edit`) and web blocks (`wsh web open`) beside the terminal.
license Apache-2.0
language Go (~2.49 MB) and TypeScript (~2.23 MB), plus CSS/SCSS; Electron ^41 shell
graphics_mechanism Everything is Electron DOM. Terminal blocks are xterm.js 6 with the WebGL or DOM renderer. Web blocks are Electron <webview> tags (WebviewTag, per-block partition). Preview blocks route by MIME type to React renderers: react-markdown for Markdown, plus specialised views for image, video, audio and PDF, and a streaming view for media. The terminal has no image protocol: there is no @xterm/addon-image in package.json, and 'Support a graphics protocol' (sixel/kitty/iTerm) is issue #2172, open since 2025-05-17.
where_it_draws Split pane. Each preview, web or editor view is a tile ('block') in the tab's tiling layout, created beside the terminal. Blocks can be dragged to re-dock, and 'magnified' (Cmd+M) to fill the tab over the others, the nearest thing Wave has to a floating panel. Nothing is drawn inline in terminal scrollback, so nothing scrolls with text.
input_model Block focus model: click, or Ctrl+Shift+arrows/hjkl/1-9, moves focus between blocks, and the focused block receives keys. In web blocks Cmd+L focuses the URL bar and Escape hands focus to the page. Wave ships a dedicated 'Refocus the current block' key (Cmd+I, 'useful if the block has lost input focus'), which tells you embedded content does steal focus. In terminal blocks, links activate only on Cmd+click (macOS) or Ctrl+click (Linux/Windows).

Warp — blocks, Markdown viewer (client AGPL since 2026-04)✅ complete
what_it_is Warp is a Rust, GPU-rendered terminal, now billed as an 'agentic development environment', that groups output into command 'blocks'. It renders Markdown (including Mermaid) in a built-in viewer pane, opens files in its own editor pane, and draws inline images via the Kitty and iTerm2 image protocols. NOT closed source any more: the client was open-sourced in late April 2026 (AGPL-3.0; UI framework MIT).
license AGPL-3.0 (client); warpui_core and warpui crates MIT
language Rust (~65.6 MB of ~67 MB), plus Shell, Python, Objective-C, WGSL and Metal shaders
graphics_mechanism Native GPU drawing through Warp's own Rust UI framework (warpui; WGSL and Metal shaders in the repo). The terminal model is an Alacritty-derived fork (crates/warp_terminal/src/model ships LICENSE-ALACRITTY) extended with three pieces: a Kitty graphics protocol parser (kitty.rs: StoreOnly, StoreAndDisplay, DisplayStoredImage, QuerySupport, Delete; zlib payloads), an iTerm2 inline-image parser (iterm_image.rs), and an ImageMap that keys each image placement to an absolute grid point. Markdown files open in a FileNotebookView-backed file pane, with Mermaid rendered as SVG.
where_it_draws Two places. Kitty/iTerm2 images are cell-anchored in the block's grid: ImageMap stores placements by absolute row and corrects for lines truncated from scrollback, so images scroll with the output. Markdown files open rendered in a split pane beside the terminal. Other files open in Warp's code-editor pane, or an external editor chosen in Settings > Code > Editor and Code Review.
input_model Cmd+click (macOS) or Ctrl+click (Linux, Windows) opens a detected path or URL. Without the modifier, a hover tooltip offers 'Open File/Folder/Link'; right-click copies the absolute path. After opening, open_highlighted_link() puts focus back on the terminal's input editor, not the new pane. Path detection runs on a background thread (dropping any previous scan), resolves relative paths against the hovered block's own pwd, and is skipped for remote sessions and while vim or nano is running.

Extraterm — frames and rich output✅ complete
what_it_is Extraterm is a TypeScript terminal emulator: Qt via NodeGui since v0.60, with the older Electron build frozen at v0.59.4. Its shell integration wraps each command's output in a 'frame', and its `show` command displays files, both highlighted text and common image formats, directly in the terminal. Frames can be popped out into their own tab.
license MIT
language TypeScript (~1.99 MB) on NodeGui 0.74 (Qt bindings for Node/V8)
graphics_mechanism Native Qt widgets inserted into the terminal as 'blocks'. `show` sends a file to the terminal as a 'bulk file' with a MIME type over Extraterm's shell-integration channel (main/src/bulk_file_handling). The terminal hands it to a registered block type, such as the ImageBlock extension (registerBlock('image-block'), a Qt image widget in a sized scroll area). Since v0.77.0 (2024-05-14) it also parses the iTerm2 inline image protocol (main/src/emulator/ITermParameters.ts, 128 MB payload cap). No Kitty graphics or sixel found in the tree.
where_it_draws Inline in scrollback. Frames and image blocks sit between terminal lines and scroll with them, and a frame's title bar stays visible while you scroll through long output. A frame's 'pop out' icon, or dragging its title bar up to the tab bar, moves the output into its own tab.
input_model Frames have title-bar controls: delete, pop out, and a numbered tag that the `from` command uses to pipe a frame's content into a new command. In selection mode a frame's content can be edited in place before reuse. How keys are routed between the terminal and a focused block widget isn't documented beyond that.

DomTerm — HTML in the terminal✅ complete
what_it_is DomTerm is a terminal emulator and multiplexer whose screen is a live DOM document. Programs can print HTML, SVG and images inline (`domterm html`, `domterm hcat`, `domterm imgcat`), and sixel graphics render too. Tabs and panes are GoldenLayout tiles, and `domterm browse URL` opens a web page in a sub-window. Front ends: Electron, Qt WebEngine (qtdomterm), a Rust wry webview, or any browser over WebSocket.
license BSD-3-Clause
language C++ (~1.43 MB, lws-term backend) and JavaScript (~0.97 MB, hlib front end), plus Java, C and a small Rust wry front end
graphics_mechanism DOM in an embedded browser engine. OSC 72 inserts an HTML fragment into the output; the HTML 'is sanity-checked for safety', <html>/<body>/<style> are ignored, and the allow-policy lives in terminal.js (elementInfo/allowAttribute), which the docs call 'a work-in-progress'. OSC 721 replaces a previously inserted fragment by key. Images travel as data: URIs, so they work over ssh. Sixel is decoded by a bundled WASM decoder (hlib/sixel-decode.js, node-sixel).
where_it_draws Inline in scrollback: inserted HTML and images are elements in the terminal document and scroll with the text. Panes and tabs are GoldenLayout tiles that can be dragged and docked. `browse` opens 'a new browser window or sub-window'.
input_model Plain links open on a normal click. 'Subtle' links, including auto-detected file:line links, need Ctrl+click or the context menu's Open Link. Clicked file: links go to the backend, which runs the command in open.file.application (templates for Emacs, Atom and others, with %F/%+P substitutions); other URLs use open.link.application. So a Ctrl+clicked path leaves DomTerm for an external viewer rather than opening inside it.

Terminology — Enlightenment's terminal (tycat/typop, click-to-popup media)✅ complete
what_it_is Terminology is the EFL (Enlightenment) terminal. Clicking a link to an image, video or Edje file pops the media up inside the terminal window. Its ty* helpers drive the same machinery from the shell over a private 'ESC } ... NUL' escape protocol: tycat (inline), typop (popup), tyq (queue), tybg (background), tyls (listing with thumbnails).
license BSD-2-Clause
language C (~1.45 MB) on EFL/Elementary, Meson build
graphics_mechanism Native EFL canvas (Evas, optionally OpenGL). The terminal's own escapes carry a local file path or URL, not pixels. `pn`/`pq` pop up media now or queued. `is`/`ic`/`if`/`it` reserve a WxH cell area, filled with a chosen 'replace character' between `ib`/`ie` markers, and draw the media over those cells: stretched, centred, filled, or as a cached thumbnail with a click-through link. `ij` embeds a live Edje object that can send signals back on stdin. No sixel ('Sixel/ReGIS Graphics Attributes: TODO' in termptyesc.c) and no Kitty graphics.
where_it_draws Two ways. Popups (a click, typop, or `pn`) are a floating layer swallowed into the theme's 'terminology.popmedia' part over the terminal, with image, scale, edje and movie variants. Escape closes it, and hover-link detection pauses while it's up. Inline media (tycat, `is` and friends) is cell-anchored over placeholder characters in the grid, so it scrolls with the text.
input_model The inverse of TD's plan. With helper.inline_please on, a plain click on a media link pops it up inside Terminology, and Ctrl+click skips the popup and runs the external helper (xdg-open, or a per-type command for image, video or general). Link activation waits 0.2 s so a double-click can cancel it. Unknown URLs get an HTTP HEAD (2.5 s timeout) to learn their type first. Links that arrived via OSC 8 escapes are gated by a separate setting (active_links_escape).

Anything that treats them as text (tmux, vim, TD's own server/client mirror) repositions the image for free. Support today: Ghostty (graphics_unicode.zig), iTerm2 3.7 (a placeholder fix is in the 3.7 notes), Rio (#1891/#1893, fixed 2026-08-24), and the ekollof cosmic-term fork (rowcol_diacritics.rs).
