# GUI in the TUI

Prior-art survey for Terminal Delight · 2026-09-24 · run with research-delight

Two posts started this. In one, a retro CRT shows a Windows 95 settings dialog sitting inside a terminal layout, and a reply jokes that inside the GUI you can open another TUI. In the other, Boyd's Jev-plays-Pokémon dashboard draws a live Game Boy screen as crisp pixels beside its text panels. The feature Terminal Delight wants sits between the two. Ctrl+click a Markdown file, an HTML brief or an image in terminal output and it opens inside TD, in a split or as a floating square, and later programs running in TD get to draw real pixels themselves. The question for this survey was who has already built pieces of that, how they did it, and which one idea from each TD should take.

The survey ran as a research-delight plan: a declared rubric (what each project is, licence, language, how the pixels get there, where they draw, input model, activity, overlap with TD, one idea to take, one trap, sources), gap-targeted rounds, and a gate that rejects any value without a source or an explicit flag. Thirty-two projects were seeded; the first round's gatherers bubbled up twenty more. <!-- SCORE -->. The one subject that never closed is the "HYPERION TUI" artwork itself, which three rounds could not tie to any software.

Every claim below carries one of three labels. *Measured* means read on a primary source this session: the project's repo, its docs, a source file, or `gh api` output. *Inferred* means taken from a secondary write-up or a search summary, or reasoned from a primary source. *Hunch* means a guess, stated as one. Nothing was built or run; every claim about behaviour comes from code or docs.

## What should shape TD's design

1. **Someone already ships the gesture Parker described.** In cmux, a Ghostty-based macOS terminal for coding agents, Cmd+clicking a Markdown path opens a live-reloading Markdown viewer in a split beside the terminal, and Cmd+clicking an HTML file opens it in a browser pane. Agents open the same viewer with `cmux markdown open plan.md`, and commands that arrive over its socket are not allowed to steal focus. What cmux lacks is the floating square. [measured: the Markdown and HTML routes are merged pull requests in manaflow-ai/cmux]

2. **cmux's bug list is TD's test plan for the click.** Cmd+clicking `src/main.py:1292`, the format every agent and compiler prints, opens Safari; `file://` URLs get mangled; paths with trailing punctuation were read as URLs; soft-wrapped URLs failed; clicks were swallowed inside fullscreen TUIs that capture the mouse; the Markdown viewer went blank after a resize or a drag to another column. Zed shows the fix for the hardest of these: it resolves a relative path against the working directory that was current when that line was printed, and only opens once a hover has resolved the target. [measured: cmux issues and changelog; Zed's `cwd_history` in crates/terminal]

3. **The first half of the feature needs no graphics protocol at all.** A viewer that TD draws itself, as a gpui pane or a floating element, is ordinary UI. It does not depend on alacritty_terminal learning anything. Zed, on TD's exact stack (gpui + alacritty_terminal), opens a clicked image as a gpui ImageView tab and a clicked Markdown file as an editor tab with a preview beside it on request, and has never drawn a pixel inside its terminal grid. For Markdown, TD already owns a renderer: markdown-delight turns comrak's syntax tree into gpui elements on the same gpui checkout, though it still shows images as their link text and raw HTML as literal lines. [measured]

4. **The second half, programs drawing pixels, cannot ride on stock alacritty_terminal.** Its parser (vte 0.15) drops the `ESC _` bytes that carry Kitty graphics, and its DCS hooks, which Sixel needs, only log. Alacritty's maintainer has declined image support twice this year, on 2026-07-07 and again on the day of this run, when he pointed at euporie's screenshots and wrote that making GUIs in a terminal is "actively working to make terminals and terminal applications worse". Zed closed its own terminal-images request as not planned and pointed at Alacritty. TD has to own this layer. [measured]

5. **Two Rust code paths already exist under licences TD can use, plus a decoder crate.** ayosec's long-running Alacritty fork puts Sixel inside the alacritty_terminal crate (about 1.6k added lines plus a patched `vte-graphics`), so TD would write only the gpui paint, but it is Sixel-only and a version behind TD (0.25.2-dev against 0.26). rio-vt, Rio's extracted VT core (MIT, alacritty_terminal lineage), already parses Kitty graphics with Unicode placeholders, Sixel and iTerm2, and hands decoded images out as events; Rio's maintainer proposed it as a drop-in for Zed's gpui terminal, and although Zed closed that pull request unmerged, its diff maps the API differences. icy_sixel is a streaming Sixel decoder crate. The two cheapest routes to try are vendoring the fork's crate half (Sixel now, with a Kitty decoder added later, as a community cosmic-term fork did in about 1.5k lines) or lifting rio-vt's Kitty and Sixel modules into a pre-parser in front of alacritty_terminal. A pre-parser has to track the cursor and emit cursor moves itself; the vendored crate does not. [measured facts; the trade-off is inferred]

6. **Implement Kitty graphics first, with Unicode placeholders, and leave Sixel for later.** Ghostty made exactly that choice and refuses Sixel. Placeholders put the image inside grid cells: the program prints U+10EEEE characters whose colour and combining marks name the image, row and column, so scrolling, splits, reflow and clipping come from the grid for free. ratatui-image's only Kitty path and yazi's preferred driver both use it, Zellij and tmux both shipped bugs where images escaped their pane, and herdr spent several releases on image occlusion. Omarchy's default terminal, Foot, is Sixel-only, so Sixel is what a stock Omarchy desktop can show today; that is the case for doing it second rather than never. [measured for Ghostty, the clients and the multiplexer bugs; the ordering is inferred]

7. **Clients find a terminal by asking it, or by recognising its name, and TD must be honest on both paths.** notcurses, ratatui-image, viuer, yazi, presenterm and euporie send the Kitty query (`a=q`) followed by a device-attributes request and trust whichever reply comes first. chafa, timg, mcat, the original rtv and Boyd's Jev client look at `TERM`, `TERM_PROGRAM` or the XTVERSION string and fall back to half-blocks for anything they do not know. The gatherers merged every probe into one conformance checklist (it is in the run's bubbles): DA1, XTVERSION, `CSI 14 t` / `16 t` / `18 t`, XTSMGRAPHICS, the Kitty query for each transmission medium, colour queries, synchronized output and SGR-pixel mouse. Answer each truthfully, report a stable `TerminalDelight <version>` name, send one-line upstream patches to the name-matchers, and never borrow Ghostty's or kitty's identity. [measured]

8. **Pixel size per pane is the first question every image client asks, and TD half-answers it today.** TD passes real cell sizes to each pane's pty on every resize, so tools that read `ws_xpixel`/`ws_ypixel` (mpv, ueberzug++, mcat, tdf, w3m) will size correctly. But reading `app/src/host.rs` in this worktree, the `CSI 14 t` reply is built from the geometry captured when the pane was spawned, so after a resize it should report the old size, and `CSI 16 t` (cell size in pixels) goes unanswered because vte 0.15 only dispatches 14, 18, 22 and 23. gpui's fractional cell widths are also truncated to integers on the way into the pty. [inferred from reading the code; not run]

9. **The projects that make a terminal a window manager converged on one verb and four placements.** kitty's open-actions table, herdr's `[[link_handlers]]`, Wave's `wsh view` and `wsh web open -r`, and cat9's `open(target, placement)` all route by MIME type or regex to a viewer, and they all ended up with split, tab, float, and "in place", where the viewer temporarily replaces the current pane and restores it on close (Zellij's in-place panes, herdr's overlay, cat9's swallow). For TD that is `td open <path> [--float|--split|--in-place]`, with Ctrl+click, the CLI and an agent's request all going through the same router. [measured for each project; the synthesis is inferred]

10. **Make the floating square a real pane that converts both ways, and keep the keyboard in TD's hands.** tmux 3.8's release candidate lets a tiled pane float and a floating pane tile, with explicit modal flags; Extraterm pops inline output out into a tab; Zellij keeps floats on one layer that a single key shows or hides, with pinned floats that stay up. EAF shows why TD's keymap must see every key first, so close, dock and move keep working over a browser or PDF. twin and foot's URL mode show the keyboard-only version: every window movable and listable, and a label on every visible path. [measured]

11. **Trust follows who asked.** In Terminology, a user's click may fall back to launching an external program, but a popup that program output requested can only render inside the terminal and never reaches `xdg-open`. cmux applies the same idea to focus: an open request from an agent never moves focus. TD's router should carry one flag, user or program, that decides whether anything outside TD may run. kitty's spec adds the file-transfer rules: refuse device, socket and `/proc` paths, delete temp files only from known temp directories, and return identical errors so a remote client cannot probe the filesystem. [measured]

12. **HTML on Linux in gpui has no drop-in webview.** gpui-component's wry-based webview says it supports only macOS and Windows and draws on top of the gpui window, covering anything behind it. EAF and ueberzug++ lay a separate OS window over a pane, which on Hyprland means guessing positions from scale and IPC. Carbonyl shows what owning a browser engine costs: a Chromium fork that takes over an hour to build and has not shipped since February 2023. The options left are a Rust HTML renderer drawing into a gpui image (Blitz, or Servo, which Parker's servo-reader already drives headless), or a static snapshot first (mcat renders Markdown and HTML to a PNG through headless Chromium) with a live view later. [measured facts; the ranking is inferred]

## Closest prior art to what Parker described

**cmux** is the closest match to the click. It ships the exact gesture (a click on a Markdown path in terminal output opens a live viewer in a split, a click on HTML opens a browser pane) in a terminal built for running many agents, and it lets agents open the same viewer from a CLI. It is macOS-only Swift on libghostty under GPL-3.0, so TD takes its behaviour and its bug list, not its code. [measured]

**Zed's terminal** is the closest match to the architecture. It is gpui and alacritty_terminal, TD's own stack, and it already turns a Ctrl+click in terminal output into a gpui pane item, an image viewer or a Markdown preview, with per-line working-directory resolution that TD can copy almost line for line. It is also the cautionary half: it closed in-terminal images as not planned and has none. [measured]

**Terminology** is the closest match to the floating square. Clicking a media link in Enlightenment's terminal pops the image or video up as a layer inside the terminal window, Escape closes it, and its `tycat` helper reserves a block of cells for inline media. Its trust rule (user clicks may leave the terminal, program requests may not) is the one to copy. Its private escape protocol, which passes file paths instead of pixels, is the part to avoid. [measured]

Three more sit close behind. Wave Terminal tiles preview, web and terminal blocks side by side and has `wsh view -m` for a magnified view, but never detects paths in terminal output. herdr, Omarchy's default agent workspace, has Ctrl+click link handlers, popup and overlay placements, and Kitty images re-emitted to the host. kitty defines the graphics protocol, and its open-actions table is the router grammar to copy. The derived "closeness" column in the table counts shared traits and ranks herdr, Warp and dmux-rs highest; the ranking above weighs the click-to-viewer path more heavily than trait count does. [inferred]

For the second half of the feature, programs drawing pixels, the nearest code rather than the nearest product is rio-vt and ayosec's alacritty fork, both on TD's side of the licence line. [measured]

## The two posts Parker shared

**Boyd's Jev-plays-Pokémon dashboard** is `npx jev-plays-pokemon`, an MIT Node client from Andrew Boyd of Standard Agents, the company behind dmux. The server renders the whole dashboard as a terminal byte stream; the client writes it straight through, adds a chat panel, and draws the Game Boy screen with the Kitty graphics protocol. Each 160×144 frame is upscaled four times with nearest-neighbour sampling on the client, because, in the source's own words, "Terminals scale Kitty images with smoothing, which blurs pixel art", then zlib-compressed and placed over a cell box at up to 15 frames a second. Where Kitty isn't available, the stream's own half-block cells show instead. So the crisp pixels in the screenshot are Kitty graphics, not Sixel or half-blocks. Run inside TD, the client would still draw half-blocks until someone passes `--kitty`, because it turns Kitty on only for Ghostty, WezTerm or kitty, and never inside tmux. TD could also spare every pixel-art client the 16-fold byte cost by scaling small images with nearest-neighbour itself. The web page says Jev entered the Hall of Fame on 2026-09-23; the npm package was first published 2026-09-16. [measured from the package source and the site; that the screenshot came from a Kitty-capable terminal is inferred]

**The "HYPERION TUI v2.7.19" artwork** could not be tied to any software. The post by Fred Nix (an Omarchy plugin author) crediting Boyd's idea could not be read: x.com answered 402, the xcancel mirror 451, and the Servo reader's engine is not built on this box. GitHub repository and code searches, the web, both men's public GitHub activity and nixfred.com turned up nothing with a Windows 95 dialog or that version string. The best reading is that it is concept art for an idea. One coincidence is recorded and not asserted: kygura/hyperion, a Go terminal console for a Jev trading runtime, opened a pull request the same day. [hunch]

## Verified claims from the outside summary

### (a) Omarchy's default terminal

The summary is half right. Foot is the default: the live manual says "Foot is the default terminal for Omarchy", and at the v4.0.4 tag `default/xdg-terminal-exec/hyprland-xdg-terminals.list` names `foot.desktop`. The supported alternatives are three, not two: "We fully support Alacritty, Ghostty, and Kitty as options as well", and `bin/omarchy-install-terminal` accepts `alacritty|foot|ghostty|kitty`. The older Omarchy 3 manual still says Alacritty is the default. [measured: https://omarchy.org/manual/terminal/ and github.com/basecamp/omarchy at v4.0.4]

### (b) rtv at Laotian-telephonebell2559/rtv

The repository is not legitimate. It was judged from metadata only; nothing was cloned, downloaded, built or run. It is a copy of Santitub/rtv: eight of its eleven commits were authored by Santitub on 2026-08-20, three days before the copy was created on 2026-08-23 by an account opened 2026-08-12, with two public repositories, no followers and issues disabled. The uploader's own commits add a 487,623-byte zip inside `src/` and rewrite every outbound README link (the build badge, the FFmpeg builds, the clone URL, yt-dlp, even the example video URLs) to the uploader's GitHub Pages site, whose page has two download buttons for a zip of the same size. Its topics are unrelated bait (voice-cloning, reddit, visual-studio). The description in the summary (Rust, FFmpeg playback, Kitty and Sixel, audio sync, MIT/Apache-2.0) is true of the original, Santitub/rtv: three stars, one day of commits, a release on 2026-08-20. Do not link or cite the copy. [measured via `gh api`]

### (c) Carbonyl

The summary is accurate, with three caveats. Carbonyl is real Chromium, a modified headless shell with a Rust core, and its README claims "pretty much all Web APIs including WebGL, WebGPU, audio and video playback". The picture is half-block characters, two square pixels per cell, rendered at a 1/7 device scale factor; Sixel and Kitty renderers exist only as unmerged pull requests. Audio comes out of the sound system of the machine running Carbonyl, not through the terminal (over SSH you forward PulseAudio yourself). And it has been dormant since v0.0.3 in February 2023, with an open "Is project alive?" issue and a community-fork proposal. [measured]

## How this was run

- Plan: `gui-in-the-tui.plan.ts` (rubric, 32 seeded subjects in five clusters, derived closeness and evidence grade). Harness: `/home/parker/BROWN-FAMILY-SPORTS/Software/research-delight`, imported by absolute path, untouched.
- Round 1: the harness wrote `run/round-1.brief.md`; five parallel gatherers took one cluster each and the lead took the two posts, the rtv check and the three claim verifications, each writing `run/round-1.part-*.json`. `scripts/merge-parts.ts` concatenated them into `run/round-1.result.json`, leaving duplicate subjects (cmux arrived twice) to the harness's own non-destructive merge. Round 1 filled 572 fields across 52 subjects.
- Rounds 2 and 3 targeted the only open gaps (the artwork's licence, language, mechanism and activity) with different search strategies, filled nothing, and the harness stopped with `no-progress`, its signal that a gap is unfindable.
- Tiering: WebSearch, WebFetch, `gh api` and unpkg for everything. The Servo tier was tried for X and failed because `servoshell` is not built on this box.
- Token figures in `run/…run.json` are the gatherers' own estimates, about 1.04M in total.
- `scripts/build-digest.ts` regenerates this file's table and notes from the run, so they cannot drift from the sourced data.
