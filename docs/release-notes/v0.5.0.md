# Terminal Delight 0.5.0 — development notes

**In development on `dev/0.5.0`.** The candidate target is November 13, 2026;
stable targets November 20 after a seven-day candidate hold and qualification.
These notes describe selected development work. No 0.5.0 release is published yet.

## Highlights

- **First launch opens in Clean.** Other designs default to Ops trim and the
  Standard UI set selected in the settings review. Fresh windows use ANSI
  program colours, Markdown syntax and desktop palette inheritance. Each design
  still remembers later changes; Clean keeps its own trim, UI and flat glass.
- **The War Room decides which agents may ask each other.** The agent counter
  opens an org chart: seat agents, draw lines between them, and a line's rung
  says whether one agent may find, read or ask another. An ask is answered from
  what the window already shows, or by a read-only copy of the other agent that
  waits for your Yes. Unseated panes behave as before and are never asked.
- **Ops uses smoked glass.** Overlay backings soften their own grid, matching
  the left spine, while foreground groupings and cards show the desktop through
  the compositor's blur. Labels stay sharp. Fullscreen, 100% opacity and an
  unavailable compositor opacity reading keep grouping faces solid.
- **An artifact rail keeps each agent's newest handover within reach.** An agent
  opening a document preserves a floating square you already have open. The
  corner glyph lists the handovers, newest first.
- **Lighting and chrome follow your choices.** Active and inactive terminals
  have independent glow and linger controls. Clean removes the tube effects,
  and UI CONFIG controls which chrome is visible.
- **Agent authority has clearer limits.** Own-pane operations check the calling
  process; off-limits panes refuse document and workbench operations. The new
  Restricted command runner provides an offline, directory-scoped environment.

Agent-to-agent communication hardening remains the release's qualification work.
Development demonstrations and local daily use do not establish candidate readiness.

## File-manager responsiveness

Revealing a file already has a three-second deadline before TD tries opening its
parent folder. That deadline cannot recover an unresponsive file manager: both
requests may reach the same stuck process. A recurring Strata freeze was
reproduced independently of TD and recovered by restarting Strata; the
[qualification record](../plans/release-0.5.0/strata-reveal-qualification.md)
links the upstream investigation and states what remains unverified for a
candidate. No new TD implementation change was needed for this finding.

## Install and upgrade

Use the existing stable download until a 0.5.0 candidate is published. Local
development builds are identified by their source commit and binary digest.
No package version or stable download is changed by these development notes.

Existing sessions and appearance choices are retained. Ops glass follows the
window's compositor opacity; it needs no desktop configuration change. Scripts
using `open_document` should handle a successful `held` response when a square
is already open. Scripts that change MCP policy must follow the new controls
documented in the [changelog](../../CHANGELOG.md).

See the [release plan](../plans/release-0.5.0/00-status.md) for qualification and
the [changelog](../../CHANGELOG.md) for the complete development record.
