# Git Coordination Architecture

Implementation difficulty: **8/10**. Product and first-release direction were approved by the three concurs and the instruction to build fully while Parker is AFK. Program design and slice decisions below proceed under that explicit autonomous authorization.

The permanent ticker is replaced by a window-wide Git signal. The inspector owns projects, connected groups and evidence; it does not add a task-tree level. Human navigation focuses existing panes or copies context. Agent calls read facts; they do not execute Git or direct another agent.

The existing background engineering scan remains the collector. Extend its worker pass with bounded byte-preserving path observations, stable pane/session metadata and per-source coverage. Preserve legacy `Report` fields. New pure coordination types group physical checkout contexts by common-dir identity and path bytes; remote origin is display grouping, never proof of shared storage. Committed overlap against an assumed main is qualified because it may be inherited by stacked branches.

The operator and authorized projections have separate stores. Authorization precedes graph derivation, identifiers and bounded history. A permission change starts a new authorized epoch; the operator's earlier history is never copied into it. In a fully exposed window, native inspection and MCP read that exact authorized snapshot. With restricted exposure, human inspection can use the broader operator projection, while copy-for-agent always uses authorized facts.

Git cannot distinguish a permitted pane's filesystem changes from a denied pane's changes. Restricted exposure therefore publishes permitted occupancy with file observations unavailable. Once this window has held an off-limits pane, that restriction persists for its lifetime; a hidden pane moving or closing cannot change the published capability. The legacy aggregate requires full exposure. This is the conservative first-release resolution of the exposure audit, rather than a claim to infer per-pane file authorship.

The four read tools are `coordination_overview`, `coordination_project`, `coordination_cluster`, and `coordination_changes`. Overview includes compact causes and exact follow-up read arguments so an agent can start a targeted plan with one call. Pagination is bounded and tied to an authorized revision; old or cross-instance cursors reset explicitly. Hidden-only changes must not alter exposed titles, identifiers, counts, ordering, revisions, cursors or deltas.

Git observations never run during render or an MCP handler. Reuse the existing worker pool and two-second sweep; coordination marks observations stale after thirty seconds. A bounded raw-byte command runner drains oversized output, kills on deadline and reports truncation. UI and MCP report sampled observations, source failures and actual reading ages. No network fetch is added to the feature. Unresolved index paths carry no inferred target; committed merge-tree checks bind exact target and HEAD object IDs.

The native overlay uses the existing over-the-glass wrapper, persistent workspace keyboard focus and bounded vertical scrolling. Logical row selection and a history stack survive drill-down/back. Pane focus revalidates IDs. Checkouts retain dirty/ahead/behind/inventory data in inspection; the permanent rail rotates nothing.
