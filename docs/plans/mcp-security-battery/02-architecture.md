# Architecture: test each boundary separately

The control socket identifies the connecting process. The MCP relay resolves a caller and builds a filtered snapshot. Mutable requests cross a UI queue and must check current policy when they take effect. Copy asks remain in the window's AskBook while waiting, running and answered; their collection is another authorization boundary.

Use the existing Chart, Orgs, Party, AskBook and control authority code. Repair the narrow transition or gate that fails. Do not add a parallel authority store. Exercise a real disposable GUI/host and child callers for transport evidence; use GPUI tests for deterministic queue interleavings and membership actions.

The attack matrix varies caller identity (known, wrong, absent), target position (Open, Read-only, Off-limits), relationship (absent, See, Read, Ask, bypass), window policy and transition (revoke, transfer, remove, reseat). For copy results, also vary waiting/running/answered and late completion.
