# A Restricted command that can consult one provider

Planning only. No online profile, provider grant or automatic delegation is implemented or approved by this document. The shipped development profile remains offline. This is the next product question after the reviewed offline boundary is qualified.

An operator sometimes needs an agent to work on an unfamiliar project while keeping unrelated panes, credentials and services outside its reach. Offline builds establish the smaller file scope, but an agent also needs model responses. Granting ordinary internet access or passing an account key into the command would change the boundary substantially.

The proposed next profile retains one explicit project grant and adds a separately selected provider route. The operator sees the provider, what project content may leave the machine, request/spend limits and expiry before launch. The workload receives a usable route, never the reusable provider credential. Other destinations, host services, desktop input and automatic Standard recipients remain unavailable. The provider may receive content from the granted project: this is an explicit disclosure, not a claim against exfiltration to that provider.

Within that scope, the workload can work without per-request permission prompts. An unavailable broker, exhausted budget, revoked route or unsupported harness fails closed; it never switches to unrestricted networking. Revocation stops future broker acceptance and reports whether an already accepted provider request can still finish. Finishing the run destroys the route. Unknown cost, provider identity or credential state remains unknown and prevents an unsupported ready indication.

Success requires a useful supported agent workflow and adversarial evidence. Complete an edit-and-test task using the selected provider. Prove that redirects, DNS/address substitution, arbitrary CONNECT requests, additional endpoints, child processes and credential-reading attempts cannot extend the route. Prove cancellation, expiry, quota and restart behavior. Record supported harness and protocol versions; compatibility with all agents is not a product claim.

The operator must decide which provider and harness to qualify first, what content disclosure is acceptable and which budget to grant. Those are open product choices. A TUI, unrestricted terminal protocol, GUI service or cross-agent delegation needs its own scope and evidence; it does not ride in on the provider route.
