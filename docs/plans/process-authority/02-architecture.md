# Architecture: an offline restricted command

Parker authorized end-to-end execution while AFK. The first release implements an explicit command launch, not a retrospective pane badge. Standard remains unchanged.

A trusted `terminal-delight restricted run` supervisor requires bubblewrap 0.12.0 or newer and starts it before executing any workload code. Required user, mount, PID, network, IPC, UTS and cgroup namespaces isolate the process and descendants, and the workload cannot create a further user namespace inside its own. Only read-only system programs/libraries, one pinned chosen directory at `/work`, temporary home/tmp, a fresh proc/dev and the per-run gateway are mounted. The environment is rebuilt; no desktop, native-agent or host TD endpoints are inherited. Setup failure prevents execution, with no Standard fallback.

All three child standard streams are pipes. The supervisor relays stdin and converts stdout/stderr into plain UTF-8 text, removing controls except newline, carriage return and tab. This closes terminal-protocol clipboard/picture/control routes. The supported profile is line-oriented offline commands and builds, not TUI, GUI, provider-connected agents or arbitrary network. Those profiles remain unavailable; Standard retains compatibility. No complete resource-DoS or compromised host/kernel protection is claimed.

An immutable optional own-pane note grant is selected at launch. A preconnected per-run datagram descriptor is the only TD route inside the boundary; it accepts a closed typed protocol, never generic RPC or a caller-named target. The supervisor resolves the actual pane from host ancestry before launch and snapshots its shell generation. The broker revalidates that generation before effects, uses existing MCP authorization and never changes global switches. All run authority lives under the fixed /run/user/UID root, excluded from every Restricted workload; runtime overrides outside it are refused. A separate operator socket is outside all mounts and permits status/revoke, never grants. Both channels have byte/rate limits; the outside stream has a read deadline, and workload packets arrive atomically. Seccomp denies new sockets, bind/listen/accept, connections, addressed sends, ancillary FD transfer and io_uring; only unnamed Unix socket pairs remain for internal IPC, so a host socket appearing later inside the chosen directory cannot reopen a host channel. Architecture checks reject alternate syscall ABIs. Revocation serializes with an in-flight note and rejects all subsequent notes. No grant survives supervisor exit or a new run.

Access requests are one bounded pending proposal per run, inspectable through status. They cannot approve or widen anything; changed scope requires an explicit new run. Automatic delegation is denied in this profile, including to stronger Standard agents. This enforces the no-amplification rule without pretending a label constrains a recipient. A provider-connected or constrained-recipient profile needs separate evidence, not a bypass flag.

The chosen directory is an explicit influence channel. Notes, terminal output and shared files can mislead or execute later in a privileged consumer; this is not semantic safety. An unrestricted reader acting on authorized output is outside the containment guarantee. Secrets already inside the chosen directory are granted content. Selecting the account home (resolved from the OS, not HOME), protected state/runtime, configured XDG state/config roots, hard-linked files, special files or nested host mounts is refused. Root and set-ID invocation are unavailable in this qualified profile. Symlinks cannot reveal unmounted paths. Hard-linked regular files are refused so a work-tree alias cannot write outside the grant. Other files already inside the chosen directory are granted content. Malicious Standard host processes can sabotage the boundary and are outside its direction of protection.

The existing control-policy patch is absorbed: unscripted windows refuse all global policy mutations, including disabling unrelated access. Scripted operator windows retain the exact launch opt-in. The off-limits pointer/probe route is fixed and regression-tested. Existing native-agent handoff approvals and their Standard cooperative-trust contract are not rewritten.

Mechanism source: bubblewrap upstream documentation, reused as an installed executable without copied code. Required namespace options and policy are tested on the running kernel; a version string alone is not qualification.
