Why Fresh Opens Still Wait

Opening a new HTML document in Terminal Delight still takes about a second. The live executable was unoptimized; correcting that helps without adding cache memory. The fourfold target remains open.

01 The Live Build Was Slower

You wanted a document you have never opened to appear quickly. The previous cache work left that wait largely intact. This investigation also found that the live Terminal Delight executable was built without application optimization.

On the same 1.4 MB brief, reading the file and checking its render cache took roughly 400 ms in the installed executable. An existing optimized release build took about 80 ms. The compiled instructions confirm that difference; a clean commit and a release-looking filename did not reveal it.

02 Verify the Build We Install

I selected a verified optimized build for installation. The additional renderer experiments did not establish enough benefit to ship, so the renderer remains unchanged.

Build information now reports the actual optimization level. The landing script refuses an unoptimized or unverified executable. The cache limits and browser lifetime stay unchanged.

03 The Larger Speedup Remains Open

The fourfold fresh-open target is still unmet. Browser startup and page rendering remain on the first-open path. The fresh-opening performance issue stays open.

I rejected the GPU plus spare-page experiment: it added about 220 MiB of RAM plus 57 MiB of graphics memory, and its first native open took 2.2 seconds. That trade did not serve your request.

The optimized release also opened five new file paths in 0.89 s median after its browser was running; its first open took 1.57 s. The first-image scheduling prototype measured 0.98 s on the same sequence. That did not establish an improvement.

Formatting, Clippy and the full test suite passed: 3,376 tests passed, with 18 existing skips. Six installation-guard cases passed, including refusal of unoptimized, unknown, dirty and wrong-commit builds. The live window has not changed: the safe-swap guard found two closed shell panes still retained for Undo.
