Reading an artifact from the keyboard

You want an opened artifact to be something you read, not a square in the corner: large, centred, and driven entirely from the keyboard, down to choosing a section, writing a note, concurring and sending. Today the square is built for the opposite job, so a few of the choices below reverse earlier ones and are yours to make.

01 The square was built to read beside, not to read

An Alt+clicked page opens as a square beside the line you clicked. It keeps three keys (Escape, Ctrl+↑/↓, send) and, by design, every other key still reaches the shell underneath. Your request makes reading the main job, so that rule flips.

02 Who gets a keystroke when boxes stack

A video opens in its own box on top of the page that played it, and today the top box hears the keyboard. Clips have nothing to comment on, so: the page or Markdown file always gets the keys, and a clip only answers the two "put a box away" keys.

03 What the keys do once the page has them

A page is drawn as a picture, but TD already knows where every section, figure and decision sits on it, because it draws their note buttons and CONCUR spaces itself. Markdown knows its blocks the same way. So the keyboard has targets to move between.

04 Where this meets the keyboard work next door

The agent beside me in this tab ("Keyboard pane navigation and scroll mode") is building Alt+O to open the newest artifact, plus pane marks and a scroll mode. Its Alt+O is the way into this frame, and both plans edit the same routing table, so this work lands on top of its first slice.

05 Yours to settle

1 · Does an open artifact take the keyboard?

This reverses the square's "read beside the shell" rule for pages and Markdown. Images and PDFs would stay as they are.

Recommend yes, with no "beside" mode in the first cut. Escape gets you back to the shell in one press.

2 · Window frame or pane frame?

80% wide, 5% above, 10% below, measured against the whole window or against the pane that opened it.

Recommend the window. Moving focus to another pane puts the frame away and coming back brings it back, so one window never shows two frames.

3 · Does Ctrl+C reach the agent while you read?

Swallowed, a habitual copy cannot interrupt a turn; passed through, you can stop an agent without closing the page.

Recommend swallowed, as the Document face already does. Escape then Ctrl+C is two presses.

4 · Which key sends to the agent?

Ctrl+Shift+Enter is built, tested, and works inside the note box too. A plain s is quicker but types an s inside the note box.

Recommend keeping Ctrl+Shift+Enter, one send key everywhere.

5 · What ships first?

Recommend: 1 · the reading frame at your numbers. 2 · the page takes the keys, the clip goes deaf, reading and zoom keys, the Escape order. 3 · targets: Tab, ] [, Enter, c, y, on pages and Markdown. Each is usable alone, and each lands after the sibling's first slice.
