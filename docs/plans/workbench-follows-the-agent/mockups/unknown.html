Two cases the wipe rule creates, and neither of them is "no agent". Same 860 px. All titles and counts are invented.

D · A live agent the window cannot bind — show nothing, and say why

An agent is running here and the window cannot tell which of the four

terminal-delight bindings says why.

The resolver already ships this rule for every other reader — show nothing rather than fall back to a directory-wide guess — and extending it to the bench is what makes the wipe safe. It costs something: an agent presenting work into an unbindable pane looks broken, so the screen has to name the refusal and point at the command that explains it.

Any process running as this user can drop a file into a pane's directory, so the file itself can never say who wrote it. What the window did witness is when it appeared — during this conversation — and that is enough to draw it, below a line, on its own terms. Nothing else appears below that line: surfaces from before this change are not read at all, which is screen G.

Parker, on the annotated brief: "Treat them all as essentially old data that will never be migrated… WE DO NOT WANT GARBAGE CODE THAT IS TAKING OUT OF DATE AGENTS / PANES AND THEN MAINTAINING THAT CODE." An earlier draft folded this work behind a count you could open, and the objection lands exactly there — visible on demand needs a reader for the old shape, and that reader is the code being refused. One screen, no reader, no fold, no count.
