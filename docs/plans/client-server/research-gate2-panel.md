## Sketch: MINIMAL MOTION — per-session PTY host with a client-side replica Term. Extract one new GUI-less process kind around the seams that already exist (instance flock, session TOML, term.rs, the line protocols); the GUI keeps every code path above the term::Session handle unchanged.

### Summary

Add one process kind: a per-session, gpui-free "session host" (`terminal-delight serve --session <id>`, same binary), which holds the flock via the existing instance::claim_in, owns the PTY masters and child trees, runs alacritty EventLoops over an authoritative headless Term per pane (scrollback lives here), and runs the capture/persist loop that writes the session TOML. The GUI attaches instead of spawning: term::Session gains a second constructor, attach_in, which runs the same stock alacritty EventLoop over a unix-stream socket via a small SocketPty trait adapter, building a client-side replica Term — so styled_lines, hit-testing, selection, scroll, FOCUS reads, and the generation counter are byte-for-byte today's code on the replica. Attach means the host encodes its Term (full scrollback + screen + cursor + modes) as synthetic VT bytes under the term lock, then tees live PTY bytes; pane/tab close sends a kill verb (intent), app quit merely disconnects (host keeps everything), and a host crash degrades to today's TOML respawn-and-type recovery, which is kept intact as the fallback path throughout. Scrollback survival is the one place the prior honestly strains: it cannot be had without a second, server-side Term and a new grid-to-VT snapshot encoder — real new code, paid deliberately, because the alternative (single server Term behind per-frame RPC) rewrites ~60 lock sites in pane.rs and moves selection/scroll over a wire.

### Process model

Three process kinds, two of them today's. (1) GUI window process, one per window as today: Workspace/tabs/rendering/theme (app/src/main.rs:1975, theme.rs gpui Globals untouched), the per-window ctl-<pid>.sock (ctl.rs:491), the MCP bridge (mcp_transport.rs) — owns replica Terms, owns no PTYs when attached. (2) Session host, one per session id, spawned setsid-detached on demand by whichever launcher resolves the session; holds the flock for its lifetime via instance::claim_in (instance.rs:471) with the existing release() ordering (persistence disarmed first, instance.rs:98); owns: PTY masters + shells/agents/vim/htop child trees, alacritty EventLoop threads (term.rs spawn_in code moved verbatim — it is already std+futures, no gpui, verified term.rs:1-159), one authoritative Term per pane (10k-line scrollback, alacritty Config::default), a pane table issuing durable pane ids, the 800ms foreground-mode poll and 30s capture checkpoint (session.rs capture/agent_resume moved verbatim — already std+libc), and persist_primary_state + write_atomic (main.rs:1250, session.rs:74) relocated so the host is the single TOML writer. Host exits when its last pane closes or on a `shutdown` verb; a systemd --user template unit is a later option (substrate verified free: KillUserProcesses=no, Linger=yes), not needed for the metric. (3) Scratch/demo/seeded windows (TD_SCRATCH/TD_SEED_*/TD_DEMO_STATE, main.rs:18422-18444): unchanged — local spawn_in, no host, zero persistence; they remain the model of a serverless client and keep tear-off working. The six headless verbs are untouched. Per-session hosts (not one daemon) keep today's blast radius: one host crash loses one session to the TOML fallback, and the flock/adoption model transfers without new mechanism.

### Grid read path

The central cut, taken with the care Parker asked for. Finding the seam: every grid touch in pane.rs already goes through one handle — self.session.term.lock() (frame paint styled_lines pane.rs:5027; scrollback reads :3205; hit-tests/word-select :4344-4506; selection writes :3429, :4238, :4448, :4813, :4964; scroll_display :3430, :4159, :4330; FOCUS document build :2098 keyed on the generation counter). So the seam is NOT the ~60 read sites — it is the construction of term::Session in app/src/term.rs. Defining it: Session gains attach_in(pane_stream, ctl_handle, size, cells) beside spawn_in (term.rs:105); a SocketPty adapter implements alacritty's public EventedReadWrite/EventedPty traits (tty/mod.rs:65/:92 in stock 0.26 — EventLoop is generic over them, event_loop.rs:46, verified in the vendored crate) around the pane's unix-stream connection, with on_resize forwarding {cols,rows,cell_w,cell_h} as a control verb. The same EventLoop thread, EventProxy, Notifier, events channel, and generation counter (term.rs:51-95) then drive a client-side REPLICA Term — frame-rate reads stay zero-cost shared memory, selection and scroll_display remain literally client state inside the replica (the multi-attach constraint satisfied by construction), and the generation counter stays the invalidation token. The server's authoritative grid is read at exactly ONE new point: the attach-time snapshot encoder (new module, app/src/gridwire.rs): iterate scrollback + screen + cursor + modes + alt screen and re-emit as VT bytes, pinned by round-trip tests against the existing headless VTE matrix in term.rs (:161+) — feed bytes, snapshot, replay into a fresh Term, assert grids equal. Snapshot-vs-stream atomicity (the trap): on the host, live bytes are teed to client buffers inside TeePty::read(), which alacritty calls while holding the term lock in its drain loop — so an attach handler that takes the term lock, encodes, and registers the client buffer before releasing can never duplicate or drop a byte. Downstream, "presenting beyond a classic terminal UI" is another attach (another replica) or structured host-side reads keyed on the host Term's generation — the door v1 leaves open at zero cost. Honest strain: dual Terms cost 2x VTE parse and 2x grid memory, and gridwire.rs is genuinely new, defect-prone code — that is the irreducible price of scrollback being in the metric under this prior; the single-server-Term alternative is far more motion in pane.rs.

### IPC and protocol

One new socket, everything else reused. New: $XDG_RUNTIME_DIR/terminal-delight/session-<id>.sock in the same 0700 dir (ctl.rs:313 convention), keyed by session id, guarded by the flock — pid recycling and the never-unlinked-socket hazard do not apply to it. Control protocol is newline-delimited JSON (the codebase's universal framing): hello{proto_version,kind}, list-panes, spawn-pane{cwd,resume,cols,rows}->{pane_id,shell_pid}, attach-pane{pane_id,cols,rows,cell_w,cell_h}, resize, close-pane, save{statefile_body}, shutdown, plus a mode/exit event push per pane (the 800ms watcher's output, host-side). Write verbs report truthful per-target outcomes, adopting the UiReq::Apply model (mcp_transport.rs:55) rather than ctl's queue-ack — the deliberate policy choice #308 demands, made for the NEW surface only. Per-pane bytes: a second connection to the same socket, first line `stream <pane_id>`, then raw unframed bytes both ways; resize never rides the byte stream. Auth stays a transport fact: accept() + SO_PEERCRED uid check; no protocol field carries identity, so remote-later is a third transport plus an auth decision, per the product gate. Reused unchanged: the per-window ctl-<pid>.sock and its whole verb set (paint/tabs/adopt/mcp rpc), the mcp stdio relay (run_mcp_cli, ctl.rs:1095), the pure mcp::handle_line_with core, td-send, and the MCP grep/pane_events surfaces — MCP grid reads hit the client replica, which holds full scrollback post-snapshot, so they work unchanged. Workspace::queue_adopt routes pane creation through spawn-pane, but adopt's wire contract to callers is untouched. Replaced: nothing removed; spawn_in remains for scratch/demo and the serverless fallback. The stdio-only push-feed gap (#12 in the seam table) is explicitly kept, not widened.

### Session ownership

The flock moves with the PTYs, using the code that exists. The host calls instance::claim_in (instance.rs:471) at boot and holds the claim for its lifetime; the fail-closed arbitration and release() ordering (instance.rs:98) transfer verbatim. GUI boot's resolve_session (instance.rs:299) grows one tier: (1) $TD_SESSION as today; (2) a session whose host socket answers hello and reports no attached GUI — the kill-relaunch re-adoption case, ranked first because "your work is still running" is exactly what reopening should find; (3) most-recently-saved unclaimed TOML — spawn a host for it, attach; (4) fresh id — spawn host, attach. Two explicit $TD_SESSION launches contending: both race to spawn the host, the flock picks one, the loser detects the held lock and connects to the winner's socket — contention resolved by the same kernel primitive, no new mechanism, and nothing assumes exactly one client (the host accepts N attach connections; resize is told, last-writer-wins). Close semantics implement the approved intent split: close-pane/close-tab verbs make the host SIGHUP the pane's child tree and drop the PTY (today's drop-is-close, main.rs:77-82, becomes a verb); GUI quit sends only a disconnect — on_app_quit stops releasing a flock it no longer holds when attached; the host marks panes detached and keeps running. Attach ground truth: the host's live pane table beats the TOML. Layout stays client-owned (StateFile, main.rs:1043) and leaves re-bind by pane_id stamped into SavedNode as Option<u64> (absent = pre-split file — unknown is not zero); any live pane the loaded layout does not claim is adopted into a new tab on attach, so a checkpoint-stale layout can never lose a running pane and the metric hole closes. Scratch windows still claim nothing.

### Dispatch and binaries

One binary. `serve` joins the six headless verbs in fn main's ladder (main.rs:18333-18386), string-matched before flag_reply (main.rs:18320) like the others. #314 dies in the same slice: the bare-positional fall-through narrows to "an existing directory path" — implementing the reserved open-here feature's validation now instead of leaving the hole open for it — and any other bare word exits 2 with usage; the pinning test subcommands_and_bare_arguments_still_reach_the_window (main.rs:17172) is rewritten to assert an existing dir reaches the window while `clt`/`sevre` are refused. Taking #314 inside this feature is justified, not scope creep: the split multiplies verbs, and a typo'd `serve` that boots a GUI and adopts a session is precisely the phantom-window class the product watches. Version skew (one binary, long-lived hosts, mv-swapped installs): the hello handshake carries a protocol version; the wire is deliberately tiny (raw bytes plus about a dozen JSON verbs) so it should rarely break; on a genuine break the client offers graceful shutdown (host checkpoints via its own persist loop, exits) and then runs today's TOML respawn recovery — degrades to exactly today, never worse, and only on an actual protocol change. A split client/server binary pair is refused: it doubles the #312 class of stale-binary regressions (two artifacts to swap atomically) for zero metric gain.

### Migration plan

Six reviewable steps; spawn_in and the TOML forensic chain are never deleted, so there is no flag day. (1) Seam prep, zero behavior change: SocketPty adapter + attach_in beside spawn_in in term.rs; gridwire.rs snapshot encoder with round-trip tests riding the existing headless VTE matrix (term.rs:161+); pane_id: Option<u64> added to SavedNode. Nothing calls any of it yet. (2) The host: `serve` verb in the ladder, pane table, session-<id>.sock control loop, spawn/attach/resize/close/list/save, TeePty snapshot-then-tee; a headless integration test (spawn host, spawn pane, write sentinel bytes, attach, assert replica grid equals authoritative grid). The #314 dispatch narrowing and the main.rs:17172 test rewrite land here. (3) GUI attach behind TD_SESSIOND=1: resolve_session's new tier; new_restored (pane.rs:2455) gains the attach path — attach if the SavedNode's pane_id is live on the host, else today's respawn-and-type verbatim; close/quit semantics wired; the 800ms mode watcher swaps its local /proc poll for the host's mode push (session.rs capture code moved, not rewritten). (4) Persistence redirect: persist_primary_state (main.rs:1250) sends the StateFile body over the control socket when attached; the host merges the per-leaf cwd/resume fields it owns, runs the shrink guard, and writes via write_atomic (session.rs:74); host runs the 30s capture checkpoint; orphan-pane adoption on attach. (5) Flip the default on; scripts/td-survival-test.sh implements the metric literally — sentinel scrollback lines plus a vim and an htop child, kill -9 the GUI, relaunch, assert scrollback content, live children, tabs, and sticky notes, N cycles, losses must equal 0. (6) Tie-off: recover.rs and the agent_resume chain documented as the host-crash fallback; follow-up issues filed for tear-off attach-by-id (today's respawn semantics kept in v1) and for retiring the redundant respawn path where a host is alive.

### What it refuses

No global daemon — per-session hosts preserve today's flock semantics, adoption model, and one-session blast radius; a single daemon would centralize all sessions behind one process and reopen the #188-class ownership bugs while adding nothing to the metric. No server-side layout, theming, or rendering — the host never learns tabs, groups, split trees, or themes beyond the opaque StateFile body it stores, which is precisely what keeps the left-bar/tabs-as-tasks overhaul (#319) a purely client-side project. No protocol-level auth and no remote transport — same-uid stays at accept(), per the product gate. No multi-attach feature work — but the replica shape, told-resize, client-owned selection/scroll, and per-pane attach connections mean v1 spends nothing to keep it cheap. No push-feed fix, no #308 gate unification for existing surfaces, no #285 hook adoption, no tear-off attach-by-id — each named as a follow-up, none load-bearing for lost-sessions=0. And nothing is deleted: spawn_in, recover.rs, and the five-level agent_resume forensic chain survive as the mandated degradation path, because a design that removes its own fallback fails the 'server death degrades to today, never worse' constraint by construction.

### Risks

- gridwire.rs snapshot fidelity is the highest-defect-density new code: wide chars, wrapped-line flags, SGR extremes, alt screen, cursor state, charset. Mitigation: round-trip property tests over the existing headless VTE matrix in term.rs before any GUI wiring (migration step 1).
- Dual-Term cost is unmeasured: 2x VTE parse on bulk output (cat of a huge file) and 2x grid memory per pane. tmux-under-a-terminal is the daily-proven precedent for exactly this shape, but measure in step 3 before flipping the default.
- Input echo latency gains two unix-socket hops (client to host to PTY and back). Expected tens of microseconds same-machine; measure alongside the above rather than assume.
- Version skew: a long-lived host running an old binary image serving a freshly swapped client. Handshake versioning plus graceful-shutdown-then-TOML-recovery bounds the damage to one deliberate session restart on an actual protocol break; the wire is kept tiny to make breaks rare.
- The 'host pane table beats the TOML' invariant (orphan adoption on attach) is a new conceptual rule hiding under a minimal surface — it must be pinned by tests or a stale checkpoint quietly becomes authoritative again.
- A wedged (not crashed) host blocks all its clients: keep the host loop gpui-free, allocation-light, and budgeted the way ctl/bridge tickers already are; a crashed host is the designed-for case, a hung one is not.
- Moving the 800ms mode watcher and capture host-side touches pane.rs task bodies and save-time behavior — small but real UI-visible surface; step 3 needs side-by-side comparison against today's mode classification.
- The snapshot-vs-tee atomicity argument depends on alacritty 0.26's drain loop holding the term lock across read-and-parse; that was verified against the vendored crate today and must be re-verified on any alacritty_terminal upgrade (a comment in gridwire.rs naming event_loop.rs:46 and the drain loop).
- tmux-in-pane keeps working (PTY children untouched) but the #215 relay parent-walk failure under tmux is consciously carried forward, not fixed.

### Answers to the Gate 2 questions

- **1. What does "nothing lost" mean — scrollback and vim/htop in scope?** Settled at Gate 1 approval: both are in the metric. This design meets them structurally — PTY child trees live in the host so vim/htop never die with the GUI, and scrollback lives in the host's authoritative Term, restored to a fresh client by the gridwire attach snapshot. The kill-relaunch script asserts both (migration step 5).
- **2. What durable, client-addressable pane id survives moves and resume — and is outside-addressability wanted?** A host-issued pane_id (u64, unique per session, stamped into SavedNode as Option<u64> and into the pane's environment as TD_PANE_ID), replacing shell pid as the address on the new surface only; shell_pid remains an attribute. Outside-addressability (#302's focus verb) is not taken in v1 — the appearance-only boundary stands — but the id existing makes it a cheap later decision rather than a re-cut.
- **3. Session ground truth: forensic inference, hook-pushed ids (#285), or both?** Keep inference (session.rs agent_resume chain), moved verbatim into the host, ledger-absent as the operating mode; #285 stays unadopted. The host also stamps TD_SESSION and TD_PANE_ID into each spawned pane's environment, making the stale instance.rs:254 comment ("TD exports TD_SESSION into every pane") true at last — cheap ground truth that shrinks the #311/#299/#272/#151 cross-wiring class, because the pane-to-PTY binding never severs while the host lives; inference is only needed after a host crash.
- **4. Who holds the flock; does adoption-by-recency still make sense; can two $TD_SESSION launches contend?** The host holds the flock via the existing claim_in/release code for its whole lifetime. Adoption ranking gains one tier ahead of TOML recency: a live host socket with no attached GUI wins — that IS the relaunch-after-kill case. Two explicit $TD_SESSION launches race to spawn the host; the flock arbitrates; the loser attaches to the winner. The Hyprland-workspace question from the recon conflict stays what instance.rs:299 implements today — a ranking hint, not a key.
- **5. Write gating: MCP's gated model, ctl's ungated queue-ack, or something new?** Decided deliberately for the new surface, inherited nowhere else: session-host verbs report truthful per-target outcomes on the UiReq::Apply model (mcp_transport.rs:55). Existing ctl and MCP surfaces keep their current policies untouched in v1; unifying them is #308's own ticket, not this feature's.
- **6. Trust and auth beyond same-uid 0700 unix sockets?** Unchanged, and kept where the product gate demands: authorisation is a checkable property of the connection (accept + SO_PEERCRED uid check on session-<id>.sock), never a protocol field. No remote transport in v1; remote later is a third transport plus an auth decision against one protocol core — no rewrite.
- **7. Grid read path: server-side Term behind generation/diff, or client-side replica fed raw bytes?** Client-side replica, decisively. The seam is term::Session construction (attach_in beside spawn_in in term.rs), not the ~60 lock sites in pane.rs; the host keeps an authoritative Term read at exactly one point — the gridwire attach snapshot — and tees raw bytes thereafter. Frame-rate FairMutex reads, in-place selection, and scroll_display stay today's code on the replica; the product's three multi-attach consequences (told-resize, selection/scroll as client state, generation counter as invalidation token) hold by construction. Cost paid: dual Terms and a new snapshot encoder — named honestly under risks.
- **8. Push feed: deliberate contract or a gap the split must close?** Kept as-is, explicitly. The relay path still gets no notifications/message (start_bridge push=None); closing it is orthogonal to the metric and rides no worse after the split. Filed as a follow-up at tie-off, not smuggled in.
- **9. Binary shape and dispatch: one binary or two; #314; gpui-free extraction (#300); canonical checkout (#313)?** One binary, `serve` added to the ladder before the flag gate. #314 is fixed in this feature: bare positionals must name an existing directory (the reserved open-here feature implemented as validation), everything else exits 2; main.rs:17172's pinning test is rewritten. #300's extraction is unblocked but not performed (the host is gpui-free by module discipline, not by crate split). #313: this plan's slices land only in the live tree at ~/Work/terminal-delight, and the plan docs should be committed there — the checkout collapse remains its own issue.
- **10. Discovery and addressing: what replaces the pid-keyed socket scan and /proc parent-walks?** For sessions: session-<id>.sock keyed by session id and guarded by the flock — pid recycling and stale-socket ambiguity structurally gone for the new surface (a dead host's socket fails connect and the flock is free). For windows: ctl-<pid>.sock and its sweep stay as today. The #215 tmux parent-walk gap in the mcp relay is kept, not fixed — noted as surviving follow-up.
- **11. Product framing: has the staged trigger fired?** Yes, and it is now on record: Gate 1 approved 2026-09-08 with the metric (lost sessions = 0 under scripted kill-relaunch, scrollback and non-resumable programs included), which is the formal firing of the 2026-08-29 staged trigger. The composition promise holds in this design: the host answers crash/logout, the TOML/reincarnation layer answers reboot and host death — #180's work remains non-throwaway as the mandated degradation path.

## Sketch: PROTOCOL FIRST — define one versioned wire contract ("td/1": NDJSON JSON-RPC 2.0 over a single per-uid unix socket) and derive the processes from it. The contract is grown out of the two seams that already exist and already share a dispatcher — mcp::handle_line_with (app/src/mcp.rs:441, a pure function of line + Snapshot + closures) and mcp_transport::respond() (app/src/mcp_transport.rs:259, the line-in/line-out entry stdio and the ctl socket's `mcp rpc` verb both call today). Every consumer, the gpui window included, becomes a client of that one documented protocol. The grid read/write path is a first-class protocol domain (grid.frame / grid.lines / grid.grep, generation-invalidated, budgeted), designed before any process moves.

### Summary

Grow the existing pure protocol core (mcp.rs handle_line_with + mcp_transport respond()) into "td/1", a versioned NDJSON JSON-RPC contract with six domains (session, layout, pane, grid, input, events) served on one per-uid unix socket by a new headless `terminal-delight serve` process that owns the PTYs, alacritty Terms, scrollback, flock claims, and the 30s TOML checkpoint loop. The GUI becomes a client: it renders from a cached, serializable grid::Frame (the exact product of today's styled_lines iteration at pane.rs:5027) invalidated by the existing generation counter (term.rs:69), with selection and scroll lifted out of alacritty's Term into client state — the cut Parker asked for extra care on, made as a function boundary inside one process (Step 2) before it becomes a wire (Step 4). Pane/tab close are explicit kill verbs (intent); client disconnect kills nothing; server death degrades to today's TOML recovery because the server writes the same StateFile the fallback path already reads. Unknown argv verbs exit 2, killing #314 at the dispatch ladder. Migration is five reviewable steps — crate split, protocol-in-process, Frame seam, opt-in server, flip — with the scripted kill-relaunch metric harness built at Step 3 and the metric (lost sessions = 0, scrollback and vim/htop included) checked through the protocol itself.

### Process model

Two runtime processes, one installed binary. (1) `terminal-delight serve` — a headless, gpui-free daemon, one per uid, launched on demand by the first client that fails to connect (setsid double-fork), with a systemd --user unit + Linger as the preferred install (substrate verified free: KillUserProcesses=no, Linger=yes, per docs/2026-08-29-foundation-interrogation-zed-gpui-quickshell.md). It owns everything in research-inventory §4: PTY masters and the whole child tree, the alacritty EventLoop threads, every Term (grid + 10k-line scrollback + alt screen) behind its own FairMutex, term::Session handles (app/src/term.rs:60), the flock claims (instance::claim_in, app/src/instance.rs:471, relocated — clients never touch sessions/*.lock), the capture/persist loop (session::capture + persist_primary_state → session::write_atomic writing the SAME StateFile TOML schema, 30s checkpoint, shrink guard, backups), the 800ms /proc mode watcher, keepalive stage machines, vitals/usage sweeps, mcp_tail offsets, sticky-note store, and the durable layout model (tabs, split Tree, groups — today fused into Workspace, main.rs:1975/627/106). (2) The GUI — gpui, one window per process as today, holding only view state: cached grid Frames, selection, scroll offset, theme/warp/CRT (warp.rs stays client-global — renderer-only), focus, drag. Tear-off re-exec survives as a GUI-only concern; the new window attaches to the same server. Lifecycles: GUI crash/kill/swap = socket disconnect = server keeps everything (the metric); pane ✕ / tab ✕ = explicit protocol kill verbs (intent, per the approved close semantics); server SIGTERM = checkpoint all session TOMLs then exit, PTYs die, next launch degrades to exactly today's TOML recovery — never worse, as the product gate requires. Headless verbs (agent-usage, agent-vitals, probe) stay plain subprocess exits; ctl and the mcp stdio relay become thin clients of server.sock.

### Grid read path

The central cut, at a named file-level seam. Today TerminalView::styled_lines (app/src/pane.rs:5027) locks session.term and iterates renderable_content().display_iter into Vec<(String, Vec<TextRun>)> every frame — one of 33 term.lock() sites in pane.rs. The cut: a new serializable td-core type, grid::Frame — exactly the product of that iteration (per-row text + style runs, cursor, TermMode bits, display_offset, cols/rows, topmost_line, generation stamp) — produced server-side under the mutex by a `grid.frame {pane, top?, since_gen?}` verb, and consumed client-side lock-free: styled_lines becomes a pure fn of (&Frame, &Theme, Option<SelRange>). Invalidation is the existing generation counter (term.rs:69, bumped by EventProxy on every event; term.rs:47-49 documents "equal generations guarantee unchanged" — the exact cache-soundness the wire needs): the server pushes coalesced `grid.changed {pane, gen}` notifications (~16ms floor, one outstanding per pane per client); the client pulls at its own cadence; idle panes cost zero. `since_gen` lets the server answer with row diffs instead of a full viewport as a v1-additive optimization inside the same verb. Scrollback and arbitrary-offset reads are `grid.lines {pane, first, last}` — literally grid_rows_in (pane.rs:3200) serialized, which already proves alacritty grid[Line(l)] indexing reads any history row without mutating display_offset; the FOCUS reader's mirror_document (pane.rs:2312), already memoised on MirrorDocKey{generation} (pane.rs:1885), transplants onto it unchanged. grep stays a server verb (today's UiReq::Search budgets kept). The two in-place mutations the recon ranks hot-spot #2 are lifted OUT of Term into the client, satisfying the product's multi-attach constraint by construction: selection (term.lock().selection = Some(sel), pane.rs:4238; clear at :4813) becomes client state over Frame coordinates, with a `grid.semantic_bounds` helper verb for word-select (replacing term.semantic_search_* at pane.rs:4209); scroll (scroll_display at pane.rs:4159/:4330) becomes a client-held offset passed as `top` to grid.frame — server display state is never scrolled by a viewer. Viewport-only overlays (syntax pass, human tinting, cursor, selection) stay client-side decoration, exactly the boundary grid_rows_in's doc comment already draws. This seam is also what 00-status asks the split to unlock: any client — GUI, TUI, web, the #319 left-bar — can pull Frames and documents without a terminal window existing.

### IPC and protocol

Transport: one SOCK_STREAM unix socket, $XDG_RUNTIME_DIR/terminal-delight/server.sock (0700 dir, same dir the per-pid ctl sockets use today), replacing the pid-keyed socket scan. Framing: newline-delimited JSON-RPC 2.0 both directions — requests/responses plus server→client notifications — the same framing respond() speaks today, so the protocol core is an extension, not a rewrite. Handshake: `hello {proto:"td/1", client:{kind,name}, want:[capabilities]}` → `{proto, granted:[…]}`, mirroring MCP's initialize; versioning is additive-within-major, version echoed, unknown methods answer JSON-RPC errors (never a GUI boot). Domains and verbs: session.list/attach/detach/create/release; layout.get/apply (TabOp/AdoptReq grammar from ctl.rs generalized, addressed by durable ids); pane.spawn/close/resize/config.get/config.set/events (GradeReport/ConfigPatch/leave_note carried over from mcp.rs unchanged); input.write {pane, bytes} (keystroke_bytes VT encoding stays client-side, informed by Frame's TermMode bits); grid.frame/lines/grep/semantic_bounds; events.subscribe {feeds} — the push feed (mcp::Watcher's agent_appeared/vanished/tool_call diffing reused) plus grid.changed, layout.changed, session lifecycle, offered to EVERY connection, closing the stdio-only push gap (hot-spot 12). Budgets are contract text: grep keeps 50k lines/pane / 50 matches; frame ≤ one viewport; lines paged with a continuation cursor; the 5s SNAPSHOT_BUDGET dies for reads because the server answers from its own state with no gpui main-thread round-trip — the UiReq bridge (mcp_transport.rs:50) and its 40ms/150ms tickers are migration-only scaffolding, deleted at Step 5. Reused seams: handle_line_with dispatch shape and closures (mcp.rs:441), ApplyOutcome per-target truthful writes (mcp.rs:318, generalized to every write path per #308), Watcher diff (mcp.rs:1149), StateFile/write_atomic persistence, flock arbitration, one-line ctl verbs kept as a compat grammar on the same socket (first-byte sniff: '{' = JSON-RPC, else legacy verb → internal translation; ctl.rs parse_line:333 already isolates the grammar). ### Session ownership

The server holds every flock. instance::claim_in (instance.rs:471) relocates into the server, which claims each session it owns at boot/spawn against the unchanged sessions/<id>.lock files; release() ordering (disarm persistence, then unlock) is kept verbatim. The flock stays on disk as the arbitration between the server and any legacy/stale binary: a TOML nobody holds is adoptable, which IS the degrade path — server unreachable ⇒ the GUI falls back to today's in-process resolve_session (instance.rs:299) + TOML recovery, satisfying "never worse". Session ids stay the durable key; adoption ranking ($TD_SESSION > most-recent-unattached > fresh, Hyprland workspace as a client-supplied ranking hint — resolving the recon's instance.rs conflict in favour of hint-only, per the session-core and persistence maps) moves into the `session.attach {selector, hints}` verb. Two explicit $TD_SESSION attaches contend at the server: v1 refuses the second with a clear error (multi-attach out of scope), but the refusal is a policy answer on a connection, not a lock race — a second viewer later is a policy change, not a protocol change. Adoption of running-but-unattached sessions is the normal GUI boot: relaunch attaches, pulls layout.get, then Frames — scrollback included. Close semantics as approved: pane.close and tab.close are kill verbs (SIGHUP to the pane's process group, grace, SIGKILL; tab.close fans out to all its panes) because a manual close is intent; client disconnect (app close, crash, binary swap) releases nothing and kills nothing. The server exports TD_SESSION and a new TD_PANE_ID into every PTY it spawns — making instance.rs's stale "TD exports TD_SESSION" comment true at last, and giving in-pane tools self-identification that survives tmux for the common case.

### Dispatch and binaries

One installed fat binary, three workspace crates. Cargo workspace split: td-core (term.rs, session.rs, instance.rs, recover.rs, mcp.rs's pure protocol + the new proto/grid::Frame types — std+libc only, unit-tested without gpui, which is #300's extraction ridden along), td-server (daemon runtime: PTY ownership, socket, dispatcher), td-gui (gpui app, the zed-upstream patch surface). The dispatch ladder (main.rs:18333) becomes an explicit allowlist: existing six headless verbs, plus `serve` (headless, never initializes gpui), plus `open <dir>` claiming the reserved "open in this directory" positional. #314 dies here: an unknown first argument — verb-shaped or not — prints usage and exits 2; a bare no-arg launch and answered flags (flag_reply, main.rs:18320) still open the GUI. The pinning test subcommands_and_bare_arguments_still_reach_the_window (main.rs:17172) is rewritten in the same commit to pin the refusal and the `open` form — the research notes changing it is a decision; this sketch makes that decision. The GUI path stops being able to mutate disk pre-handshake: session claiming lives server-side, so even a mis-launched GUI can only attach or run scratch — the phantom-window class (writes + windows from a CLI-shaped call) loses both its window (exit 2) and its writes (no client-side claims).

### Migration plan

Five reviewable steps, no flag day; each lands green and shippable. Step 0 — workspace-ize: mechanically extract td-core (term/session/instance/recover/mcp + tests) from the 18.7k-line main.rs orbit; zero behavior change; #300 satisfied. Step 1 — protocol before processes: write docs/protocol/td1.md + td-core::proto serde types; generalize respond() into the td/1 dispatcher IN-PROCESS (the GUI still hosts it); route the ctl verbs (parse_line:333) and `mcp rpc` through it; rewrite the #314 dispatch ladder + test. Every existing consumer now exercises the documented contract with zero process risk. Step 2 — the Frame seam, still one process: introduce grid::Frame; split styled_lines (pane.rs:5027) into a frame-builder (locks Term) and a pure renderer; lift selection (pane.rs:4238) and scroll (pane.rs:4159/:4330) into TerminalView client state; route hit-testing, FOCUS mirror_document, recent_lines, grep through Frame/grid_rows_in-shaped calls until exactly ONE module touches the FairMutex. This is the risky UX-preserving refactor, done where everything is still diffable in-process — Parker's extra-care seam gets its own gate-reviewable slice. Step 3 — the server exists, opt-in: `terminal-delight serve` hosts td-core sessions; GUI behind TD_SERVER=1 spawns panes via protocol and renders pulled Frames; build the scripted kill-relaunch harness HERE (kill/relaunch GUI N times mid-agent-run; assert every PTY, pane, tab, sticky note, scrollback line — via grid.lines — and a live vim/htop survive; the metric instrument is the protocol itself). Step 4 — flip: server mode default; in-process path demoted to the degrade mode behind a connect-failure fallback; ctl + mcp relay retarget server.sock; push feed armed for all transports; td-send updated. Step 5 — cleanup: delete the UiReq bridge and tickers, retire per-pid ctl sockets after a deprecation window (compat grammar stays on server.sock), move layout ownership fully server-side, revisit MAX_PANES=8 (main.rs:75) as a client capacity rather than a session bound.

### What it refuses

No remote transport and no auth design beyond the capability-grant slot — the product refusal, honored structurally: same-uid stays a transport fact checked at accept, so remote is a future transport + authenticator, not a v1 tax. No multi-attach implementation — only the three checkable non-assumptions (resize told, selection/scroll client-held, generation the shared token), all of which fall out of the Frame design rather than being extra work. No client-side Term replica and no raw-byte-stream mirror feed — one emulator, one truth; a replay feed can be added as a new subscription verb later without re-cutting the seam. No scrollback persistence to disk — server memory answers GUI death (the metric); server death keeps today's floor, deliberately. No new UI (the product says the existing screens surviving IS the product) and no tmux-like surface area (the 2026-06-20 review's 30k-LOC trap): tmux-in-pane keeps working untouched because the pane's child process tree is never interpreted, only kept alive. No fd-passing live server upgrade in v1. No left-bar/#319 work — but layout.* stays id-addressed data so the overhaul reshapes a client and a document, not the wire. Each refusal is a feature: it keeps v1's surface exactly the set of verbs the kill-relaunch metric exercises, which is what makes the metric shippable at zero.

### Risks

- Frame-pull render latency vs today's zero-cost shared-memory reads is the load-bearing perf bet: 8 panes at burst output must repaint from pulled Frames without visible lag. Same-machine unix RTT is tens of microseconds and generation-coalescing bounds traffic, but budget headroom is unmeasured (research-inventory hot-spot 5) — Step 3's harness must measure frame-pull p99 under a 50k-line scrollback flood before Step 4 flips the default, and row-diff `since_gen` is the pre-planned relief valve.
- Lifting selection and scroll out of alacritty's Term is fiddly correctness work: semantic word-select (term.semantic_search_* at pane.rs:4209), the #149 inverted-paint selection permutation, and the three-legged wheel (mouse-report bytes / alt-screen arrows / offset change, pane.rs:4245+) all re-route through Frame coordinates. Mitigated by doing it in-process at Step 2 where behavior is A/B-diffable frame-for-frame.
- Untangling Workspace's durable layout model from its ~100 frame-transient fields (hot-spot 6) so the server can own tabs/splits is the largest refactor; mitigated by making the wire layout document literally the existing StateFile/SavedNode serde model at first, but scope creep here is the schedule risk — and #319 will re-shape the same model later, so the layout.* verbs must stay id-addressed data, not UI shape.
- Server-side frame-at-arbitrary-offset rendering needs an early spike: grid_rows_in (pane.rs:3200) proves arbitrary history-row reads, but cursor/mode/selection semantics away from offset 0 and WIDE_CHAR/WRAPLINE edge cases in a serialized Frame need a verification matrix against term.rs's existing headless VTE tests before the contract freezes.
- Server binary upgrades restart sessions (degrade to TOML) — correct per the gate but operationally surprising next to "swap the GUI freely"; td-redeploy and docs must distinguish the two, or the first server hot-swap becomes the next phantom-window-class incident. fd-passing handoff is deliberately not in v1.
- The always-on server inherits the /proc+transcript sweeps (mode watcher, vitals, capture) at daemon lifetime — CPU/memory creep and file-handle hygiene in a process that never exits needs a soak test; likewise 28 idle mcp relays reconnecting to one socket is a new fan-in pattern the per-window world never had.
- Migration-window dual grammars (legacy one-line ctl + td/1 on one socket, per-pid sockets during deprecation) can mask contract drift; the compat shim must be conformance-tested against docs/protocol/td1.md, not against the old implementation.

## Sketch: STATE FIRST — the server owns Term, PTYs, and scrollback wholesale (wezterm-mux / VS Code ptyHost shape); clients are renderers fed an authoritative-content replica via snapshot+delta keyed on the existing generation counter.

### Summary

One long-lived, gpui-free `td-server` daemon (systemd --user; substrate verified free: KillUserProcesses=no, Linger=yes) owns every PTY master, child process tree, alacritty EventLoop thread, and `Term<EventProxy>` grid — the whole `term::Session` (app/src/term.rs:60) moves server-side, along with the session flocks (instance.rs:471), the 30s TOML checkpoint (main.rs:1250 → session::write_atomic), and all /proc-local introspection (session.rs capture, the 800ms mode watcher, keepalive, vitals, mcp_tail). The GUI becomes a mortal renderer: it attaches to sessions over one well-known unix socket, feeds keystrokes as input frames, and paints from a client-side content replica (styled cells + scrollback ring) updated by damage-tracked grid deltas — alacritty_terminal 0.26's stock `TermDamage`/`LineDamageBounds` API supplies the damage; `Session::content_generation` (term.rs:69-80) stays the invalidation token, exactly as the product gate requires. Selection and scroll become replica-local client state (killing the `term.lock().selection = …` writes at pane.rs:4238/4964 and `scroll_display` at 4159/4330), so scrolling and hit-testing never cross the wire. The existing pure protocol core (mcp::handle_line_with, mcp_transport::respond) and the ctl verb grammar are re-hosted on the daemon unchanged; per-pid sockets, /proc parent-walks (#215), and the unknown-verb GUI fall-through (#314) all die. Close semantics are explicit verbs (pane/tab close kills), connection EOF is detach (app close preserves); server crash degrades to exactly today's TOML recipe recovery because the persistence format and chokepoint move, not change. Migration is seven reviewable steps with the risky grid-seam cut done in-process first, A/B-diffable, before any IPC exists.

### Process model

Three process kinds. (1) `td-server`, one per user, gpui-free, run as a systemd --user unit (socket-activatable; the 2026-08-29 foundation doc verified KillUserProcesses=no + Linger=yes on this box). It owns: all PTY masters and child trees (shells, agents, vim, htop — spawn moves from term::spawn_in, term.rs:105); alacritty's per-pane EventLoop reader/parser threads; the authoritative `Term<EventProxy>` per pane with its 10k-line scrollback and alt screen; the session flocks (instance::claim_in, instance.rs:471, fail-closed semantics kept verbatim) plus a singleton `server.lock` in instance::config_dir so two daemons cannot coexist; the persist loop (persist_primary_state → session::write_atomic, same TOML files in ~/.config/terminal-delight/sessions/); and every kernel-local scrape — session::capture tcgetpgrp+/proc (session.rs:59), the 800ms foreground-mode watcher, keepalive PTY typing, vitals/usage sweeps, mcp_tail transcript tails, recover.rs tombstones. The agent-state grid heuristics (thinking-scan, wants_human) move server-side too — they are facts MCP list_panes needs headless anyway. (2) GUI clients: today's gpui window process minus emulation ownership — one window per process stays for v1 (tear-off via TD_SEED_* unchanged, main.rs:18236). A window owns rendering, font/cell metrics (cols×rows is a fact it TELLS the server — sync_size measurement stays client-side), theme/palette/warp/CRT (warp.rs global and the gpui fork stay pure client), input encoding (keystroke_bytes, pane.rs:5755), replica-local selection/scroll, FOCUS reader document builds, and all chrome (Workspace/Tab/Tree layout, main.rs:106/627/1975). (3) Thin CLIs: `ctl` and the `mcp` stdio relay talk straight to the server socket — no window process involved, so automation can never boot a GUI. Lifecycles: pane/tab close = explicit kill verbs (intent); window close/crash/binary-swap = connection EOF = detach, server keeps everything; server crash = clients degrade to today's TOML recipe recovery (respawn shell at cwd + type resume line, pane.rs:2455's new_restored path), never worse, because the on-disk format is unchanged.

### Grid read path

The central cut, and the file-level seam: `TerminalView` stops holding `session: term::Session` and instead holds a `replica::PaneHandle` — a new module pair `app/src/grid_wire.rs` (serde types: GridSnapshot {generation, cols, rows, history lines as styled runs, cursor, modes, alt flag}, GridDelta {from_gen, to_gen, scrolled_lines, damaged absolute-indexed lines, cursor, modes}) and `app/src/replica.rs` (client-side scrollback ring + a renderable-view API deliberately shaped like what pane.rs already consumes from `renderable_content()`). Every one of the ~dozens of `self.session.term.lock()` sites re-points at the replica: `styled_lines` (pane.rs:5027-5046, the per-frame-per-pane read) iterates replica rows instead of `content.display_iter`; hit-testing and selection (pane.rs:4238, 4964, 4999) operate on a replica-local Selection struct — selection leaves alacritty's Term entirely, which is what the product's multi-attach constraint demands ('selection is client state'); wheel leg 3's `scroll_display` (pane.rs:4159, 4330) becomes replica display_offset, so scrolling is a zero-round-trip local read; the FOCUS reader's `mirror_document` (pane.rs:2312) builds from the replica's full history, still cache-keyed on the generation (MirrorDocKey, pane.rs:1770-1776 — the existing pattern survives unchanged). Server side, the feed comes from stock alacritty damage tracking: on EventLoop wakeup the server locks its authoritative Term, drains `TermDamage`/`LineDamageBounds` (verified present in alacritty_terminal-0.26.0 term/mod.rs:137-222), maps viewport-line damage plus scroll events to absolute history indices, serializes only damaged lines, bumps and stamps the generation (term.rs:51-58's EventProxy already bumps it on every event). A client that misses deltas or reconnects requests a full GridSnapshot at current generation — the same degrade-to-full pattern mirror_doc uses today. Headless grid consumers (MCP grep ≤50k lines/pane, pane_events context, recent_lines-style scans) read the server's authoritative Term directly and never touch the wire. Why this shape and not raw-byte replay: the replica is styled CONTENT, not a second emulator — no client-side VTE, deterministic across clients, and the wire types are display-independent, which is Parker's stated downstream wish ('presenting the terminal beyond a classic terminal UI'): any process that speaks GridSnapshot/GridDelta can render a pane — a web view, or a #319 task-card mini-view — without linking gpui or alacritty.

### IPC and protocol

Transport: one well-known unix socket, $XDG_RUNTIME_DIR/terminal-delight/server.sock in the existing 0700 dir (ctl.rs:321's dir logic reused; the per-PID ctl-<pid>.sock naming dies). Framing: length-prefixed binary frames per client connection, each frame tagged with a lane — `input` (keystroke/paste bytes + resize, client→server), `grid` (GridSnapshot/GridDelta, server→client), `ctl` (a JSON text line, both ways) — one connection keeps resize/delta ordering sane. Reused seams, per the recon's own inventory: the pure MCP core `mcp::handle_line_with` and `mcp_transport::respond()` (mcp_transport.rs:259) become the server's ctl-lane handler verbatim — the recon says a third transport plugs in without redesign, and this is that third transport; the ctl verb grammar (ping/paint/adopt/tabs/mcp rpc, ctl.rs) is served by the daemon with the same one-line-in/one-line-out contract so existing scripts keep working; the truthful write round-trip `UiReq::Apply(Vec<ConfigUpdate>, Sender<Vec<ApplyOutcome>>)` (mcp_transport.rs, verified — Snapshot/Apply/Search enum) becomes the server's ONLY write model: every mutation reports per-target outcomes, resolving #308's ctl-ack-vs-MCP-outcome asymmetry deliberately in favour of outcomes. Replaced seams: the gpui main-thread bridge and its 40ms/150ms tickers and 5s snapshot budget die — the server has no gpui thread; handlers read server state directly (hot-spot #5's nested-budget latency model goes away rather than getting inherited). The push feed (agent_appeared/vanished/tool_call) is pushed on any subscribed connection, so the `terminal-delight mcp` relay becomes a dumb pipe and the push=None gap (hot-spot #12) closes by construction. Auth stays a transport-accept fact: SO_PEERCRED uid check at accept, recorded per-connection; no protocol message ever encodes 'who' — same-uid-therefore-authorised never leaks into the protocol, so remote later is a new transport + the #284 auth decision, zero message changes.

### Session ownership

The server holds every session flock: instance::claim_in (instance.rs:471) moves server-side with its fail-closed contract intact (unarbitrated claim → the server refuses to load that session rather than risk co-ownership, the #188 lesson preserved). A singleton flock on `<config_dir>/server.lock` arbitrates daemons: a second `td-server` finding the lock held pings the socket and exits; finding a dead socket and a free lock, it claims and boots — flock-dies-with-fd keeps this SIGKILL-safe exactly as today. Identity: session id stays the durable unit; the server mints a stable pane id at spawn (session-scoped, survives window reattach and tab moves) and demotes shell pid to an attribute — and it makes the stale instance.rs:255 comment TRUE by actually exporting TD_SESSION and TD_PANE_ID into every PTY it spawns, which is what fixes the tmux parent-walk failure (#215) and the four session cross-wiring incidents' addressing class (#311/#299/#272/#151). Attach: a window sends `attach {session: $TD_SESSION | adopt-newest | fresh, workspace_hint}` — resolve_session's ranking (instance.rs:299) moves server-side wholesale, with the Hyprland workspace passed BY the client as the ranking hint (the client knows the compositor; the server stays display-agnostic). Two explicit $TD_SESSION launches now contend at one arbiter instead of racing the kernel: v1 policy is one attachment per session, second attach refused with the holder named. Scratch/demo windows become `attach {ephemeral:true}` — a server session with persistence disarmed, the existing zero-persistence client model. Close semantics as verbs: `close-pane` and `close-tab` (sent from the ✕ and tab-close paths that today save at main.rs:11321) make the server SIGHUP/kill the process trees and drop the Terms — deliberate action, intent; connection EOF is only ever detach — absence of a client is never intent. Release-order discipline (persistence disarmed before flock freed, instance.rs:98) is kept inside the server's shutdown path.

### Dispatch and binaries

Two binaries out of one workspace, three crates: `td-core` (lib — term.rs, session.rs, instance.rs, recover.rs, mcp.rs, mcp_tail.rs, sticky.rs Saved model, the Tree<L> ops and StateFile serde, plus the new grid_wire types; all already std+libc-only per the recon, so this is a mv not a rewrite, and it delivers #300's gpui-free vitals extraction for free), `td-server` (bin, links td-core, never gpui), `terminal-delight` (the GUI bin, links td-core + the gpui fork). Rationale is #312's measured lesson: client and server sharing one binary and one dispatch ladder regressed every headless caller at once; with two binaries, td-redeploy hot-swaps the GUI while the daemon and every session keep running — which is the product's headline scenario, and it removes the stale-fork blast radius (a stale GUI can at worst render badly, never kill sessions). Headless verbs (`ctl`, `mcp`, `probe`, `agent-usage`, `agent-vitals`) stay in the GUI binary for PATH compatibility but are pure socket clients of td-server. Unknown verb (#314): the fall-through at main.rs:18391-18408 — where anything surviving the six-verb ladder and the `-`-flag gate boots the GUI and mutates session state — is replaced by an allowlist: known verbs dispatch; flag_reply answers flags; a bare positional that IS an existing directory launches the GUI 'open here' (the reserved feature, honoured, not deleted); any other positional exits 2 with usage. The pinning test `subcommands_and_bare_arguments_still_reach_the_window` (main.rs:17172) is rewritten to pin the new contract: directories reach the window, non-directories are refused — the decision the recon says #314 requires. And structurally, #314's sting is drawn even for a stale binary: session claiming lives in the server, so a phantom GUI that does boot can no longer adopt or mint on-disk sessions by accident — worst case is a visible scratch window asking the server for nothing.

### Migration plan

Seven steps, each a reviewable PR that leaves the app working, no flag day. (1) Crate split, zero behaviour change: extract td-core from app/src — the recon already certifies term.rs/session.rs/instance.rs/recover.rs/mcp.rs as gpui-free and unit-tested without gpui; lands #300 as a side effect. (2) Dispatch hardening: the #314 allowlist + rewritten main.rs:17172 test — independent, shippable immediately, kills phantom windows before any daemon exists. (3) THE GRID SEAM, IN-PROCESS: introduce grid_wire.rs + replica.rs and re-point every pane.rs read (styled_lines :5027, hit-test, selection :4238/:4964, scroll :4159/:4330, mirror_document :2312) at the replica, fed by an in-process channel from the same event pump — the Term still lives in the window, so every frame is A/B-diffable against the old lock path (the #149 inverted-selection subtlety gets caught here, not over a wire); benchmark delta volume under htop/vim/agent-scroll worst cases while transport cost is still zero. (4) Daemon skeleton: td-server serves the ctl grammar + mcp respond() on server.sock; GUI still self-hosts sessions; `ctl`/`mcp` CLIs prefer server.sock when present — the discovery/addressing switch (#215, pid-scan death) lands here in isolation. (5) PTY ownership flips: `attach` protocol; new panes spawn server-side (spawn_in moves), grid frames flow over the socket into the step-3 replica; flocks, the 30s checkpoint, capture/keepalive/vitals sweeps move server-side; TD_STANDALONE env keeps the old in-process path as the escape hatch and the server-unreachable degraded mode for one release. (6) Close semantics + the metric's harness: detach-vs-close verbs wired to the ✕/tab-close/quit paths, and the scripted GUI kill-relaunch test asserting lost sessions = 0 — explicitly checking scrollback bytes and a live vim per the approval amendments, plus a server-kill leg proving degrade-to-TOML-recovery is never worse than today. (7) Cutover: systemd --user unit + socket activation, remove TD_STANDALONE, retire the forensic agent_resume chain (session.rs:176-232) to fallback-only status (it IS the server-crash recovery, so it is kept, not deleted), delete per-pid ctl sockets, commit these plan docs to the live tree (#313's canonical-checkout choice made real).

### What it refuses

No multi-attach implementation in v1 — but the constraint is honoured structurally, not verbally: the replica feed is per-connection, generation-keyed, resize is a told fact, selection/scroll are client state, so a second viewer is a second subscription rather than a re-architecture. No remote transport and no auth protocol — authorisation stays an accept-time transport fact (SO_PEERCRED), never a message field, which is precisely what keeps remote a bolt-on. No server-side layout or UI engine — zellij's documented mistake; the server owns content, processes, and persistence, while tabs/splits/theme/chrome remain client-composed facts the server stores through the existing StateFile chokepoint. No second emulator in the client — the replica is styled content, not VTE replay (shpool's reattach-fidelity glitches are the cautionary tale), keeping clients deterministic and the wire display-independent. No protocol sprawl — two message families (grid feed, line control) against wezterm-mux's 30k-LOC surface that the 2026-06-20 review rightly feared; the ctl grammar and pure MCP core are re-hosted, not redesigned. No fork of alacritty_terminal — damage tracking is stock 0.26. No touching the gpui render fork — warp.rs, the CRT pass, theme globals stay client-side exactly as they are. And no big-bang: the riskiest cut (the grid seam) lands in-process, diffable, before a single byte crosses a socket — while everything TD keeps that the field tools lack (sticky notes in the session TOML, vitals/usage economics, the MCP surface, theme/warp) becomes headless-served rather than window-bound, which is what #300's Wool-wall ask and the MCP relay users actually wanted.

### Risks

- Grid-wire volume is unmeasured: a full-screen TUI redrawing at 10-20Hz times N panes must fit one socket; migration step 3 exists to benchmark delta volume in-process before any IPC commitment, and the recon explicitly flags budget headroom as unmeasured (hot-spot #5).
- alacritty's damage is viewport-relative (LineDamageBounds carries display_offset adjustment): mapping damage plus scroll-region events to the replica's absolute history indices is the subtle bookkeeping — reflow-on-resize and scroll regions are where wezterm's equivalent model earned its scars; mitigated by the in-process A/B step and by degrade-to-full-snapshot on any doubt.
- Input echo latency gains a hop (key → server → PTY → delta → paint) versus today's same-process path; unix-socket round-trips are sub-millisecond but the feel bar must be measured in step 5, with input frames never queued behind grid frames on the connection.
- The server is a new single point of failure holding ALL sessions at once — a daemon bug loses more than a window crash ever could; mitigated by the unchanged 30s TOML checkpoint, the kill-the-server leg of the harness proving degrade-to-recovery, and TD_STANDALONE through the migration window.
- Selection/scroll extraction from Term touches the #149 inverted-mode styled_lines subtleties; byte-identical frame diffing in step 3 is the guard, and it must land before the wire does.
- Server-side agent heuristics (thinking-scan, mode watcher) change cadence economics: what was a per-window 120ms UI clock becomes daemon work for every session including detached ones; needs an idle-session backoff so a headless daemon isn't the new battery drain.
- The two-checkout hazard (#313) now has daemon-scale blast radius: a stale-fork td-server would own real sessions with old code; the fork must never grow the server target, and the singleton server.lock plus binary-version handshake on attach should refuse a version-skewed client pair loudly.
- #319 interaction: layout/tabs stay client-composed and server-persisted, which honours 'make nothing harder' — but if tabs-as-tasks later wants task state server-visible, the persistence verb must carry a schema-versioned envelope rather than an opaque blob, so the left-bar overhaul can add fields without a protocol break.

### Answers to the Gate 2 questions

- **1. What does 'nothing lost' mean — scrollback, and vim/htop?** Settled by the Gate-1 amendments and answered structurally: both count in the metric. STATE FIRST keeps them by construction — scrollback lives in the server's authoritative Term (never persisted, never needs to be: the owning process no longer dies), and vim/htop are children of PTYs that survive GUI death, so ProbeKind::Other's 'non-faithful to migrate' classification (session.rs:922-1005) becomes moot for reattach: reattach is not migration. The kill-relaunch harness (migration step 6) checks scrollback bytes and a live vim explicitly.
- **2. Pane identity — what durable client-addressable id, and is outside-addressability wanted?** The server mints a stable session-scoped pane id at spawn, exports it into the PTY env (TD_PANE_ID), returns it from list_panes, and demotes shell pid to an attribute — it survives moves, reattach, and resume because the minting authority survives. Outside-addressability (#302's focus verb): the protocol reserves verb space but v1 keeps the appearance-only write boundary; 'focus' would be a server→client notification a client MAY honour, and the decision whether to want it at all is deferred without being foreclosed — client-side focus state means adding it later costs a notification handler, not a protocol change.
- **3. Session ground truth — forensic inference, hook-pushed ids, or both?** A third source outranks both: the server KNOWS, because it spawned the shell and typed the resume line itself — pane→agent binding becomes a fact recorded at spawn, not inferred. The forensic chain (session.rs:176-232, agent_resume's five-level fallback) is retained as fallback for foreign/adopted panes and as the server-crash recovery path; design assumes ledger-absent (the operating mode on this box — ~/.local/state/terminal-delight/agent-ledger does not exist). #285's hook-push stays unapproved and unneeded for v1. - **4. Session ownership in a client/server world — who holds the flock, does adoption-by-recency survive, can two $TD_SESSION launches contend?** The server holds all session flocks (claim_in moves wholesale, fail-closed contract intact) plus a singleton server.lock arbitrating daemons. Adoption-by-recency survives as the ATTACH ranking for windows — resolve_session's ordering (instance.rs:299) moves server-side, with the Hyprland workspace passed by the client as a ranking hint only (settling the recon's gui-shell-vs-session-core conflict on the side the code supports: hint, not key). Two explicit $TD_SESSION launches contend at one arbiter, not at the kernel: v1 refuses the second attach and names the holder.
- **5. Write gating — MCP's gate, ctl's queue-ack, or something new?** Unified on the MCP model, deliberately (the #308 decision): every mutation on every surface flows through one server policy gate (per-session McpConfig, TD_MCP_WRITE override honoured) and reports truthful per-target outcomes on the UiReq::Apply pattern (mcp_transport.rs's Apply(Vec<ConfigUpdate>, Sender<Vec<ApplyOutcome>>) — verified). ctl's ungated queue-ack dies; ctl verbs keep their wire syntax but return outcome-bearing replies. Silent skips of unresolvable targets become named refusals.
- **6. Trust and auth — what beyond same-user 0700 unix trust?** v1 changes nothing and hardens the boundary's shape: authorisation is asserted at transport accept time (0700 dir + SO_PEERCRED uid check) and recorded as a property of the connection; no protocol message ever encodes identity or trust. That is the product gate's binding constraint made mechanical — same-uid-therefore-authorised cannot leak into the protocol because the protocol has no field for it to leak into. Remote attach later = a third transport whose accept-time assertion is #284's unsolved auth decision; the message core is untouched. adopt --run stays same-uid-only by construction.
- **7. Grid read path — server-side Term behind generation/diff, or client-side replica fed raw bytes?** Both halves of the true answer: the server-side Term is authoritative (scrollback, alt screen, modes, headless grep/scans), and the client holds a CONTENT replica — styled cells, not a second VTE — fed GridSnapshot + damage-tracked GridDelta keyed on the existing generation counter (term.rs:69, the product-mandated invalidation token). Damage comes from stock alacritty_terminal 0.26's TermDamage/LineDamageBounds (verified in the registry source). Selection and scroll move into the replica as named client state (killing pane.rs:4238/4964/4159/4330's in-place Term mutations — coupling hot-spot #2 dies). Scroll/hit-test/FOCUS builds are replica-local, zero round-trips. The raw-byte-replay alternative is refused: it duplicates the emulator per client, makes clients non-deterministic replicas, and loses the display-independent wire that Parker's beyond-classic-terminal-UI wish needs.
- **8. Push feed — deliberate contract or a gap to close?** A gap, closed by construction: pushes (agent_appeared/vanished/tool_call, and now grid deltas and detach/attach events) go to every subscribed connection of the one server; the stdio relay becomes a transparent pipe instead of a bridge started with push=None. The Watcher diff logic (mcp.rs) is reused server-side at its ~1Hz cadence for the MCP-shaped feed.
- **9. Binary shape and dispatch — one binary or split; #314 semantics; #300 extraction; canonical checkout?** Two binaries (terminal-delight GUI + td-server), one workspace, shared gpui-free td-core lib — #300's extraction is step 1 of the migration. Unknown bare verb exits 2; existing-directory positionals launch 'open here' (the reserved feature honoured); main.rs:17172's pinning test rewritten to the new contract. - **10. Stale-socket sweeping collapses to the singleton server.lock check; recycled-pid hazards vanish because pids are no longer keys. Hyprland IPC remains only as the client-side workspace hint.
- **11. Product framing — has the staged trigger fired?** Yes, and it is now on record: Gate 1 was APPROVED 2026-09-08 with amendments (00-status.md), which IS the formal firing of the 2026-08-29 staged trigger — the phantom-window morning, the logout incident's hand-built tmux rescue, and five external-client issues (#300, #302, #284, #308, #215) are the measured hurt the trigger named. The composition promise holds in this sketch: the daemon slots UNDER reincarnation — live PTYs answer GUI-crash/logout, the TOML recipe chain answers server-crash and reboot — so #180's work is load-bearing fallback, not throwaway.

# Judge verdicts

## Lens: PRODUCT-METRIC FIT — lost sessions = 0 under scripted GUI kill-relaunch (scrollback bytes and vim/htop included), pane/tab-close-kills vs app-close-preserves, and server-crash degrading to today's TOML recovery, never worse. Every survival story was pressure-tested for where the scrollback bytes live during the kill and how the harness proves zero; load-bearing claims were verified against the live tree and the vendored alacritty_terminal 0.26 source.

- **MINIMAL MOTION (per-session PTY host + client-side replica Term)** — 3.5/5. Concrete everywhere the lens demands: scrollback bytes live in the host's authoritative Term, vim/htop are host PTY children, per-session hosts give the best blast radius (one host crash loses one session to TOML), spawn_in/recover.rs/agent_resume are never deleted, and the orphan-pane-adoption rule explicitly closes the stale-checkpoint metric hole. But its central scrollback-exactness argument is FALSIFIED by the vendored source it claims to have verified: in alacritty_terminal 0.26 event_loop.rs, pty_read reads PTY bytes (line 122) BEFORE acquiring the term lock (137-145), holding only a FairMutex lease on the next-slot (sync.rs: lock() = next then data; lease() = next only). An attach handler holding the data lock while encoding the snapshot runs concurrently with a PTY read; a chunk read before tee-registration but parsed after the snapshot lands in the authoritative Term and never reaches the replica — lost scrollback bytes at the exact splice the metric measures, in the normal test condition (attach under active output). The naive fix deadlocks (pty_read holds data+lease and would block inside read() on a tee mutex the handler holds); the real repair is a host-owned read loop that tees and parses under one critical section, abandoning 'stock EventLoop verbatim' on the host. Repairable without shaking the architecture, but the design's own kill-relaunch script could flake on the race as written, and the false 'verified today' claim is precisely what this lens exists to catch. Dual-Term divergence also has no re-sync mechanism short of re-attach, and gridwire (VT re-encode of wide chars, wrap flags, SGR, alt screen) is the highest-defect-density new code sitting directly on the metric's assertion path.
- **PROTOCOL FIRST (td/1 contract, server-side Term, grid.frame/lines pulls)** — 4.5/5. The most watertight scrollback story of the three because it manufactures no second truth: bytes live in the one server Term that always held them, the client pulls Frames and grid.lines stamped with the verified generation counter (term.rs:69-72: 'equal generations guarantee the grid has not changed'), and the harness asserts scrollback through grid.lines — a serialization of the already-proven grid_rows_in read path (pane.rs:3204). No snapshot splice, no tee race, no replica divergence class exists to lose a byte in. vim/htop survive as server PTY children; close semantics are exactly the approved intent split (pane.close/tab.close SIGHUP-with-grace kill verbs, disconnect kills nothing); server crash degrades correctly because the server writes the SAME StateFile and the in-process TOML-recovery path is kept permanently as the connect-failure degrade mode — never deleted. The metric harness is built at Step 3, before the default flips, and its instrument is the product surface itself. Anchors verified: handle_line_with (mcp.rs:441), respond (mcp_transport.rs:259), new_restored (pane.rs:2455). Costs are real but not metric-threatening: the frame-pull perf bet can fail visibly (lag) without ever losing a session, has a measure-before-flip gate and a since_gen diff relief valve; the Step-2 lift of selection/scroll out of Term (33 term.lock sites in pane.rs) is a large refactor whose failure mode is visible UX bugs, not silent losses. Docked half a point for the per-uid daemon SPOF (one daemon bug sends ALL sessions to TOML fallback at once — each degrades to today, but aggregate exposure is new) and for a migration plan whose harness does not explicitly include a server-kill leg.
- **STATE FIRST (wezterm-mux shape, content replica via TermDamage deltas)** — 3/5. Bytes-during-kill is concrete (server Term), vim/htop survive, close semantics match the approval, and it is the only sketch whose harness explicitly includes the server-kill leg proving degrade-to-TOML. Its TermDamage claim checks out (verified: term/mod.rs:137-222 in the vendored crate). But two metric-facing strains. First, the continuous replica-maintenance path is the scarred territory it itself names: alacritty damage is viewport-relative (TermDamageIterator::new takes display_offset) and does not track lines scrolling into history, so 'scrolled_lines' must be synthesized and mapped to absolute indices forever on the hot path — a missed or misindexed delta shows the user wrong scrollback content and persists until reconnect, the 'degrade to full snapshot on any doubt' trigger is unspecified (no doubt-detector is named), and the harness does not say whether scrollback is asserted through the replica (where divergence lives) or the server (where it would hide). Second, step 7 removes TD_STANDALONE: post-cutover there is no in-process path at all, so a crash-looping or bad-binary daemon means no working terminal — a genuine 'never worse' violation at the edge, where sketch B keeps the in-process fallback permanently and sketch A never deletes spawn_in. Add the all-sessions single daemon blast radius and the metric credibility sits below both rivals despite an honest risk register.

**Pick:** PROTOCOL FIRST (sketch 2). Under this lens the winner is the design whose survival story has the fewest places to lose a byte, and PROTOCOL FIRST has structurally the fewest: one emulator, one truth, scrollback never copied into a second store that can drift, the metric asserted through the same verbs the product ships, and the TOML degrade path kept alive as a permanent connect-failure fallback rather than an escape hatch scheduled for deletion.
