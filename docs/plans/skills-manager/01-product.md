# Product

A person chooses TD-added skills under CONFIG → Agents. One global switch activates the selection for supported agent starts through the launcher or ordinary shell commands. Their own skills and explicit exclusions retain authority. Briefing and Software Factory are starter choices; repository references and local folders supply others. Sources retain supporting files and a revision.

Every agent session shows attached, partial, unknown or not attached. The status describes availability, not whether the model follows every instruction. Missing confirmation stays unknown. Existing running sessions can show a changed selection as pending restart. Per-session loadout editing comes later.

Success is a real typed-command test in which native provider discovery sees the added fixture and the person's existing skill, plus negative tests that reject stale or missing receipts. Unsupported paths get an honest status.
