# CONFIG › ADMIN: export, old builds, uninstall

**Difficulty 8/10.** It deletes software, edits other programs' settings and stops processes; a mistake can sit unnoticed until it costs someone a machine. Four gates would normally apply. Parker concurred on all six decisions of the second-look review (`reports/2026-10-30-uninstall-second-look.html` in the operator checkout) and asked for the build end to end while away, so this one page stands in for gates 2–4 and records what was decided without him. The review's product choices are the approved gate 1.

## Decisions carried in (all concurred 2026-10-30)

1. Sibling products (the TD Omarchy theme, the tools repo's `td-tubes`/`td-tint`/`td-monitor`/`td-mcp`, Terminal Paint, the mobile gateway) are detected and reported, never removed.
2. The first removal deregisters TD's MCP server, exact match only, through each client's own CLI; wrappers are reported, never edited.
3. The Legion guard is code: a `protected` marker naming `/etc/machine-id`, refused by the worker, the panel and the handoff alike.
4. Old builds get their own ADMIN row; uninstall reuses the same code.
5. Ownership is decided by install receipts and a table of every shipped hash, not by comparing with today's checkout.
6. The install page keeps working removal steps until the engine replaces them.

## Shape

```
app/src/uninstall.rs            CLI: uninstall preview|plan|run, admin export|builds|protect|guard
app/src/uninstall/roots.rs      Roots::from_env: every directory, from an env lookup (fixtures pass their own)
app/src/uninstall/guard.rs      Machine, Protection, the marker
app/src/uninstall/jsonorder.rs  order-preserving JSON, so a settings edit changes only what it removes
app/src/uninstall/known.rs      known_hashes.txt (generated) + receipts reader
app/src/uninstall/export.rs     byte copies + manifest + verification
app/src/uninstall/builds.rs     list, in-use detection, prune
app/src/uninstall/inventory.rs  discovery v2 (what the preview and the plan both read)
app/src/uninstall/plan.rs       inventory + choices -> ordered operations, blockers, reports
app/src/uninstall/apply.rs      the worker: journal, operations, receipt
app/src/main.rs                 ⚙ ADMIN entry in CONFIG, render_admin_overlay
```

The worker is the TD binary run as `terminal-delight uninstall run --plan <file>`, started with `setsid` so stopping TD's windows and hosts does not stop it. Linux lets a process unlink its own executable and keep running. Its journal, its copies of every shared file before editing, and its receipt go to `<XDG_STATE_HOME>/terminal-delight-removal/<stamp>/`, outside every TD root, and that directory is named in the final message.

## Contracts

**Install receipts** (written by the source installers from this change on): `<XDG_STATE_HOME>/terminal-delight/receipts/<component>.receipt`, tab-separated lines: `file<TAB><sha256><TAB><abs path>`, `hook<TAB><settings path><TAB><exact command>`, `block<TAB><file path><TAB><open marker line>`. Components: `agent-hooks`, `recovery-hook`, `keys-hotkey`, `plugins`, `desktop`. Lines starting `#` are comments.

**Known hashes:** `app/src/uninstall/known_hashes.txt`, lines `<sha256>  <repo path>`, generated by `scripts/known-hashes.sh` from every committed version of each installed file. A test fails when a shipped file's current hash is missing from the table.

**Ownership rule:** an installed file is TD's when its hash is in a receipt or in the known table. Anything else with a TD-like name is reported as unresolved, never removed.

**Export:** `~/terminal-delight-export-<YYYYMMDD-HHMMSS>/` with `config/`, optional `state/`, and `manifest.json` (`td-export/1`): every file's relative path, bytes, sha256 and mode; symlinks recorded, not followed; exclusions with reasons. Excluded: the phone token (`mobile/`), lock and temp files, machine-bound undo records (`hotkey-terminal-key.*`, `default-terminal.journal`, `protected`), runtime files. Copies are re-read and re-hashed before the export reports verified. Never inside a TD root.

**Builds:** `td-*` ELF files in `~/.local/lib/terminal-delight`. In use = the launcher's target, or the executable of any process of this user (`/proc/*/exe`, deleted or not). Prune keeps every in-use build and the newest three, re-checks use immediately before each removal, and reports anything else in the directory without touching it.

## Order of a removal

1. **Refuse** on a protected machine, on a plan made on another machine or for another HOME, or on a plan older than its inventory.
2. **Copy** every shared file the plan edits into the removal directory, and export first when the person chose export.
3. **Undo while the binary exists:** default terminal (journal copied first), briefing hook, TD's Claude hook entries and allow rule, MCP registrations (owner CLIs), the key-sheet block.
4. **Stop TD:** windows, then session hosts, then MCP relays, all matched by executable path in the plan, never by name; thaw frozen `td-pane-*` scopes of the plan's sessions (account home only). Anything still running after 20 s blocks file removal and is named.
5. **Remove:** helpers and plugin servers (owned only), desktop entry and icons then refresh their caches, loose runtime assets and the `/tmp` fallbacks, the cache root, TD's own data (another product's files stay), builds, the launcher, the AppImage; records only when chosen.
6. **Verify and write the receipt:** removed, retained, blocked and reported, each with a reason. A partial result never says complete.

## Safety in development

No test or fixture run touches the operator's home: every engine test builds a fixture HOME, the account-home predicate gates the systemd bus and other programs' CLIs, and process matching is by executable path inside the plan, which a fixture's paths cannot match. The Legion gets its marker in this change. Live qualification belongs on the other Lenovo once its identity is verified.
