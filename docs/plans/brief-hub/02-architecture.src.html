The hub has two doors: a private one for opening a brief, a public one for reading and saving it

Terminal Delight asks the hub for a brief's address through a socket only your user can open; the browser then reads and saves through 127.0.0.1:8781. Four choices below decide how it is built. Each has a recommendation.

01 Four architecture choices

The hub lives in the briefing skill, in Python, grown from today's review server. Terminal Delight only asks it for an address.

Recommended. The skill owns the notes format and already has the tested save path; writing it again in Rust would mean two servers to keep in step.

An idle hub stops after 15 minutes and systemd starts it again on the next click.

Recommended. The first click after a quiet spell waits well under a second.

The per-brief servers keep running for 7 days after the hub is installed, then are stopped.

A browser page left open on an old address flushes its unsaved notes within seconds of any activity, so a week is generous. The three running today would be stopped then.

If the hub cannot be reached, Terminal Delight opens the file as it does today and says why in the pane.

Recommended. A link never fails silently and never silently loses saving.
