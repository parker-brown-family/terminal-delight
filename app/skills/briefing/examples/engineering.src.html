A Comment's Return

You leave a comment on an explanation, then the agent revises that explanation. Before acting on the comment, the agent needs to establish which passage and version you were reading.

01 The Target

Each section keeps a stable identifier when its heading changes. The feedback map carries that target, the reader's words and the document's content fingerprint.

02 The Return

The agent checks the map against the supplied document. A matching identity, version and target establishes where the comment belongs. That does not mean the concern has been answered.

Heading renamed

The explicit target stays the same. The changed version still asks the agent to review the context.

Version unknown

Carried HTML notes may have mixed origins. Their revision stays unknown until the old and current context are reviewed.

03 The Evidence

The brief carries the explanation. Its support lives in a linked note, where the reader can continue to checks and source without filling this page with logs.

04 Using It

Use a heading or figure's comment control and copy the resulting map. In a standalone browser the live edits stay in browser storage; in Terminal Delight its native reader can write submitted comments into the original file.

The Markdown rendition uses a saved adjacent map as its portable fallback. This is an engineering example of the new skill's mechanism. Video annotation is reserved for later. Limits.
