TERMBENCH

Terminal Delight ships as one file, terminal-delight-x86_64.AppImage, for 64-bit Linux on X11 or Wayland. Download it, make it executable, and run it.

Three commands 
curl -LO https://github.com/parker-brown-family/terminal-delight/releases/latest/download/terminal-delight-x86_64.AppImage
chmod +x terminal-delight-x86_64.AppImage
./terminal-delight-x86_64.AppImage

Those commands fetch the stable release, 0.3.0. 0.4.0 is out as a candidate, 0.4.0-rc.3: a preview of the next stable, for people who choose it on purpose, and what the rest of these docs describe. Its release page lists what is new. When stable 0.4.0 ships, the commands above fetch it.

The 0.4.0 candidate 
curl -LO https://github.com/parker-brown-family/terminal-delight/releases/download/v0.4.0-rc.3/terminal-delight-x86_64.AppImage
chmod +x terminal-delight-x86_64.AppImage
./terminal-delight-x86_64.AppImage

The rest of these docs call it terminal-delight, and so does the desktop launcher. To get that command, move the file into a folder on your PATH under that name.

mv terminal-delight-x86_64.AppImage ~/.local/bin/terminal-delight

Nothing is installed system-wide. It runs from wherever you put it, uses your system's graphics driver like any other native app, and keeps its settings in ~/.config/terminal-delight/.

TERMBENCH

Terminal Delight is built on gpui, the UI framework from the Zed editor, and it needs a gpui that crates.io does not have. That one fact decides how it is distributed: a prebuilt AppImage for running it, and a build against a pinned Zed checkout for changing it.

What the AppImage needs

A 64-bit x86 machine, X11 or Wayland, and a working Vulkan or OpenGL driver, taken from your system. The renderer is wgpu, which targets NVIDIA, AMD and Intel. At startup the app logs the GPU and driver it found. There are no fonts to install: it walks an explicit monospace fallback chain and warns if the default font is missing.

Four things are optional, and each is looked for only when it's first needed. Without one, Terminal Delight runs as before and hands that file to your desktop with a sentence saying why.2

The file

The address releases/latest/download/terminal-delight-x86_64.AppImage always redirects to the newest stable release, so the command in the Brief keeps working after the next one ships. A candidate is on its own release page, marked Pre-release. To update, download it again over the old file.1

From 0.4.0 on, each release attaches the file's SHA-256 as terminal-delight-x86_64.AppImage.sha256. Download it into the same folder as the AppImage and check the two against each other; it prints OK when they match. The 0.3.0 release has no checksum file.

The AppImage's launcher passes every argument through to the program, so the subcommands work through it: ctl, mcp, serve, skin, surface, conversation, probe, bindings, agent-usage, agent-vitals, default-terminal and briefing. Command line has each one.3

0.5.0 adds admin, uninstall, restricted and ui.

The binary is MIT-licensed. The GPL crates that Zed's dependency graph would otherwise link are cut out at build time, cargo deny check passes with no GPL exceptions, and the licences of everything bundled are listed in THIRD-PARTY-LICENSES.md.

Building from source

scripts/prepare-gpui.sh sets up a sibling zed-upstream/ directory at Zed commit abbe85a, the pin recorded in app/Cargo.toml, and applies nine patches from docs/patches/. Eight change what gpui draws: 0001-td-crt-pass (the per-pane barrel warp), 0002-focus-blur, 0003-text-crawl, 0004-warp-tube-cap-32, 0005-glyph-transform, 0006-lazy-path-targets and 0007-path-targets-fit-the-paths (which hold back the GPU memory an idle window never needs), and 0008-glass-rim. The ninth, 0002-sever-gpl-crates, removes the GPL crates. Each applies once; running the script again changes nothing. CI builds the same way.4

For a release binary, run cargo build --release in app/; it lands in app/target/release/terminal-delight. scripts/build-appimage.sh builds the AppImage into dist/, and scripts/release-smoke.sh runs the checks a release goes through. CONTRIBUTING.md has the CI bar and the clean-room rule.

The 0.5.0 branch applies four more, 0009-image-glow, 0010-image-glow-taps, 0011-desktop-cutout and 0012-tube-blur, at the same Zed commit. Run prepare-gpui.sh again after switching branches.

# on Ubuntu: Vulkan and the build libraries
bash scripts/setup-deps.sh
# the pinned Zed checkout, patched
bash scripts/prepare-gpui.sh
cd app && cargo run
# the AppImage, into dist/
bash scripts/build-appimage.sh

Why there is no cargo install

The crate is not on crates.io, and it cannot be published as it stands. app/Cargo.toml sets publish = false, and gpui is a path dependency on the pinned Zed checkout. The gpui that is on crates.io ships an older renderer, blade, with known problems on NVIDIA under X11.

The desktop launcher

From a checkout, scripts/install-desktop.sh puts a launcher in ~/.local/share/applications/terminal-delight.desktop and the icon in ~/.local/share/icons/hicolor/, as an SVG and, when rsvg-convert is installed, as PNGs at four sizes. The launcher runs terminal-delight, so move the AppImage onto your PATH first, as in the Brief. The same entry is what lets terminal-delight default-terminal on make it Omarchy's terminal; Omarchy has that, and the key sheet.5

bash scripts/install-desktop.sh

Where things are kept

~/.config/terminal-delight/theme.tomlYour own theme. Changes are picked up while the app runs.
~/.config/terminal-delight/skin.tomlA skin override for the chrome. $TD_SKIN does the same.
~/.config/terminal-delight/launch.tomlWhat a new agent opens with, once you save it.
~/.config/terminal-delight/notifications.tomlWhat a finished agent may do to the rest of the desktop.
~/.config/terminal-delight/sessions/One file per window session: its layout, each pane's working directory, and each agent's resume command, so the work reopens after a restart.
~/.config/terminal-delight/plugins/Plugins, one folder each with a plugin.json.
~/.local/state/terminal-delight/The workbench's surfaces and conversations, notes, handovers, and the logs.
~/.cache/terminal-delight/Rendered HTML pages, kept to open faster next time.

$XDG_CONFIG_HOME, $XDG_STATE_HOME and $XDG_CACHE_HOME replace ~/.config, ~/.local/state and ~/.cache when they are set. Config files lists every file, and First launch says which are written when.

Agent hooks

For an agent's replies to reach the workbench on their own, Claude Code needs Terminal Delight's hooks. Their installer lives in the source tree, not in the AppImage.

It puts td-agent-hooks in ~/.local/bin and adds it to ~/.claude/settings.json on five events: UserPromptSubmit, PreToolUse and PostToolUse for AskUserQuestion, Stop, and Notification. It appends to any hooks already there and keeps a timestamped backup of the file. Running it twice changes nothing. CLAUDE_SETTINGS and DEST point it at another settings file or folder.6

bash scripts/install-agent-hooks.sh

The briefing hook

One hook needs no source tree. A Claude agent you start by typing claude is not told what a LAUNCH AGENT pane is told, about the workbench and decision briefs, until a SessionStart hook tells it. The binary adds that hook itself, after you say yes on the agent's bench, or from a terminal. It appends to ~/.claude/settings.json and keeps a timestamped backup, the same way. status says whether it's there and off takes it out.

terminal-delight briefing hook on

Removing it

Undo what you set up, in the order alongside, while Terminal Delight is still there to undo it. Then delete the AppImage.

  1. Open another terminal and check that it works, since the next step may make it the default again.
  2. Take out the briefing hook and put the previous default terminal back. Both commands say what they changed.
  3. From the checkout, run the matching --uninstall of each source installer you used, with the same CLAUDE_SETTINGS, DEST or HYPR_BINDINGS you installed with. Two have no uninstall in 0.4.0. For the desktop launcher, delete ~/.local/share/applications/terminal-delight.desktop and the terminal-delight icons under ~/.local/share/icons/hicolor/. install-plugins.sh copied leanctx-mcp and td-send-mcp into ~/.local/bin.
  4. Delete the AppImage, at ~/.local/bin/terminal-delight if you moved it there.

Your settings, sessions and saved work stay in ~/.config/terminal-delight/, ~/.local/state/terminal-delight/ and ~/.cache/terminal-delight/. Delete those folders too if you want nothing left.

0.5.0 adds Uninstall under CONFIG › ADMIN, and terminal-delight uninstall, which write a plan for you to read, then remove Terminal Delight's own pieces, keeping or exporting your records as you choose. Uninstall has the steps.

terminal-delight briefing hook off
terminal-delight default-terminal off

Each source installer you used, from the checkout:

bash scripts/install-agent-hooks.sh --uninstall
bash scripts/install-recovery-hook.sh --uninstall
bash scripts/install-keys-hotkey.sh --uninstall
bash scripts/install-hotkey.sh --uninstall

If you used the Brief's move onto PATH:

rm -- "$HOME/.local/bin/terminal-delight"

What would prove this wrong

This page claims the three commands in the Brief give you a working Terminal Delight on a 64-bit Linux desktop with a working graphics driver. If they don't, that is a bug. Open an issue with your distribution, your GPU, and the lines the app logs at startup, which name the GPU and driver it found.7
