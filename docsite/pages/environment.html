A handful of TD_ variables change how Terminal Delight starts. The ones you might actually set: TD_SCRATCH=1 for a throwaway window that doesn't touch your session, TD_SPINE=0 to hide the attention rail, TD_NO_SESSIOND=1 to run without the session host, and TD_THEME or TD_SKIN to load a theme or skin from somewhere else.

Three more are set for you, inside every pane: TD_SESSION, TD_PANE_ID and TD_TAG. They are how a script or an agent in a pane knows where it is. Everything else is for debugging, or for staging screenshots with made-up data.

Technical lists every variable and its default.

Set inside every pane

VariableHolds
TD_SESSIONThe session this pane belongs to. terminal-delight mcp and terminal-delight surface use it to find their window.
TD_PANE_IDThis pane's number. It outlives the shell, and it's the pane <n> in list_panes.
TD_TAGEight random characters. Lines the workbench types into this pane arrive as [workbench:<tag>].

These come from the session host, so a window started with TD_NO_SESSIOND doesn't set them.

Debugging

Each prints a trace to stderr: TD_KEYDEBUG (keys), TD_HITDEBUG (clicks), TD_SELDEBUG (selection), TD_BENCHDEBUG (the composer's length, never its text), TD_DOCDEBUG (documents), TD_ANCHORDEBUG, TD_RAIL_DEBUG, TD_LATENCY (keypress to echo). TD_VERB_PREVIEW=1 shows the typed-verb preview under bench cards.

Staging and capture

These fill a window with made-up agents, usage and notes, so a screenshot shows no real work: TD_DEMO, TD_DEMO_STATE (restore a saved state file; implies scratch), TD_DEMO_SEED, TD_DEMO_LOGOS, TD_DEMO_LOGO_DIR, TD_WALL_DEMO, TD_WALL_THEME, TD_FOCUS_DEMO, TD_CONFIRM_DEMO, TD_TRAY_DEMO, TD_OSD_DEMO, TD_SAVINGS_DEMO, TD_USAGE_DEMO, TD_GRAVEYARD_DEMO, TD_GAMBA_DEMO, TD_SPINE_DEMO, TD_WORKBENCH_DEMO, TD_BAY_DEMO (how far the bay door is open, 0 to 1), TD_IGNITION_FREEZE (hold the power-on effect at a point), TD_RAIL_TABLE. TD_USAGE_LIVE opens the usage face on your real records, and is never for capture.
