Terminal Delight is a terminal made for Linux, and for Omarchy in particular: a native app, written in Rust on gpui and rio-vt, the terminal core from the Rio terminal, drawn by your GPU. It is a real terminal first, with tiling panes, tabs, session restore, pictures that programs draw, and a CRT look you can dial up or down. When a pane is running a coding agent, it reads that agent's own transcript and shows you what the agent is doing, what it has spent, and whether it is waiting on you.

On Omarchy

Every Omarchy theme installed on your machine is already in Terminal Delight. Press Super+Alt+P and a paint overlay rises over the window with all of them on it. One letter paints the outer shell, or just the terminal you're in, so each pane can wear a different theme from its neighbours.

The chord comes with Terminal Paint, the 🎨 in the Omarchy bar. Without it, terminal-delight ctl paint on raises the same overlay. Themes has every key.

Underneath

Terminal Delight used to read every program through alacritty_terminal, the part of the Alacritty terminal that turns a program's output into a grid of characters. It kept that grid well, and it threw away every picture a program drew, so an image viewer, a plot or a video player showed nothing in a pane. We recorded six programs that draw pictures and replayed them into four candidate cores to see which ones kept them.

Terminal Delight now runs on rio-vt, the terminal core from Rio. It beat libghostty-vt, the core from Ghostty, 0.82 to 0.72, on weights written down before the final measurements. The swap put the core behind one module, app/src/vt/, that nothing else in the app may name, and Terminal Delight took over the loop that reads a program's output. Pictures now arrive over the Kitty graphics protocol, which is how the recording above plays, and keystroke echo is faster: the median went from 30 to 24 microseconds in a pane the window runs itself, and from 67 to 56 in a pane the session host keeps.

How the choice was made is written up on Parker Brown's site, in five parts:

  1. Program Pixels — which cores kept the pictures that six recorded programs drew
  2. Claim Check — checking 315 quoted facts from the research before relying on any of them
  3. Sealed Weights — weights written down before measuring, and what twenty panes did to the ranking
  4. Agent Fluency — six fresh agents given the same task on the last two cores
  5. Read Loop — building the swap, and what it measured

The plan, the evidence and every measurement are in the repository, under docs/plans/core-swap-rio.
