Close Terminal Delight halfway through a prompt. Reopen it, and every word already typed is still there, with the cursor waiting after the last one. If an agent was working, it never stopped. Shells, agents, servers, scrollback and the unfinished prompt live in a background session host; the window can close, crash or relaunch without taking any of them with it.

Terminal Delight is a native terminal for Linux, built on Omarchy and for it, written in Rust on gpui and built on rio-vt, the terminal core from Rio. It tiles panes and tabs, opens pictures, PDFs, web pages and video beside the line that named them, and runs from a flat screen to an old curved tube. Every Omarchy theme installed on the machine is already inside it.

Agent panes have a second face. TERM is the whole terminal. BENCH holds the replies, decisions and artifacts meant for you, read from the agent's own transcript. The agent wall shows every agent in the window as a card, and the tab strip says which ones need you.

On Omarchy

Terminal Delight can be the terminal Omarchy opens, so Super+Return and the TUI launchers land in it, and one command puts the old terminal back. INHERIT keeps it wearing the desktop's theme as you change it. Super+Alt+T lists every Terminal Delight key in Omarchy's own key menu, and Super+Alt+P raises a paint overlay where one letter paints the outer shell, or just the terminal you're in.

In development

0.5.0 is being built on the dev/0.5.0 branch, with its candidate planned for 13 November 2026 and stable for 20 November. No build is published yet. Three changes lead it:

  • The Threshing Floor decides which agents may reach which. You seat agents in orgs and draw a line from one to another; the line says whether it may see, read, ask or prompt the other. The agent counter opens it.
  • Resting agents: an agent pane nobody has touched for ten minutes is frozen until you look at it, and after two hours a Claude agent is ended with its conversation kept, so a key starts it again.
  • A new Clean design turns the tube and every light off, and a new window opens in it. UI CONFIG hides any piece of chrome you don't want.

Pages that describe it mark it in amber, as this block is. Uninstall, Restricted commands and the artifact rail are new in it too.

Underneath

Terminal Delight used to read every program through alacritty_terminal, the part of the Alacritty terminal that turns a program's output into a grid of characters. It kept that grid well, and it threw away every picture a program drew, so an image viewer, a plot or a video player showed nothing in a pane. We recorded six programs that draw pictures and replayed them into four candidate cores to see which ones kept them.

Terminal Delight now runs on rio-vt, the terminal core from Rio. We scored each candidate out of 1 on weights fixed before the final measurements, with speed and memory weighted highest, and rio-vt came out ahead of libghostty-vt, the core from Ghostty, 0.82 to 0.72. The swap put the core behind one module, app/src/vt/, that nothing else in the app may name, and Terminal Delight took over the loop that reads a program's output. Pictures now arrive over the Kitty graphics protocol, which is how the recording above plays, and keystroke echo is faster: the median went from 30 to 24 microseconds in a pane the window runs itself, and from 67 to 56 in a pane the session host keeps.

How the choice was made is written up on Parker Brown's site, in five parts:

  1. Program Pixels — which cores kept the pictures that six recorded programs drew
  2. Claim Check — checking 315 quoted facts from the research before relying on any of them
  3. Sealed Weights — weights written down before measuring, and what twenty panes did to the ranking
  4. Agent Fluency — six fresh agents given the same task on the last two cores
  5. Read Loop — building the swap, and what it measured

The plan, the evidence and every measurement are in the repository, under docs/plans/core-swap-rio.
