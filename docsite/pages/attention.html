Every agent gets a badge on its tab. A small robot breathes while it works, a yellow HEY blinks when it's waiting on you, and ✅ or ❌ says how it finished. Visiting the pane clears the finish.

At the top of the right edge, a pill counts what's waiting, by kind: amber for an agent asking for access, red for a decision, orange for a failure, green for work to review. Ctrl+Shift+N opens the NEEDS ME queue, which lists them in order, each with the line from the screen that raised it. ↵ takes you to the pane. An ask for access is answered right there in the queue, with Yes or No.

When an agent finishes in a pane you aren't watching, it pings, and a desktop notification goes out with the agent's last message. Clicking the notification brings you to it.

Technical has the queue's order, its keys, and how each signal is detected.

One state, every surface

The tab badge, the left bar, the pill and the queue all read one value per agent. Waiting on you beats working, which beats a finish; a finish is ❌ if an error was on screen when it happened, otherwise ✅. An ask for access outranks all of them in the queue, whatever the screen says, and has no badge of its own.1

A tab shows up to four badges and +N for the rest. The left bar rolls them up onto each group and project. The pane header says the same in words: ❓ your turn, ✘ blocked, ✔ done, exited or live.

How it's detected

A pane on screen reads its bottom rows every 120 ms; a pane in a tab you can't see reads them once a second. A prompt counts as waiting on you unless you've already answered it on that same screen. A finish is an agent that stops thinking for 300 ms after thinking for more than 1.2 seconds, or rings the terminal bell mid-turn. Focusing the pane acknowledges it.1

The pill

One number per lane, in the lane's colour: amber for access, red for decision, orange for failure, green for review. A lane with nothing in it draws no number, and with nothing waiting at all the pill shows a dim 0. ? appears when some panes couldn't be read, and ● when something is unseen. Click it to open the queue. TD_SPINE=0 hides it, and Ctrl+Shift+N then does nothing.

The pill is the spine piece in UI CONFIG, and the Clean set keeps it.2

The queue

NEEDS ME · <n>, sorted by your level for the project, then lane (access, decision, failure, review), then oldest first, then pane. The order holds still while the queue is open; anything new joins at the bottom.

A row opens with a ● if it's unseen, the lane, where it is (the tab's group or project, a colon, the tab's name, with — for whichever is missing), ▲ or ▼ if it has a level, and its age. Under that come the reason (Asks you to change its access, Stopped at a prompt, Finished against a wall, Finished, not yet seen), the screen line that raised it in quotation marks, and which instrument read it beside its age, such as prompt · 3m. An age nobody saw start reads —, never zero. Panes that couldn't be read fold into one line at the bottom: 3 more panes could not be read. With nothing waiting: Nothing is waiting on you.

The selected row opens a tray of four lines: deliverable, changes, checks and read by. changes and checks read unavailable on every row in this build. An ask gets no tray.

Access asks

An agent that needs a setting only a person may change can ask for it with the MCP tool request_access, which works with writes off. Its row says what it wants in Terminal Delight's words, then the agent's reason, at most 40 words, in quotation marks, and two buttons, Yes y and No n. Pressing one answers without taking you to the pane. These five can be asked for:1

ChangeThe row says
open_paneLet agents see “<pane>”
close_paneMark “<pane>” off-limits to agents
writes_onLet agents write: notes, deliverables, the bench, appearance
expose_shellsShow plain shells to agents, not only agent panes
events_onLet agents read other agents' tool calls

Yes changes the setting at once, the way your own control would; No leaves it as it is. Either way the agent is told in one line in its own terminal, signed with the session's tag. A new ask from the same pane replaces the one waiting. The whole exchange is on the MCP page.

Each ask is coloured by how serious it is, in the theme's own colours, and the glyph and its name lead the row, as in ✓ CLEAR · Mark “build” off-limits to agents.2

The pill still counts asks in amber. Two more kinds of ask wait in the same lane. A bypass line from the Threshing Floor (ask_line) reads Let it ask “<pane>” directly, past the chart, and its row lets you pick 1, 3 or 10 prompts before pressing Yes, with 3 picked. A read-only copy of another agent reads Asks you to start a read-only copy and names ask_agent as its source. An agent has one ask waiting at a time: a second is refused with one ask at a time: your earlier ask is still on the person's rail.

Deliverables

An agent can name what it produced with the MCP tool declare_deliverable: a label of up to 48 characters and an absolute path or full URL. It needs writes on. The row then shows html, md or open and the label. o opens it: a file Terminal Delight can draw floats in the document square over the focused pane, and anything else goes to the desktop's own handler. ⇲ beside, or b, opens a file Terminal Delight can draw in a pane beside the agent. The same declaration goes into the pane header's list of what that agent has handed over.1

Urgency on a response

An agent that ends its turn with a response on the workbench can say how much it needs you, with escalation set to blocking, wanted or none. While at least one of the asks it lists is unanswered, the card draws a frame above its title in the theme's red: ◆ NEEDS YOU · 2 unanswered · BLOCKING. wanted draws the same frame fainter, as ◆ WANTED · 1 unanswered · WORK CONTINUES. none, or every ask answered, draws nothing. A response that never mentions escalation but has an asks section is drawn at wanted and labelled inferred.1

The frame stays on the card. It adds no row to the queue and leaves the tab badge alone; an open question card on the workbench is what puts a pane in the DECISION lane.

Levels

Right-click a project, group or tab in the left bar and choose Promote or Demote; choose it again to clear. Promoted work sorts first (▲, green), demoted last (▼, blue). A level passes down to everything inside, and the nearest one set wins.

The finish

A pane you aren't watching plays a short built-in ping when its agent finishes, through ffplay, or pw-play without it. There's no setting for the sound. Then, unless the window is active with that pane focused, notify-send posts a notification titled tab → pane, marked ❓ … — your move, ❌ … — blocked or ✅ …. Its text is the agent's last message, when Terminal Delight is sure which conversation the pane holds, or else the last two lines on screen. Jump to pane raises the window through Hyprland and focuses it.1

Turning it down

The 🔔 in the chrome, or Notifications in the … menu, opens NOTIFICATIONS, which writes ~/.config/terminal-delight/notifications.toml:

system = true    # desktop notifications
marquee = false  # a chasing-bulb banner across the top of the window

With system off, nothing reaches the desktop and no transcript is read. With both off, the badge and the ping remain.

The 🔔 is the notifications piece in UI CONFIG. The Clean set folds it, with the other corner glyphs, into CONFIG.2

What would prove this wrong

If a tab blinks HEY for a pane that has no DECISION row in the queue, the one-value rule has failed, since both read the same state. If anything other than the rail's buttons or y and n ever answers an access ask, the rule that only a person answers has failed.
