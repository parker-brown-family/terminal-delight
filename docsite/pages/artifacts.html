When an agent finishes something you are meant to open, such as a report, a page or a pull request, Terminal Delight records it as a handover. The agent's pane header names the newest one. Click the name and it opens in a floating square over the pane; click ▼ beside it, or press Ctrl+Shift+M, for everything that agent has handed over, newest first.

An agent hands something over in one of three ways: it calls the MCP tool declare_deliverable, it puts an artifact card on its workbench, or it prints a line that starts Deliverable: followed by a link. However many times it names the same file, the list holds it once.

A 📜 in the bottom-right corner opens the artifact rail: one card per agent that has handed something over, newest first. An agent can no longer replace a document you have open; what it tried to open waits on the rail. The rail's Archive opens a searchable page of every handover with a saved copy of each file.

Technical has what counts as a handover, where the list is kept, and the 0.5.0 rail and archive.

What counts

Each handover is a target, a label and the way it arrived. The list shows the way as a word:1

WordHow the agent handed it over
declaredCalled declare_deliverable over MCP.
presentedPut an artifact surface on its bench. The target is the first of href, open, path, file, url or link the surface carries.
saidPrinted a line starting Deliverable:, read from its screen or its transcript.

A target is an absolute path, a file:// URL, or an http:// or https:// URL. A relative path, javascript: and data: are refused.2

A Deliverable: line counts when the words start the row, after an optional bullet (⏺, ●, •, - or *). The link can be on the same row, wrapped over up to four rows, or first on the next non-blank row. A link cut off at the pane's edge, a placeholder such as <file:// or https:// URL>, and a row of a Links table are ignored.3

The same target handed over twice is one entry. Paths are compared after normalising, so /a/b.html and file:///a/b.html are the same file. The entry keeps the time it was first handed over; a stronger way (declared over presented over said) replaces its word and its label. When the agent has its own bench card for a file, that card is the only one on the bench.

The header chip

On an agent pane with at least one handover, the header's right-hand group reads: the TERM ⇄ BENCH switch, the ⌁ AGENT chip, then the handover chip. A pane with nothing handed over has no chip.4

Pane width, at normal text sizeThe chip shows
534 px or moreThe newest handover's label, cut at 28 characters, then ▼. A ● before the label means you have not opened it yet.
328 to 533 px▤ artifacts, which opens the list
under 328 pxNo chip; ▤ artifacts is a row in the pane's ⋯ menu

The header first sets 64 px aside for the launch button and measures what is left in the skin's own text scale, so the thresholds are 470 and 264 px of that space; a larger text size or skin scale moves them.

Clicking the label opens the newest handover. A file Terminal Delight can draw opens in the floating square over the pane: Markdown, HTML, a picture, a video, a sound or a PDF (see Documents). Anything else, and every web link, goes to your desktop's own app. A file that has since been deleted reads <label> · file gone.

The list

▼ or Ctrl+Shift+M opens the list in the floating square; pressing either again, or Esc, puts it away. It is a Markdown page Terminal Delight writes, headed Handed over, then the pane's name and a line such as 3 artifacts, newest first · 1 new · click a name to open it over this pane, Esc puts this page away. Rows are grouped under Today, Yesterday or a weekday and date, and each carries:

  • new until you have opened it;
  • its kind: the file's extension, web or file;
  • the time it was handed over, and the word for how;
  • rewritten and a time when the file changed after it was handed over, or file gone.

Click a name to open it in place of the list. With nothing handed over, the page says how an agent hands something over.5

Where the list is kept

Each handover is filed in the agent's conversation record, $XDG_STATE_HOME/terminal-delight/conversations/<id>.ws, so the list belongs to the conversation and comes back with it after a restart or a resume. A new conversation in the same pane, such as one started with /clear, starts an empty list. The page itself and a record of what you opened sit in $XDG_STATE_HOME/terminal-delight/handovers/<id>/, as handed-over.md and opened.jsonl. The list has no length limit.

Until a pane knows which conversation it holds, its handovers are kept in memory, up to 256, and a restart before then loses them.6

declare_deliverable

The MCP tool an agent calls to hand something over on purpose. It also puts the deliverable on the agent's row in the attention rail, where ⇲ beside opens it in a pane beside the agent. It needs the MCP server's writes switch on.

ArgumentMeaning
hrefAn absolute path or a full URL.
labelWhat the row calls it, 48 characters at most. Defaults to the file's name.
pidThe pane. Leave it out for your own.
clearTake the deliverable off the attention rail. Calling with neither label nor href does the same. The handover list keeps it.

Success reads declared — "<label>" is on pane <pid>'s row in the rail. A relative path is refused with … is relative. It would be resolved against the TERMINAL's working directory rather than yours, so give an absolute path or a full URL., and a label over 48 characters with label is N characters; keep it under 48 ….7

The artifact rail 0.5.0 dev

A 📜 sits in the bottom-right corner, first of the glyphs there. Clicking it opens the artifact rail above the corner, headed 📜 ARTIFACTS and the number of cards, with an Archive button. With nothing handed over it says Nothing handed over in this window yet.8

Each pane in the window whose agent has handed something over gets one card, newest handover first. The card names the project and the pane's left-bar tab (and the pane, when two cards share a tab), shows the agent's state as a glyph, ▶ working, ‖ blocked, ✕ error, ✓ done, ○ idle, ☾ resting, z asleep or ? unknown, and is edged in that state's colour. Its row shows the newest handover's label and kind, a green dot until it is opened, and +N earlier when there are more. A card goes when its pane closes. While the rail is open the order holds still, and only a pane new to the rail goes on top.

Key or clickDoes
↑ ↓Move between cards
Enter, or a click on the handover's rowGo to that pane and open its newest handover there. The rail closes and the card stays.
a click on the cardGo to that pane
Esc, or a click outsideClose the rail

📜 is one of the corner glyphs UI CONFIG can hide. Hidden, it folds into the CONFIG ▾ menu, whose 📜 Artifacts row opens the same rail; that row is in the menu either way. The Clean design hides both the 📜 and the header chip, so in Clean the rail is under CONFIG and the list is the ▤ artifacts row in each pane's ⋯ menu.9

When a document is already open 0.5.0 dev

In 0.4.0 an agent's open_document replaces whatever the floating square over its pane is showing, or is refused when the square holds notes you have not saved. In 0.5.0 an agent never replaces a square you have open. When one is up, the file is not opened; it becomes the pane's newest handover, the 📜 lifts once and keeps a green dot until you open the rail, and the agent is told:

held pane <n> — a square is already open over your pane, so this was not opened over it. It is kept as your handover: the person sees it on the artifact rail (📜) and opens it from there. Do not open it again.

Over MCP that is a success, with "held": true. Two cases are not held: the same file already showing (it already shows this file), and a video or sound, which plays as a clip above the square. Whatever you do yourself still replaces the square: the header chip, the rail, a click, or ctl doc here. A square holding notes you have not saved is kept even then.10

The archive 0.5.0 dev

Archive on the rail writes a page, $XDG_STATE_HOME/terminal-delight/conversations/artifact-archive.html, and opens it in your default browser. It is built from every conversation record, including conversations whose panes have closed, and is headed Artifact archive, with a search box, Find a title, path or conversation, that filters by label, target and conversation. There is one entry per file, per revision, per conversation, newest first:

  • Open current target links the file or URL as it is now, with Current file exists; bytes may have changed., Current file unavailable. or Remote link; availability not checked.
  • Open captured revision links the copy saved when it was handed over, after checking its SHA-256 again. Where there is none the entry says Captured copy unavailable and why: Revision unavailable: this handover has no capture record., Remote link; no local bytes captured., or Saved revision changed; its content hash no longer matches.
  • Source and revision unfolds the conversation, the target, the revision's hash and both times, Handed over and Captured. A conversation it cannot name reads Conversation unavailable.

A record the archive could not read is listed under Some records could not be read. This archive is incomplete., and captures still in progress add Some revision captures are still pending. Reopen the archive to refresh. The page is in English in every language setting.11

Saved copies 0.5.0 dev

Each new handover of a local file saves one copy of its bytes, named by their SHA-256, in $XDG_STATE_HOME/terminal-delight/conversations/artifact-revisions/, readable only by you. Identical bytes share one copy. A copy is made only of a regular file of at most 16 MiB; a web link, a file that is itself a symlink, a special file, or a file that changes while it is read stays a link, and the archive says why. Pictures and other files a page links to are not copied. Nothing deletes saved copies automatically, so they stay until you remove them.12

When an agent declares the same file again, with declare_deliverable or a held open_document, the file's current bytes are saved as a new revision of the same handover. The list and the rail keep one row for it, and the archive shows each revision. Copies are made in the background, up to 128 waiting at once, and the time a copy was made is recorded apart from the time of the handover, since the bytes saved are the ones on disk when the copy runs. Reopening a conversation does not make new copies of old handovers. A handover made before the pane knew its conversation is kept in a separate record, and the archive joins it to its conversation once that is known.

What would prove this wrong

Have an agent print Deliverable: and an absolute path to a file that exists. If the header chip does not name it within a few seconds, or Ctrl+Shift+M does not list it, this page is wrong. So is it if the same file declared twice shows two rows, or if the list is empty after the agent's conversation is resumed in a restarted window.
