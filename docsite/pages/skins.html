A theme decides the colours. A skin decides the shape of everything around the terminals: whether corners are round, square or cut, whether an edge is a hairline, a double rule or nothing, how the selected row stands out, which fonts the menus use, and whether the controls are plain or paper.

Pick one from the SKIN row in the Style area of the window's painter (🎨, bottom right), or run terminal-delight ctl skin chalk. A skin dresses the whole window, never one pane. Chalk turns the controls into paper with handwritten labels; OPS is a command deck of cut corners and countable pips. Because a skin describes its colours as adjustments to the theme's, every skin works with every theme.

Your own skin is a file: start from terminal-delight skin --template chalk, save it as ~/.config/terminal-delight/skin.toml, and it appears as custom and reloads as you edit.

Console is retired and TERMINIMALIST arrives: square, flat furniture with word labels that follows the Omarchy theme.

Technical has the built-in skins, how one gets chosen, and every key in skin.toml.

The four fonts the skins name, Caveat, Oxanium, Chakra Petch and Share Tech Mono, ship with Terminal Delight under the SIL Open Font License, so a skin can name them on any machine.1

The row is chalk, default, deco, ops, clean ▫ (nearly square, flat, no glow; the Clean design asks for it) and TERMINIMALIST. Console is retired, and a saved Console opens as OPS. custom is no longer offered in the row, though a window already wearing it still shows it and ctl skin custom still selects the file.3

Which skin draws

  1. A skin you chose, from the SKIN row or with terminal-delight ctl skin <name>. It stays until ctl skin theme hands the choice back.
  2. The file TD_SKIN names.
  3. Your ~/.config/terminal-delight/skin.toml.
  4. skin = "…" in the design's theme file: Tactical asks for ops, Deco for deco.
  5. default.

The SKIN row lights whichever skin is drawing, chosen or not. Picking one there is a choice, so a design you pick afterwards no longer changes the skin. Nothing is written on first run. An unknown name is refused with the list of known ones: err no skin "…" — have: …. ctl skin status says what is drawing and what is available.1

Picking a design never moves the skin, whether or not you ever chose one: a window keeps the skin it was drawing. A design file that names no skin asks for ops, so every design but Clean starts on OPS.3

Your own skin

Print a built-in skin to start from, edit it, and save it where the window looks:

terminal-delight skin --template chalk > ~/.config/terminal-delight/skin.toml
terminal-delight skin --check --skin ~/.config/terminal-delight/skin.toml --theme hacker

The file is checked every 300 ms. A valid save reloads it, and the window adopts it as custom unless you've chosen another skin. A save that doesn't parse prints skin reload error (keeping current): … and the last good skin stays, so an editor writing in two steps never flashes the default look. --template default lists every key, commented out, with the value it resolves to.1

docs/skins/examples/field-notes.toml in the repository is a second paper look made from the file alone: a monospace interface, restrained grain, plain notes and a glass terminal. The td-skin agent skill walks an agent from a reference picture to a checked skin file and a review in a private window, using the running binary's own catalogue.2

The file

Every key is optional; one you leave out takes its default, worked out against the live palette.

name = "mine"
icon = "▲"

[font]
family  = "Share Tech Mono"
heading = "Oxanium"
data    = "Share Tech Mono"

[shape]
corner   = "cut"       # round | square | cut
boundary = "hairline"  # hairline | double | inset | none
emphasis = "bar"       # fill | underline | bracket | rail | glow | bar
divider  = "line"      # line | double | none
caps     = "upper"     # off | upper | tracked
shine    = "flat"      # gradient | flat
material = "grid"      # plain | paper | grid

[note]
decoration = "plain"   # plain | flower

[metric]
radius = 0
cut    = 8

[ink]
rule = { from = "accent", a = 0.2 }
ink_on_mark = { from = "bg" }

Metrics

In pixels before the window's scale is applied; borders never scale. Defaults: radius 4, radius_lg 10, hairline 1, border 1, rule_gap 2, gap 4, pad_x 6, pad_y 4, chip_px 5, chip_py 1, row_h 15, label_size 9, bracket 5, rail 2, glow 5.25 (how far the ring spreads), glow_a 0.11 (how bright it is, 0 to 1) and cut 7 (how far a cut corner reaches, read only under corner = "cut"). Paper reads four more: grain 1 and roughness 1 (0 to 1), lift 1 (contact shadow and stock depth, 0 to 2) and marker_alpha 0.22 (highlighter opacity).

corner_cap caps the largest corner anything draws (Clean caps it at 3), and frost softens the grid under a grouping into smoked glass (OPS sets 3).3

Fonts

[font] sets the chrome's type, never the terminal's. family is the interface face; heading sets names (projects, the notice, a pane's title) and data sets numbers (percentages, counts, the zoom), each falling back to family, which falls back to the design's font. scale (0.5 to 3), min_px (0 to 32) and line_height (0.8 to 2) fit a face optically; Caveat falls back to 1.45, 16 and 1.15, any other face to 1, 0 and 1.15.

Inks

An ink is either a fixed colour, "#1a2226", or a recipe over one of the theme's colours: { from = "accent", l = 0.8, s = 1.2, a = 0.5, max_l = 0.3, toward = "text", t = 0.4 }. from and toward name bg, surface, text, accent, complement, human, faint, cursor, light (the lighter of bg and text), white, black or ansi0 to ansi15. l scales lightness, max_l caps it, s scales saturation, toward blends by t (0.5 if left out), and a sets opacity, applied in that order.

Fractions without a word are opacity. ink_faint at 0.6 is the lowest setting at which faint text passes 4.5:1 contrast on every built-in theme. Selection uses the theme's human colour, not the accent.

A key the parser doesn't know is reported, never fatal, with a guess: rule_stong (no such token — did you mean rule_strong?). Under --check it fails the file.

Checking a skin

terminal-delight skin --skin deco --theme hacker

Prints every resolved shape, ink, metric and type size as JSON, without a window. --palette lays a bundled palette or a palette file over the theme; --scale is the menu-bar gauge (0.7 to 1.6) and --text-size the text-size gauge's factor (0.6 to 2.0).

In 0.5.0

TERMINIMALIST is square, flat furniture that follows the selected Omarchy palette, in JetBrainsMono Nerd Font. The chrome's actions are words, compact states are unboxed symbols, and nested pane frames, button outlines and settings boxes are gone; hairline sides, structural dividers and a single rule on a selected choice or a warning remain. It asks for the Clean UI set: tabs across the top, the corner's actions in CONFIG, the Git notice hidden, and pane actions behind a right-click on the title. Any switch you flip yourself still wins. Sticky notes become a flat square with an open hairline edge, and a right-click raises one in the theme's complementary colour. Its terminal field matches the chrome, where other skins keep their own background until the field-colour gauge in GAUGES is moved.3

Where the field matches the chrome like that, an agent's own shades of the background become lines in Claude Code and Codex panes: a full-width band, such as your turn or Codex's composer, is ruled above and below, and a short one, such as Jump to bottom, sits in a hairline box. A diff's red and green keep their fills.

OPS uses two layers of glass. The backing of an overlay softens its own grid, the way the left spine does, and foreground groupings and cards show the desktop through the compositor's blur. Fullscreen, 100% window opacity, or an opacity the compositor won't report keeps those faces solid.

What would prove this wrong

Save a skin.toml with a syntax error while a window is open. If the chrome changes at all, rather than staying on the last good skin with an error printed, the reload has stopped protecting the look it was given.
