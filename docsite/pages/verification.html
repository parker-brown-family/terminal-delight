Every change to Terminal Delight is checked by machine before it merges. The checks are 3,269 Rust tests run on two terminal cores, twelve models that try every order of events against nine promises about the window, an audit of every dependency, a release build, and an uninstall run from a throwaway account.

A test checks the cases someone thought to write. A model checks every order of steps in a small copy of the design, which is where a window goes wrong: two things happen at once and the keys go to the wrong place. Each promise is one sentence a person could hold the program to, such as typing into a surface never reaches the shell behind it.

The same checks gate a release. In the thirty days to 12 November 2026, 314 changes merged, 128 of the 130 CI runs on main were green, and one change was reverted.

Technical lists each check, each promise, the numbers with the command that measures them, and what none of it covers.

The models are written in TLA+ and checked with TLC 1.7.4, pinned by checksum1. They were designed with two skills from pstack by Lauren Tan, under the MIT licence; no file of theirs is in the repository2.

How a rule is known to be able to fail

A rule that has never failed proves nothing. verify/mutate.sh copies a model, breaks it the way a careless change to the code would, and checks that the rule now breaks3. Each folder keeps a list of expected findings, and a change that breaks a promise, or fixes one without saying so, fails the Formal models job.

What a release needs

A release is cut from a commit on main or a release branch with green CI, and the release scripts refuse a tag whose version, changelog or notes do not match4. A red push reaches nobody: the Dev channel serves the newest green commit only.

What none of this covers

  • Speed. No check measures startup time or the delay between a key and its letter. A same-machine keystroke comparison against Alacritty and a 20-pane stress proof are open work on the 1.0 milestone.
  • Features with no model. Nine promises are modelled. Everything else, such as themes, the CRT look and usage readings, has no model and rests on its tests.
  • Other machines. CI runs on Ubuntu images. Graphics drivers, other compositors and other distributions are checked by the people who run it.
  • Whether it is useful. A green build says the window keeps its promises, and nothing about whether a person wants it.
