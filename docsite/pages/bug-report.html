Click 🐞 at the right end of the bottom bar. A panel opens with three steps, and each one is its own click.

Step 1 writes a report on your machine and opens it, so you read every word before anything else happens. Nothing is sent. Step 2 starts Claude Code or Codex in a new tab with that one file; it drafts a GitHub issue, shows you the exact text, and files it only when you say yes. Step 3 opens GitHub's new-issue page in your browser instead, for you to write yourself.

A report holds Terminal Delight's own build, your system's versions, how many tabs and panes are open, any crash records, and its own error lines with paths, links and quoted values blanked out. It never holds scrollback, anything you typed, pane titles, working directories, commands or a screenshot.

An orange dot on the 🐞 means Terminal Delight recorded a crash since your last report.

Technical has the panel word for word, the report's sections, the blanking rules and where every file goes.

Where the 🐞 is

In the bottom bar, among the glyphs at its right end: 🎨, the display tray, 🪦, 🔔, 🐞, 🧩. In a window narrower than 720 pixels those glyphs fold into one … button, and its menu has Report a bug. Esc or a click on the dimmed background closes the panel.1

The orange dot appears when Terminal Delight wrote a crash record after your last prepared report, or when the window itself crashed on a background thread since it started. The second kind stays lit until the window restarts.

On 0.5.0 the 🐞 is hidden in the Clean and Standard UI sets, and a first launch opens in Clean. With it hidden, a CONFIG ▾ button takes its place at the end of the bar, Report a bug is in its menu, and the crash dot moves onto CONFIG and onto that menu entry. To bring the glyph back, switch it on in UI CONFIG or choose the all set. Under a skin that draws controls as words, it reads report.4

The panel

Headed 🔒 REPORT A BUG, then: TD never puts your terminal's input or output in a report. Each step is its own click, and nothing leaves this machine until you choose step 2 or 3. When a crash is waiting it adds, in orange: TD recorded a crash since your last report. It will be included.

That section of the report tells the agent that the file is everything it gets: it may not read your terminals, scrollback, transcripts or files, or ask you to paste terminal output. Where the files go

PathHolds
~/.local/state/terminal-delight/bug-reports/<unix-seconds>/report.mdOne report per click of step 1. Nothing deletes them.
~/.local/state/terminal-delight/bug-reports/.last-preparedWhen the last report was written, which is what the orange dot is measured from.
~/.local/state/terminal-delight/crashes/<nanoseconds>-<pid>.txtOne record per crash, written on its own, kept on this machine. Nothing deletes them.
~/.local/state/terminal-delight/logs/window.log, host-<session>.logThe window's and each session host's error output. When a log is over 4 MiB as a process starts, it is moved to .log.1, and one old copy is kept.

$XDG_STATE_HOME replaces ~/.local/state when it is set to an absolute path. A window started from a terminal keeps writing its errors to that terminal, and any TD_…DEBUG switch keeps them out of the log, so key traces never land in a file (see Environment flags).2

What a report holds

  1. # Terminal Delight bug report, the time it was prepared, and Nothing in this file has been sent anywhere.
  2. ## What happened: a placeholder for your own words, the one part that needs you.
  3. ## What this file holds, and what it never holds: the promise below, in the file itself.
  4. ## System: the window's build (the installed binary's name, which carries its commit, and the version), the builds of any session hosts running, the OS name, the kernel version, $XDG_CURRENT_DESKTOP and $XDG_SESSION_TYPE. A value it can't read says unknown.
  5. ## This window: how many tabs and panes, with panes counted by kind (shell, claude, codex, remote, other). Another program is counted as other, never by its name.
  6. ## Crashes TD recorded (newest first): up to five crash records, whole.
  7. ## TD's own error lines (the last 80 per log, repeats folded): from up to six logs. Only lines Terminal Delight wrote about itself count: they start terminal-delight or td:. A line about launching an agent is left out, because it names a project's path.
  8. ## For an AI agent reading this file: the rules quoted above.

It never holds your terminal's input or output, scrollback, screen rows, pane titles, working directories, command lines or a screenshot. Nothing is collected about your GPU, theme or settings. You can delete any line before it goes anywhere.2

How values are blanked

Each error line, and each crash's message, has these replaced by ‹…›:3

  • a quoted value: anything between backticks or double quotes, and between single quotes when the quote starts a word, so can't survives;
  • a link: letters followed by ://, up to the next space or closing bracket;
  • a path: a word starting / or ~/, up to the next clause break, so it can take a few words past the path.

Relative paths such as notes/x.md, host names and email addresses are left as they are unless they were quoted. A crash record goes in whole: below its scrubbed message are the place in Terminal Delight's source where it failed and up to 120 lines of backtrace, which name source files as they were on the machine that built the binary.

What would prove this wrong

Any text from a terminal in a prepared report: a line you typed, something a program printed, a pane's title or a directory you worked in. The test that writes a whole report plants a password, a project name, a program name and a home path, and fails if any of them appears.
