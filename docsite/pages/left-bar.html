The left bar is a tree down the left edge of the window with every tab in the session in it. A tab is a task. Tasks are filed under a project, optionally inside a group, and no deeper than that.

Each task row shows what its agents are doing: a robot that breathes while an agent works and blinks when it needs you, ✅ when it finished, ❌ when it finished against an error, 📌 for a pinned note. Fold a branch and those marks roll up onto the branch row, so a folded project still blinks when something inside it asks a question.

Click a task to go there; a project or group row takes you to its first tab. Drag a task onto a branch to file it, or carry the active tab with Ctrl+Shift+Alt and the arrows. Alt+L finds a project, group, tab, pane or sticky note by name. A deleted branch or closed tab waits in the bay at the foot of the bar for an hour or more, and Ctrl+Shift+Z brings it back.

Ctrl+Shift+B shows and hides the bar.

A new 0.5.0 window opens in the Clean design, which lists tabs across the top and keeps the bar shut until you open it.

Technical has every mark, key, menu and saved setting.

The tree has three kinds of row, two layers deep: a project contains groups, a group contains tasks, and a task may also sit directly in a project. A group is the same thing as a tab group on the tab strip; the tree gives it a project. Tasks filed nowhere sit below the UNFILED line, which stays a drop target even when every tab is filed.1

What each row shows

RowDrawn as
ProjectA filled colour dot and an UPPERCASE name. A new project's colour comes from its id.
GroupThe group's colour band stood on end, the same band its tabs sit on in the tab strip. New groups start teal; Colour… on the group menu changes it.
TaskA small swatch in the tab's colour, the tab's name (or its number when unnamed), its level mark, one badge per agent pane, 📌 for a pinned note, and a × on hover that closes the tab.

The active task wears a ring, and the project and group that hold it wear a faint wash of their own colour. Rows carry no counts.

Marks

MarkMeans
robot, yellow HEY blinkingAn agent needs input. It blinks on a 700 ms square wave.
robot, breathingAn agent is working (a 1.4 s breath).
✅An agent finished. Clears when you visit the pane.
❌An agent finished with an error on screen. Clears when you visit.
📌A pinned sticky note on a pane in this task. Steady, never pulsing.
▲ green · ▼ bluePromoted or demoted. A task inheriting a level from its branch shows it at half strength.

With more than one agent in a task, the loudest wins: needs input, then working, then finished. An idle agent shows nothing. A folded branch shows one robot and the ✅ ❌ 📌 of everything under it; an open branch shows nothing, because its tasks are on screen.2

Moving around

KeyDoes

Ctrl+Alt+↑ ↓Move the highlight one row, wrapping at both ends. Opens and activates nothing.

The arrow and number chords only work while the bar is open, and they travel over what is drawn, so folding a branch lets the same key press go further. A click on a task goes to it. A click on a project or group goes to the first tab anywhere in that branch; a click on the branch you are already in changes nothing. Double-click any row to rename it: a project or group takes 24 characters, a tab 18. Clicking a fold triangle folds without going anywhere, and the triangle in the bar's header folds or opens the whole tree.3

Finding by name

Alt+L opens LOOKUP, a list of every name in the window: each project, group and tab as the bar shows it, each pane by its header title, and each sticky note by its words. Under every name is where it sits, such as WORK › api · 2 panes, so twenty panes with the same title can be told apart. With nothing typed it is the tree laid flat with every fold open.4

  • Type to narrow it. The letters you type have to appear in order, though not side by side, and a project outranks a tab that matches as well, so typing a project's name lands on the project.
  • ↑ ↓ or Tab select, Enter goes there, and Esc or a second Alt+L closes it. The footer reads ↑↓ select · ↵ go · esc close.
  • A pane or note goes to its tab with that pane focused. A branch goes to its first tab; if you are already in it, the bar unfolds it and highlights it instead.
  • Nothing matching reads Nothing here is called “…”.

Filing

Drag a task onto a branch row to file it inside. The top or bottom quarter of a branch row, or either half of a task row, puts it above or below instead, and a chip reading into <name>, above <name> or below <name> says which. Dropping onto a task takes that task's branch and place. Dropping onto a project takes the task out of any group. Drag onto the UNFILED line to file it under nothing. Drag a project above or below another project to reorder them.

A group with no project can be dragged into one. A group already filed under a project stays there: a drop on a different project is refused and nothing moves. To move it, drag it to the UNFILED line first, then file it where it belongs. A group can't go inside another group.3

You can also drag a running pane by its header onto the tree. Dropped on a task, it joins that tab as another pane; a tab already holding four panes refuses it, its row shows red while you hover, and the layout is left as it was. Dropped on a project, a group or the UNFILED line, it becomes a tab of its own there.

Ctrl+click a task for its tray, which has a project section with a chip per project and ＋ new project. Adopt loose tabs into their directories, on the header's menu, files every unfiled task under a project named after its git root (a worktree counts as its own root), or its working directory outside a repository. It never moves a task that is already filed.

Carrying a tab from the keyboard

Add Shift to the walking chords and the tab travels with the highlight. The carried tab is the highlighted task if the highlight is on one, otherwise the active tab. Like the walk, it only works while the bar is open.3

KeyDoes
Ctrl+Shift+Alt+↑ ↓Move the tab one place up or down. At the edge of its group it steps out into the next group, and at the edge of its project into the next project, in the same press.
Ctrl+Shift+Alt+←Widen the step, from a place to a group to a project. Moves nothing by itself; the next ↑ or ↓ takes the tab to the previous or next group in its project, or the previous or next project.
Ctrl+Shift+Alt+→Narrow the step again.
EscStop carrying.

The highlight ring follows the tab, or the group or project it would move between at a wider step. Only the tab travels; a group never leaves its project this way.

Making branches

The + in the bar's header, and New project on the header's menu, make a project holding a fresh terminal. New group does the same for a group. New tab here on a branch's menu makes a tab in that branch, and Ctrl+Shift+T one in the branch you are in. Each opens on its name box: type a name and press Enter, or press Esc to keep the name it was given, such as project 7, and go to the terminal.

The bay

The bay sits at the foot of the tree: two doors in a frame that open a little when you start dragging and all the way when you drag over them, reading drop here to delete and then release to delete. Deleting a project or group, closing a tab when more than one is open, and dropping a task or pane into the bay all put it there. Its shells keep running.5

  • Anything with one pane stays recoverable for an hour; two or more panes, four hours. The bay holds ten things; the eleventh pushes out the oldest, whose shells then end.
  • Deleting a branch that holds anything asks first: DELETE PROJECT? or DELETE GROUP?, Enter to delete, Esc to cancel. An empty branch goes without asking.
  • With something inside, the shut doors read N recoverable. Click them, or right-click the header, and pick a row such as Recover project “api” — 42m left; the time reads under a minute, 42m left or 3h 5m left.
  • A recovered branch comes back with its groups and its tabs in their old places. A recovered pane comes back to its old place if it can, and says which: back where it was, back in its tab, in a new seat or back as its own tab.
  • The bay's contents do not survive the window closing.

Under the tree

Below the bay, the bar shows one row per AI subscription with how much of its allowance is left. Usage and vitals has what those rows read and how to change them.

What is saved

The tree lives in the session's layout file, ~/.config/terminal-delight/sessions/<session>.toml, so a second window on the same session shows the same tree. See Sessions and restarts.

KeyHolds
[[projects]]id, name, color, collapsed, level
[[groups]]id, name, color, text_color, collapsed, project, level
[[tabs]]each tab's name, color, group, project and level
left_barShown or hidden. Absent means the default, which is shown.
left_bar_wWidth, 132 to 420 px; the default is 208. Written only once you drag the edge.

level is Promoted, Neutral or Demoted. A missing level means "inherit from the branch", which is a different answer from Neutral. Files from older builds that mention a branch pin or a strip scope still load. Scratch windows and demo windows never show the bar. terminal-delight ctl tab and ctl tabs can name and group your own tab from a script (see ctl); there is no scripting for projects yet.

In 0.5.0

  • A new window wears the Clean design, whose UI set asks for tabs across the top instead of the bar. The handle that opens the bar is always there. Opening the bar yourself, with Ctrl+Shift+B, the handle or a new project's name box, is saved as your own choice and keeps it open; UI CONFIG has the switch.6
  • In tabs view, the project chip at the head of the tab strip opens a switcher listing every top-level project and group in the tree's order, with the one you are in lit. Choosing one goes where a click on its row in the bar would. This applies to every skin. In 0.4.0 the chip goes to the project's first loose tab.
  • Under the TERMINIMALIST skin, or any skin with controls = "text" and boundary = "none", ADD PROJECT stays at the top left whether the bar is open or shut, with a hairline between it and the handle. The handle reads SPINE to open the bar and TABS to close it, branches fold with + and −, the status and pin marks are compact words and symbols, levels are green up and blue down arrows, and the selected task is shown by a thicker bar beside its title. The bar's header and the bay are not drawn there; Ctrl+Shift+Z still brings back what you closed.

Not yet

  • Clicking a project does not open an overview of it; it goes to its first tab.
  • There is no keyboard path to delete a branch. Use the menu or drag it to the bay.
  • The F1 help has no row for Ctrl+Shift+B or for carrying a tab yet.

What would prove this wrong

If a folded branch holds an agent that is asking you something and its row does not blink, the roll-up has failed at the one job it exists for. That is a bug worth filing with the tree's layout file attached.
