Press Alt+A in any pane, or ⌁ AGENT in its header. A panel opens with your projects listed, newest first, and the one you're in already picked. On a pane with nothing on its workbench, ⌁ LAUNCH AGENT or ↵ opens the same panel.

Type to filter, then choose Claude Code, Codex or a local program you've set up, a model, an effort level, and how far the agent may go without asking: this repo, this machine or anywhere. The model and effort lists come from the Claude Code and Codex you have installed. Agent default passes neither, so the agent uses its own settings. The bottom of the panel shows the whole command it will run, and ↵ runs it.

If the pane you started from is sitting at a shell prompt, the agent starts right there. If something is already running in it, you get a new tab instead, next to the one you're in. The last line of the panel tells you which before you press ↵.

Every agent the panel starts is also told about the Threshing Floor in its briefing.

Technical has the keys, the exact commands and where the defaults live.

Opening it

  • Alt+A in a pane, on either face.1
  • The ⌁ AGENT chip in a pane's header, beside the TERM ⇄ BENCH switch. A narrow pane shows just ⌁.
  • The ⌁ LAUNCH AGENT button under NOTHING ON THE WORKBENCH, or ↵ on a workbench with no agent and no card open.
  • When a pane's agent has ended, the verb at the end of its bench strip changes from END SESSION to LAUNCH AGENT.

The panel is titled ⌁ LAUNCH AGENT, with sections PROJECT, HARNESS, MODEL, EFFORT and REACH.

Projects

Directories one level deep under a fixed set of folders, your home directory and ~/Work among them, newest-modified first, with hidden directories skipped. The set can't be changed yet, so projects two levels down, such as ~/code/app, don't appear (issue 802). ◆ marks a git repository. Matches rank by exact name, then prefix, then anywhere in the name, then anywhere in the path; a repository beats a plain directory at the same rank. Up to 1,000 directories are read and 40 rows show; the filter reaches the rest. With nothing matching: nothing matches — ⌫ to widen.

Models and effort

The model and effort chips are whatever the installed program says it offers. Terminal Delight asks Codex through codex app-server, leaving out models Codex marks hidden, and Claude Code through a one-off claude --print session that saves nothing and loads no MCP servers.2 Under the model chips a status line reads Loading models…, Installed agent catalog, or Models unavailable · and the reason. Click it to ask again. An answer is kept for a minute, and one that takes longer than 15 seconds counts as a failure. While the list can't be read, the only model on offer is Agent default.

ChipMeans
Agent defaultAlways first, in both rows. Passes no --model or effort, so the agent uses its own configuration.
opus 5.5A known model family with its version. A name Terminal Delight doesn't know is shown whole.

… · unavailableA saved model or effort the program no longer lists. It stays visible until you change it.

The effort row lists the levels the chosen model reports, so it changes with the model; a model that takes no effort setting offers only Agent default. Changing the model puts effort back on Agent default. ↵ refuses an unlisted choice with Selected model unavailable · and the status, or Selected effort unavailable; choose Agent default or a reported effort.

The command

TD_BRIEFED=1 claude [--model <model>] [--effort <effort>] [reach] --append-system-prompt "$(cat '<briefing>')"
TD_BRIEFED=1 codex [--model <model>] [reach] [-c model_reasoning_effort=<effort>] "$(cat '<briefing>')"'<wait for a task>'
TD_LOCAL_AGENT=1 '<your command>' '<its arguments>'…

The bracketed parts appear only when chosen. The briefing is the workbench's instructions to the agent, written owner-only to briefing.txt in the session's folder under ~/.local/state/terminal-delight/surfaces/. Claude Code takes it as an appended system prompt. Codex takes it as its first message, followed by a line saying this is launch context only and to wait for your task, and keeps its own AGENTS.md. TD_BRIEFED=1 tells a briefing hook in that agent that it has already been told; an agent you start by typing claude gets the same text from that hook. When the window has a desktop connection, the line begins with env and whichever of DISPLAY, WAYLAND_DISPLAY, XDG_RUNTIME_DIR and XAUTHORITY are set.

A local program

Choose local to start a program of your own, declared in ~/.config/terminal-delight/local-agent.toml as a list of arguments:

command = ["my-agent", "--instructions", "{briefing}"]

The first entry is the program. Three tokens stand in for what Terminal Delight provides, and each must be a whole argument on its own: {briefing} is the path to the briefing file, {context} is the briefing as a first message, the way Codex gets it, and {prompt} is a task, which the panel doesn't send. The command needs {briefing} or {context}. Every argument is quoted, so nothing in the file is run as shell script.1

Model, effort and reach belong to the file, so the panel hides those rows and says Model, effort and permissions come from local-agent.toml. The file is read each time the panel opens. If it's missing or wrong, the error takes the command's place at the bottom of the panel, for example command needs a whole argument {briefing} or {context} to receive TD instructions, and ↵ repeats it and starts nothing. The program is typed at the shell like any other launch, so the pane is a shell again when it exits.

Where it lands

If the pane you opened the panel from is known to be at an idle prompt, Terminal Delight types into it: Ctrl+U to clear anything half-typed, cd to the project if the pane is somewhere else, then the command. If the pane is busy, or hasn't been read yet, a new tab opens in the same branch of the left bar. The hint ends in ↵ starts in this pane or ↵ opens a new tab. The pane keeps whichever face it had.

Each launch is recorded in launches.jsonl in the session's folder: program, model, effort, reach, directory, command, where it landed and a fingerprint of the briefing it was handed.

Defaults

Open Σ usage and unfold ▸ LAUNCH AGENT CONFIG at the top of the card.3 It has three rows, harness, model and effort, each tagged chosen or unset. An unset row still lights the value the panel would use. The model and effort rows read the same lists as the panel, with the same status chip to click when they can't be read; with local chosen they give way to The local runner uses local-agent.toml. Pressing a lit harness chip clears it, and Agent default clears model or effort. Each press writes ~/.config/terminal-delight/launch.toml at once:

harness = "codex"
model = "gpt-6.1-sol"
effort = "high"

Every key is optional. A missing file, or a harness word no program answers to, reads as unset, and unset means Claude with Agent default for model and effort. Reach is never stored.

After it starts

The bench strip reads, for example, CLAUDE ▾ · HIGH ▾ · END SESSION. The model and effort dials ask the agent running in that pane for their lists, so they match the program and profile it was started with, and the model dial names the version, such as OPUS 5.5. When the list can't be read, the dial offers the status and retry. Choosing a value types the program's own /model or /effort command and keeps whatever you had in the composer; see the workbench. The launcher only starts agents; bringing one back is the job of session restore and the graveyard.

What the briefing adds

The briefing every launched agent gets opens with loose cues for choosing between an existing Terminal Delight teammate, a native subagent where the program allows one, and doing the work itself. A later paragraph teaches the Threshing Floor: what a line is, the floor_position tool for where it stands, how to answer a turn that opens with [Threshing Floor prompt <n>, from …], and how to hand work out along a line with a work order that says how it will be judged done, another try when a reply falls short, and its person told after two or three tries. Codex gets it in its first message, as it gets the rest.4

What would prove this wrong

If ↵ ever types into a pane whose prompt hasn't been read, the landing rule has failed. If a model chip ever appears that the installed program doesn't report, or the panel launches a model marked unavailable, the lists are being guessed rather than read. The command at the bottom of the panel is built by the same code that launches, so it should match the line in launches.jsonl exactly.
