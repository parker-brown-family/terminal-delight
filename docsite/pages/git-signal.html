Two agents can edit the same file in two checkouts of one repository, and nothing tells you until their branches meet. The GIT signal at the top left of the window watches for that across every project in the window. Most of the time it reads Git · No new findings. When something needs a look it reads Git · 1 project with new findings, in yellow for a warning or red for a conflict.

Press Alt+G, or click the signal, to open GIT COORDINATION. It shows a card per project and, under each, the findings: panes sharing one working folder, the same file changed in several working copies, a merge check that says a branch will not combine cleanly with main, or Git's own unresolved merge entries. Each finding has a Why shown? line saying what was seen and what that does not prove. Sharing you intend can be marked expected for 15 minutes, an hour or four hours.

It only looks. It never commits, fetches, checks out or edits a file. Agents can read the same findings through four read-only MCP tools.

Technical has every finding, how often it checks, what it runs and the MCP tools.

A project here means a branch of the left bar: the project a tab is filed under, else its top-level group, else Unfiled, whichever repositories its panes are in. Each pane is placed by the working directory of the program in its foreground, and a directory becomes a checkout through git rev-parse --show-toplevel. Panes filed under other projects that sit in the same repository are counted in, so filing a tab somewhere else cannot hide an overlap.1

The signal

The signal sits in the top bar's left corner, after the app's mark. It sums every project in the window, so a quiet project you are standing in cannot silence an alert in another.2

It readsMeans
Git · No new findingsEvery check that finished found nothing new.
Git · No new findings · scan incompleteNothing new so far, but some working folders could not be checked.
Git · 1 project with new findings, Git · 3 projects with new findingsA finding nobody has marked seen. Red when the loudest is an alert, yellow when it is a warning.
Git · 1 project with a conflict · seenA conflict you have marked seen. It stays on the signal until it is resolved.

Clicking the signal opens or closes the inspector.

Each sentence carries what it does not prove: Sharing is observed; simultaneous editing is not established., A shared file path does not establish a conflict., Uncommitted edits were not included. and An incomplete check does not establish that work is clear. A file only one working copy touches is never a finding, separate clones of a repository are never matched with each other, and unpushed commits and ahead/behind counts are shown in the evidence but never raise a finding on their own. The target is the first of origin/main, main, origin/master and master that exists.13

Seen and expected

Mark seen · keep the condition visible stops a finding counting as new without hiding it. This sharing is expected… is offered only on a shared checkout or shared file, only while the evidence is fresh and only when the branch and checkout are known. It offers 15 minutes, 1 hour (the default) or 4 hours, each confirmed with Confirm expected for …, and quiets sharing notices for that scope; conflicts and missing observations stay visible. While it holds, the glance line reads Expected until and the time. It ends when the time runs out, when the branch or file set changes, when the evidence goes stale, or at a restart, after which it asks to be confirmed again. Revoke expectation and Change expectation undo or adjust it.4

These marks are saved per session in ~/.local/state/terminal-delight/coordination-attention/ (under $XDG_STATE_HOME when it is set), one JSON file with a lock beside it. Records older than seven days are dropped, and the file holds 512 at most.

How often, and what it runs

A background loop wakes every two seconds and scans one project whose reading is twenty seconds old or older, the project you are in first, one scan at a time. Sitting still costs one scan per project every twenty seconds; switching projects gets a fresh reading within a few seconds.2

Every Git call runs with GIT_OPTIONAL_LOCKS=0, so git status never takes the index lock from under an agent, and each call is killed at its deadline (three to eight seconds a call, ten seconds a checkout). The commands are reads: rev-parse, symbolic-ref, status --porcelain, diff --name-status and diff --numstat, log, rev-list --count, merge-base, worktree list, stash list, remote get-url origin, and merge-tree --write-tree for the integration check. Nothing commits, fetches, checks out, garbage-collects, or touches refs, the index or your files. The one write is merge-tree's: it stores the trial merge's tree and blob objects in .git/objects, where nothing points at them and Git's own housekeeping prunes them in time. A scan stops at 20,000 paths, 128 checkouts or 4 MiB of output and says the scan was partial.3

For agents

Four read-only MCP tools serve the same findings. They need the MCP server on (see MCP server); with it off they answer MCP exposure is disabled.5

ToolArgumentsReturns
coordination_overviewcursor, limit (1–100)Every project the agent may see, its findings, how complete the evidence is, and the exact arguments for a follow-up read.
coordination_projectproject_id; view = meanings, checkout_id, cursor, limitA project's coordination groups, checkouts, branches, panes and sessions, and what could not be observed. view: "meanings" pages the explained findings; a checkout_id pages that checkout's file and conflict evidence.
coordination_clusterproject_id, cluster_id, cursor, limitOne group's joined evidence: panes, sessions, checkout roots, branches, where each change came from, and what is uncertain.

An agent sees only the panes it is allowed to see. When every pane is exposed, the agents' view and the inspector's are the same; when some panes are hidden from agents, the inspector shows you the fuller picture. Branch names, paths and titles in the answers are marked as untrusted terminal data.

On 0.5.0 which panes an agent may see is decided in the Threshing Floor, so a seated pane is left out of the agents' view unless a line reaches it.6

Hiding it

In 0.4.0 the signal is always drawn and has no switch. Alt+G is listed in the F1 help as Open Git coordination. There is no ctl verb for it.

On 0.5.0 the signal is a switch in UI CONFIG, git notice, saved as git_notice under [outer]. A new window opens in the Clean design, whose UI set hides it, so on a fresh 0.5.0 window the signal is not on screen until you turn it on; TERMINIMALIST asks for the same set. A switch you flip yourself always wins. While the signal is hidden, its red or yellow moves onto the CONFIG button, and Alt+G still opens the inspector. The findings and their sentences are the same as in 0.4.0.6

What would prove this wrong

Run two agents on one repository in two worktrees and have both change the same file. If the signal still reads Git · No new findings after twenty seconds with both changes uncommitted, the shared-file finding has failed. And if any Git command from Terminal Delight ever leaves an index.lock behind or moves a ref, the page is wrong about the one thing it promises.
