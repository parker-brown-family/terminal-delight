Run terminal-delight and one window opens with one terminal in it. Behind the window, a small background process called the session host starts and takes charge of your shells, so closing the window, or losing it to a crash, doesn't end them.

A new install opens flat, in Terminal Delight's own colours, with the tube switched off. Each pane wears Terminal Delight's mark in its header. The left bar down the left side holds your session as a tree of projects, groups and tasks. In the top right, the agent counter tallies your agents by state, and a click opens the agent wall. The window's own controls sit at the bottom right.

A few things to try first:

F1every shortcut, and the language
Alt+Astart an agent in this pane
Alt+V / Alt+Hsplit the pane side by side, or stacked
Alt+arrowsmove between panes
Ctrl+Shift+Ta new tab
Alt+Kturn a pane to its workbench and back

Typing claude or codex at a prompt works too: Terminal Delight notices the agent. Close the window and open it again, and your tabs, splits, directories and agents come back where they were.

0.5.0 opens a new window in the Clean design, with tabs across the top instead of the left bar and fewer controls on show. See UI CONFIG.

Technical has which session a window opens, what is written to disk and when, and what 0.5.0's first window looks like.

Which session opens

A session is a set of tabs and panes with a name of its own, 1, 2 or work, saved as ~/.config/terminal-delight/sessions/<name>.toml. A window opens:1

  1. the session in TD_SESSION, if set;
  2. otherwise a session whose host is running with no window attached, which is what happens when you close the window and open it again;
  3. otherwise the most recently saved session, preferring one last used on this Hyprland workspace and one with more than a single pane;
  4. otherwise a new one, numbered from 1.

The window's title says which: terminal-delight — 1. In its log it writes attached to the session host for session '1'. If no host can be reached, it says so and opens anyway, owning its terminals itself. Sessions has the rest, including running without a host.

A window opened by another program through xdg-terminal-exec, as Omarchy opens every terminal once Terminal Delight is the default, is a quick window: it never takes a session. Omarchy has how that works.

The window

  • No title bar from the desktop: Terminal Delight draws its own frame and its own — ☐ ✕. Drag the top bar to move it. ✕ saves before closing.
  • With no saved size, it opens at 1280 by 720, centred.
  • At startup it reports the GPU and driver it found, and warns if the theme's font is missing. The window and the session host log to ~/.local/state/terminal-delight/logs/.
  • Narrower than 720 px, the controls at the bottom right fold into a … menu.

The first look

A new install opens flat: the Terminal Delight palette, which ships inside the app, with the tube switched off and contrast raised to make up for the glow a flat screen doesn't have. Every pane follows the window's look until you dress one. The tube is a switch in the collapsed CRT section at the foot of GAUGES (Ctrl+Shift+G for a pane, ⛭ at the bottom right for the window), and switching it on brings the warp and the roll already set. An install that ran an earlier version keeps the tube it had.2

Each pane's header shows Terminal Delight's mark, because the first start maps /, the folder every other folder sits under, to it. Themes and CRT say how to change any of it.

What is written, and when

FileWritten
~/.config/terminal-delight/theme.tomlAt the first start, as a copy of the built-in hacker theme, so you have a file to edit. It reloads as you save it.
~/.config/terminal-delight/dir-logos.toml and logos/terminal-delight.pngAt the first start, only if dir-logos.toml doesn't exist. An existing file, even an empty one, is never touched.
~/.config/terminal-delight/sessions/<name>.tomlAt the first save, then after every layout change and every 30 seconds.
~/.local/state/terminal-delight/logs/As the window and the host run; crashes/ beside it only after a crash.
launch.toml, local-agent.toml, documents.tomlOnly when you save a setting that lives there.
conversations, brief backups, Markdown notes, handover listsUnder ~/.local/state/terminal-delight/, only once there is something to keep.
~/.cache/terminal-delight/pages/Only when an HTML page is opened: renders kept for next time, up to 256 MiB.

$XDG_CONFIG_HOME, $XDG_STATE_HOME and $XDG_CACHE_HOME replace the three folders when they are set. Config files lists every file.3

What's saved

The session file keeps the window's size, every tab with its name, colours, group and project, the split layout, the left bar, the look, the MCP switches and the language. For each pane it keeps the directory the foreground program is in and, if that program is Claude Code or Codex, the command that resumes its conversation: claude --resume <id> or codex resume <id>. Reopening starts a shell in that directory and types the command.

A save that would lose more than half the panes or tabs without your having closed them is refused, and the last ten versions are kept in sessions/backups/.

Closing

Closing a tab sends it to the bay at the foot of the left bar, still running, and Ctrl+Shift+Z brings it back. Closing the last tab asks first, then ends its shells and quits. A session host with no window attached and nothing printed for twelve hours saves and stops.1

The first window in 0.5.0

A new window wears the Clean design: no tube and no glow on the letters, corners that are nearly square, and the Terminal Delight palette with INHERIT on, so it follows your Omarchy theme. Clean also asks for its own set of chrome. Tabs run across the top instead of the left bar, and the ◀/▶ handle brings the bar back. The app mark, the Git notice and the agent counter are hidden; the attention pill at the top right stays. The bottom-right glyphs, among them the graveyard and the 📜 artifact rail, fold into a CONFIG menu, and each pane's header comes down to its title, its state and its ⋯, with the handover chip and the rest folded in there.4

Every one of those is a switch in UI CONFIG, and a switch you flip there beats Clean. The default for new windows can be changed too. A session saved by an earlier version opens the way it was saved.

On the desktop

From a source checkout, scripts/install-desktop.sh adds a launcher and icon. On Omarchy, scripts/install-keys-hotkey.sh binds Super+Alt+T to a searchable list of every Terminal Delight key, and terminal-delight default-terminal on makes it the terminal the desktop opens. Omarchy has all three.

What would prove this wrong

A first start on a machine with no ~/.config/terminal-delight/ should leave behind exactly the files the table names as written at the first start, plus the session file once it saves. Any other file there before you've used the feature it belongs to means a default was written that nobody asked for.
