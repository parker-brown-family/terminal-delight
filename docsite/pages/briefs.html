When an agent hands you something to decide on, you answer it on the page. A decision brief, one HTML page an agent draws, and any Markdown file you open in Terminal Delight both take notes: on a brief, each figure, finding and decision; in Markdown, each heading, paragraph, code block and list item. A decision also takes a CONCUR stamp.

Point at an element and click its 💬, or hold Alt to outline everything that takes a note. Write, then Ctrl+Enter. A note box takes a paste, pictures included. ↪ send to agent, or Ctrl+Shift+Enter, puts every note in the agent's prompt, tied to its element, without pressing Enter. An agent can also read them with the MCP tool document_notes.

A brief keeps its notes inside its own file; Markdown notes are kept by Terminal Delight, and the .md is never touched. Agents started from LAUNCH AGENT are told how to build a brief, and the kit they build it with ships inside Terminal Delight.

Technical has how notes are saved, where they go, and what the agent is told. Opening documents is on Documents.

What takes a note

DocumentTakes a note
Decision brief (HTML)Every element the brief's notes script marks: by default each figure, read-first item, finding, verdict card, stat tile, table row, chart row, callout, decision and dialog subheading. A brief can choose its own.
MarkdownEach heading, paragraph, code block, quote, table, HTML block, picture on its own line, and each top-level list item; a nested item goes with the item it sits under. Rules take none.
Any other HTML pageNothing. It opens and reads normally.

Point at an element and its 💬 appears; once it has notes, the button shows their count and stays, and a rule runs down the element's left edge. Hold Alt over the document to outline everything that takes a note, then click inside an outline to open its box. Until the first note, a line above the notes bar says how: click anything to note it · hold Alt to see what takes one · ✓ stamps a decision · ↪ sends your notes to agent. The stamp clause appears only on a brief that takes stamps, and the send clause only with an agent beside the document.1

The note box

Ctrl+Enter or Add note adds the note, Enter starts a new line, and Esc or a click outside closes the box. A note holds up to 20,000 characters. Each note in the box has a delete.

Ctrl+V, Ctrl+Shift+V and Shift+Insert paste text at the caret, and copied files as their paths. A pasted picture, or copied picture files, are attached to the element the note is on: the bar says attached as [doc-image #1], and the box lists each picture by that name with its time and a delete. Pictures are kept in $XDG_STATE_HOME/terminal-delight/notes/pictures/, never written into the note's words or the document.2

A note on words the file no longer has can still be read and deleted, behind N on words no longer here.

The box's button reads Submit comment. A box with more notes than fit scrolls: the wheel, PageUp and PageDown, Ctrl+↑ ↓ and Ctrl+Shift+↑ ↓ turn it, and it opens on the newest. In 0.4.0 older notes past the box's height are hidden.

CONCUR

On a brief whose notes script supports stamps, each decision carries a dashed slot reading ? over CONCUR. Click it to stamp the decision; click the stamp to peel it off. A concur with no note means the decision is approved as recommended, and the kit tells the agent to read it that way. A brief whose script predates stamps refuses one: This brief's notes script is older than CONCUR stamps, so a stamp saved here would never show.3

Saving a brief

A brief's notes are saved into the brief itself. The notes bar reads, left to right: the count (2 notes · 1 concur), ⎘ copy map, the send button, 💾 save into file, and N unsaved while edits wait. A save changes only the notes inside the file, then reads it back: saving into …, saved into … · reading it back…, and saved into … ✓ once the reopened file shows every note and stamp.

  • Before each save, the file as it was is copied to $XDG_STATE_HOME/terminal-delight/brief-backups/, readable only by you, and the newest eight copies of each brief are kept.
  • A brief that is a symbolic link, or has a second name on disk, is never saved into. A brief that changes on disk during the save is left alone, and your notes stay to save again.
  • Closing the square with unsaved notes warns once: N unsaved · save them into the file, or close again to leave without them. Closing the pane or the tab does not ask.

Every note, deletion and stamp is saved into the brief the moment you submit it, so a closed square loses nothing. The bar has no save button, and sending the notes never writes the file. N unsaved appears only when a save failed; the next edit, or ctl doc save, tries again. Closing with notes not yet written warns N not kept · close again to leave without them.4

Markdown notes

A note on a Markdown file is kept the moment it is added, in $XDG_STATE_HOME/terminal-delight/notes/, one file per document named from the file's name and a hash of its path. The .md is never written. The notes bar has no save button.5

Each new note also keeps what it was written on: the passage's words, the passages either side, and the SHA-256 of the file as it was read. When the file is edited, the note follows its passage:

The note saysWhen
same revisionThe file has not changed.
quotation matchedExactly one passage of the same kind has the same words, wherever it moved.
quotation and context matchedSeveral passages have the same words, and only one has the same neighbours.
wording changed; context matchedThe words changed a little: at least six words, most of the passage still running the same from its start or its end, and a neighbour unchanged.
passage not found, ambiguous passage; no automatic attachmentNo passage, or no single passage, fits. The note waits under N notes without a clear passage.

The note box and the notes map show each note's Original quotation, Revision SHA-256 and Attachment. A note written by an older build reads legacy note; quotation and revision unavailable; nothing is made up for it. A store gains this as format 2 on its next save, and a 0.4.0 window refuses to overwrite a format 2 store; it shows none of its notes. Two saves to one document at once take turns, so neither loses the other's note, and deleting a note while it is being saved deletes it without dropping the next one.6

Sending notes to the agent

↪ send to agent in the notes bar, or Ctrl+Shift+Enter over the document, sends the notes map to the agent beside the document: the agent in the pane the square floats over, otherwise the nearest agent pane in the same tab. With several candidates the button names the pane instead of saying agent. With no agent in the tab there is no button, and ⎘ copy map puts the map on the clipboard instead. On a brief with unsaved notes the button reads ↪ save & send to agent, and the save starts first.7

The notes map

Each line in brackets points into the document, so the agent finds the passage without rereading it. In a brief it is an element id:

NOTES — 2026-09-25-telemetry-cache.html
2 notes on 2 elements · 1 concur.
Each [anchor] is an element id in that file — search it to find the passage.

[readfirst-a-60-second-cap] A 60-second cap costs 0.6 points. The cap evicts anything older than …
  · Is 60 s the planner's own limit?

[fig-03-age-of-the] 03 · Age of the reading served
  · Show the cold start too, not only the quiet pass.

[ask-1-evict-by-recency] 1 · Evict by recency or by age?  ✓ concur

In Markdown it is the line the block starts on:

NOTES — /r/plan.md
1 note on 1 block.
Each [L<n>] is the line in that file where the block starts.

[L7] ## Slice 2 — the agent side
  · before slice 1 please

A pasted picture appears under its note as · [doc-image #1] and its full path, and the map explains Each [doc-image #n] is a picture pasted onto that element — open its path to see it.8

document_notes

An agent connected to the MCP server calls document_notes, with no arguments, to read the notes on the document beside it: a square floating over its own pane, else a pane it opened beside, else the first document pane in its tab. The answer names the file, counts notes, stamps and edits not yet saved, and then gives the map, unsaved notes included. Pasted pictures follow as images, up to eight of up to 3,750,000 bytes each in PNG, JPEG, GIF or WebP; any others are named with the reason. It writes nothing and does not need the writes switch. With nothing open it says nothing is open beside you — no brief floats over your pane, and no pane in your tab shows a document.9

A document on a pane marked off-limits to agents is skipped unless it is the caller's own pane.

What the agent is told

The launcher hands a Claude agent its briefing through --append-system-prompt, and writes it to $XDG_STATE_HOME/terminal-delight/surfaces/$TD_SESSION/briefing.txt. When the kit could be written, the briefing carries this paragraph, with the kit's SKILL.md in place of <kit>:10

DECISION BRIEFS. When what you finish is something the person has to read and then decide on — an audit, a review, a comparison of options, a findings write-up, a proposal — build it as a decision brief: one self-contained HTML page, drawn rather than written, that they read inside this window. Read <kit> before you start; Terminal Delight wrote it for you, with the assets it names beside it. Keep it SHORT and DRAWN: five minutes to read, a figure for every argument, prose only as captions, depth in modals. The page is yours to lay out; the surface only points at it, as an `artifact` whose href is the file's absolute path and whose mime is text/html. A click on that card opens the page over the bench, where the person notes any element, stamps CONCUR on a decision, and presses ↪ to paste the notes into your prompt as [anchor] lines, each anchor an element id in your file. A question with a few short answers is a `decision` surface, not a brief; one brief per decision is the rate.

When the kit could not be written, the paragraph is left out. A Codex launch gets the same briefing as its first message, ahead of anything you typed in the panel.

An agent you started by typing

Claude Code runs a SessionStart hook at the start of every session and hands what it prints to the model. terminal-delight briefing prints the briefing a LAUNCH AGENT pane gets, the same text byte for byte, after writing the kit. It prints nothing outside a Terminal Delight pane, and nothing in a pane the launcher started, whose command line carries TD_BRIEFED=1, so the hook is quiet in every other Claude session on the machine.

Nothing installs the hook until you say so. On the bench of a Claude agent the launcher did not start, while the hook is not installed, Terminal Delight asks once, NOT TOLD ABOUT THE WORKBENCH, with TELL THEM and NO THANKS. Yes adds one entry to ~/.claude/settings.json, beside whatever hooks are there, and keeps the file as it was as settings.json.td-backup.<time>. It takes effect from the next agent you start by typing. Either answer is kept in ~/.config/terminal-delight/briefing.toml, and the bench stops asking. From a terminal instead:11

terminal-delight briefing hook status
terminal-delight briefing hook on
terminal-delight briefing hook off

The hook names the binary the way you reach it (the AppImage you downloaded, or the terminal-delight on your PATH), and a binary that has since moved fails silently instead of putting an error in front of every Claude session. A typed codex is not told.

The kit

The binary carries the decision-brief kit and writes it to $XDG_DATA_HOME/terminal-delight/skills/decision-brief/, or ~/.local/share/terminal-delight/skills/decision-brief/, each time LAUNCH AGENT starts an agent and each time terminal-delight briefing briefs a typed one. Only files whose bytes changed are rewritten, so the kit on disk is the one the running build carries.12

The workbench edition asks for less than the skill it comes from: five minutes of reading, at most three read-first items, a figure for every argument, and no paragraph over three sentences on the page.

What would prove this wrong

Open a Markdown file, note a paragraph, and close and reopen it: if the note is gone, or the .md changed, this page is wrong. Over a brief with notes, beside an agent on its bench, Ctrl+Shift+Enter must leave the map in the composer, unsent. And launch a Claude agent from LAUNCH AGENT and open briefing.txt in the session's surfaces folder: if it has no DECISION BRIEFS paragraph, or the SKILL.md it names is missing, the agent was never told.
