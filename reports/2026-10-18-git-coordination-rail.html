Implementation Contract

Identity and scope

Keep declared TD project ID and observed repository identity distinct. Remote origin groups display; Git common-dir plus canonical checkout root identifies a work context. Separate clones require explicitly qualified cross-clone comparison. Preserve detached HEAD, raw path bytes and rename links. Qualify pane/session IDs by instance; multiple panes of one session do not become multiple agents. An uncertain session join stays unknown. Shared checkout occupancy can be shown without attributing an edit.

Required coverage

Keep evidence_coverage for known members separate from membership_coverage for the declared project graph. A partial observed group count is not a lower bound: missing observations may join groups. Required dimensions: checkout/pane association and committed, staged, unstaged, untracked path measurements for the declared scope. Each source carries errors and timestamps. Missing base makes committed coverage partial; staged/unstaged/untracked evidence can still produce a known hotspot. The main ref is labelled an assumed integration target until declared. Qualify stacked-branch ancestry to prevent inherited files becoming unqualified overlap. Idle inventory is measured separately from active coordination; optional line analysis never turns complete path coverage into a line-conflict claim.

Display rules

Version-one defaults: two checkouts with an intersecting path → caution; three or more → warning. Multiple known agent sessions sharing a checkout → warning. Ambiguous identity yields a labelled shared-pane observation and at least caution for two or more observed panes, with distinct-session/agent count unknown. One known session represented by several panes is not multiple agents; occupancy remains visible without implying concurrent authorship. An unresolved or merge-tree-reported conflict names its exact integration target and yields alert. A single-checkout conflict is a finding, not a fabricated multi-party cluster. Complete required coverage with no observed exposure yields clear; partial coverage without known severity yields null. Deduplicate cross-project physical occupancy by observation identity while retaining both declared project labels; never move tabs. Window-wide glance summarizes evidenced alert/warning/caution projects independently of selection. Order alert, warning, caution, unavailable/unknown, then clear; retain project-specific age and stable name/ID tie-breaks. A stale known finding retains severity with an explicit age. Glyph, word and visual weight distinguish alert/warning/caution; selection remains a quiet marker.

Stable snapshots

Publish immutable snapshots with schema version, instance epoch, monotonic version, project timestamps, source OIDs, severity, coverage and limits. Derive severity once with a reported rule version. Preserve separate evidence and membership coverage in project/cluster projections; bridge events report topology and lineage, without inferring improvement from a falling group count. Reconcile cluster membership across scans; unambiguous growth retains ID. Ambiguous splits/merges get fresh IDs with lineage. Bounded delta history expires explicitly; changing instance resets cursors. Freeze the version-one schema after approval and contract tests.

MCP parity

Proposed read-only tools: coordination_overview, coordination_project, coordination_cluster, coordination_changes. Bind drill-down to a snapshot version or report an explicit version change; do not silently combine readings. Unknown IDs return not-found. Every result includes instance, version, observed time, scan age, coverage, truncation and stable IDs. Paginate large results. Keep provenance labels for hostile names/paths. No-change is explicit. Publication and pagination bind to one authorized revision; expiry and reset behavior must be independent of hidden-only activity. Test one shared fixture against actual native UI and real MCP tool responses; the HTML projection here is illustrative and cannot establish production parity.

Authorization before derivation

Share the observation model and graph algorithm; project an authorized fact set before deriving an MCP result. Never redact participant rows from an already-derived all-pane graph. A denied source cannot influence visible paths, counts, ordering, generated titles, cluster IDs/lineage, externally visible revisions/cursors, or change notices. Authorized revisions advance only for changes to that authorized projection; hidden-only changes cannot create activity through a new revision, cursor or delta. Envelope timing uses a declared fixed cadence, independent of hidden observations; project observation times describe authorized sources. Use a generic scope-limited coverage state with no hidden count. Cache by visibility scope/policy revision, invalidate on exposure changes, and test noninterference. A human and agent with the same authorized scope and snapshot see the same facts; the operator’s broader view may legitimately differ.
