Less work between changes

TD now reuses quiet panes’ text drawing and skips screen-update messages from hidden panes. In the mixed-pane test, window CPU fell 29%. The main cost is retained memory; the main uncertainty is how much your changing mix of agents benefits.

Measured on this machineVerified release · paired measurements and native checks completeAbout six minutes · details unfold below

01 The gain

You asked for the remaining savings in drawing and busy hidden panes. Both had avoidable work. These measurements compare the new changes with the already-optimized build, so earlier savings are not counted again.

The benefit needs an explanation beyond a lower number. A profile of the old drawing path showed where to look.

02 Repeated layout

Keeping a whole pane’s drawing would skip important work: its position must be registered each frame for TD’s distortion effects. The fix therefore retains only the text grid.

The text can now stay unchanged between frames. Hidden output still has an earlier opportunity to avoid work: before its screen-update message reaches the interface.

03 Hidden output

Those messages arrived with each output chunk, even when the pane was hidden. The parser must keep reading; the interface can wait until its existing check or until you show the pane.

Both changes depend on recognizing when reuse is unsafe. That is where the tests had to challenge the implementation.

04 What failed

Correctness tests explain why the changes are safe enough to ship. The unfavorable workloads and memory measurements decide whether they are worth keeping.

05 Cost and uncertainty

The least certain engineering choice was replacing the cached view on every content change. It guarantees fresh drawing, but costs allocation. The busy-pane measurements above are the direct check on that tradeoff.

06 Where I stopped

Keep the measured reuse

Recommendation: keep the narrow text cache and hidden screen-event filter. The drawing reduction repeated across launch orders and busy workloads. The hidden filter removes screen callbacks and reduces CPU in the plain-program control; the agent workload remains uncertain.

Keep the current hidden clock

Recommendation: retain the one-second check. Lengthening it risks slower attention and completion updates; these changes remove work without that exchange.

Use concrete rollback signals

Stale text on activation, a selection that fails to repaint, or repeatable CPU growth in the same stress test would invalidate this release. The previous version remains available for a GUI-only rollback.

The release replaces the window while the existing terminal host keeps running. The preceding version remains available for rollback; the local delivery copy records the completed installation.

What was compared

Baseline: clean main at 396f857, with the same application tree as installed f597f3c. Candidate: the two changes described here, built with the same release configuration and dependency checkout. Neither timing binary contains profiling instrumentation. Binary hashes and source provenance accompany the measurements.

Each visible run used two simultaneous 1000 × 700 floating windows on one private workspace, one monitor and equal scale. CPU came from process tick deltas over eight seconds. Each hidden observation lasted ten seconds. Start times guarded against PID reuse; geometry was checked before and after. Hosts were measured separately. No build, profiler or browser QA ran during these samples. Synthetic writers were separate processes.

The mixed test used one 20 Hz writer and three unchanged panes. The all-busy test used four 20 Hz writers; their updates can arrive at different times, so some frames still benefit from reuse. The stress test used four 100 Hz writers to reduce that opportunity. Hidden fixtures used thirty host-classified synthetic Codex panes plus one quiet visible tab; writer counters and parsed text checked that a lower number did not come from stopped output.

The plain hidden control uses the same writer under the filename worker.py. The original codex-fixture.py path triggers the existing substring-based agent classifier, which starts conversation lookup for a Python program. This reproduces the already-open agent-classification issue. The older host used for compatibility also predates the bounded-header read fix, so the synthetic-agent results include behavior absent from a newly started current host. Reading the numbers

A drop from 17% to 12% of one core saves five percentage points of one core. It does not make the whole computer 29% faster. Relative reductions are the median of the individual paired reductions. Memory is proportional set size: shared pages are divided among processes, so process startup and sharing affect it.

The CPU profile sampled only the main thread in user space, at 99 Hz. Summing the listed layout symbols gives 50.99%; symbols below one percent were omitted. That is why the figure says “at least.” The separate nineteen-sample live profile is retained as inconclusive evidence.

Validation and limits

Tests include positive controls: a forced refresh must actually redraw; a visible output event must resume delivery; every hidden write must reach the parser individually. Changed rows are tested without relying on a generation counter. The initial mutable-child approach failed before replacement-by-content passed. Fault controls intentionally disable caching and the hidden gate, then restore source bytes in a finally block and verify hashes.

The native test used the existing older host binary, with no wire-format changes. It verified hidden output, keyboard tab activation, shell input protection, terminal/workbench switching, opening and scrolling Markdown, GUI closure and reconnection with the same shell PIDs and start times. It is a targeted smoke test, not a complete manual tour of every visual effect.

One experiment wrapper exited with a syntax error after all ten reverse-order hidden observations completed: I edited its file to prepare the next fixture while the shell was still using it. Its exit trap cleaned the owned windows and hosts, which were checked absent. The measurements and assertions had already completed; they are retained. Later fixtures use the syntax-checked script without edits during execution.

The integrated release suites passed 2,465 default-core tests and 2,418 alternate-core tests, with nine ignored in each. Both core configurations passed strict Clippy and formatting. Existing ignored tests remain ignored; their count is disclosed in the receipts. The integrated binary also passed the native compatibility test against the older terminal host. GitHub independently passed both full test configurations and both Clippy checks before the final report update.

XERJ remained on hold throughout this work. Its service and tooling were not used.
