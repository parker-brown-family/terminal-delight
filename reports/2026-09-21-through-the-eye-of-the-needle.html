Why

How “already on main” was decided

Three different questions, three different tools, because each one lies on its own.

  • A commit — git log --cherry-pick --right-only origin/main...branch. Ancestry says a rebased or squashed commit is unmerged when its patch is on main; patch-id sees through that. Six remote branches with merged pull requests still showed “ahead” by ancestry and zero by patch-id, and one (fix/the-second-click) showed one real patch, which turned out to be #626 under a different sha.
  • An untracked file — git hash-object against git rev-parse origin/main:path. A file untracked in a worktree 89 commits behind main is very often tracked on main; 24 of the shared tree's 73 were, byte for byte.
  • A file that differs — the worktree's mtime against main's last commit of it. Four reports had been edited sixteen minutes after the earlier sweep committed them; two had been corrected on main after the worktree's copy. Newer won each time, and the two older copies were discarded with the tree — that is the one deletion in this pass with no ref behind it, and what it lost is a 21:12 draft of a file main corrected at 22:35.
  • An uncommitted code diff — its symbols grepped on main. hosted_by_default was there; RailAction and OVERLAYS_OVER_PANES were there in a six-entry form where the diff had four; m_theme_on was there, which is how the theme-toggle removal was identified as unlanded rather than superseded.

How to get anything back

  • A deleted remote branch — its pull request page still shows the head sha; git fetch origin <sha> and branch from it. Forty-nine were deleted, all with merged pull requests or zero unmerged patches.
  • An uncommitted diff — git fetch origin 'refs/attempts/*:refs/attempts/*', then git stash apply refs/attempts/2026-09-21-needle/<tree>. The three are stash-shaped commits, so stash apply reads them directly.
  • A removed worktree — nothing to recover: each was clean on a merged branch, or its untracked files were on main first (#640).
  • Deleted local branches — all merged; git reflog holds them for ninety days regardless.
