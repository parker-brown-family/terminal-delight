Measured

  • The four exits and their dates: git log -S on each deleted symbol (Peel::Face, card_waits, Stay on the bench), read back against the commits they name.
  • The two dispatch arms: read in Bench::act and the match in bench_act. That the Keys arm has never touched the face comes from a grep over the file rather than from remembering it.
  • Every write of the face in the whole crate: one automatic one, now deleted. The others are alt+k, the header chip, ctl's bench off, and the demo seeder.
  • The gate fails when the bug is replanted, and names bench_act.
  • cargo fmt --check, cargo clippy --locked -- -D warnings, cargo test --locked — the three gates this repo's CI runs — all green on the branch.

Not measured

  • Nobody has clicked it. This is not installed and I have not driven a running build. The claim is that the code path no longer moves the face, which is a source fact; how it feels is not.
  • The twelve-instance census is a grep over comments plus a read of each site. Repairs that left no comment behind are invisible to it, so twelve is a floor.
  • The overview scroll reset is read, not observed.

Invalidation — run this first

If rg 'set_face|toggle_face' app/src/pane/bench.rs returns nothing on a build where answering still turns the pane to TERM, this diagnosis is wrong and the flip is coming from somewhere I did not look. Close it and start at Pane::set_face's callers.
