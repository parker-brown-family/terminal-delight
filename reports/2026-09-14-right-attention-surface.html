Attention Spine

A collapsed strip on the right carries counts and state. Open it and the first screen is a human-handoff queue across panes. Selecting an item reveals provenance, review evidence, or risk without replacing the terminal grid.

Rail contract

Closed is the steady state

Show a narrow spine with count and severity. Never open itself over a live terminal. The user opens it.

Overlay first, pin by choice

Opening overlays the right edge so pane geometry stays stable. On wide displays, the user may pin it and reserve width.

Global queue, local detail

The queue can span workspaces. Once selected, provenance and review content belong to that one pane or task.

One action per row

The verb must match the state. Start with focus/open only. Write actions wait for an explicit orchestration contract.

Decisions

Should the first release contain more than the queue?

Every extra mode adds data contracts before the primary behavior has been tested.

Recommendation: no. Ship the collapsed spine, ordered queue, and focus action. Prototype review detail separately.

Should opening the rail shrink the pane grid?

Your two-pane screenshot shows why automatic reflow is expensive: both terminals are already using the width.

Recommendation: overlay by default; pinning is an explicit wide-screen preference.

Should the rail control agents?

TD's current promise is observation and navigation. Sending prompts, merging, or retrying crosses into orchestration.

Recommendation: first-slice verbs only move the human to the right place. Revisit writes as a separate product decision.
