What was actually wrong

Rust masks SIGPIPE at process start so that a write to a pipe with no reader arrives as an ordinary io::Error rather than killing the process. That is a good default for a program that wants to handle the error. println! is not such a program: it unwraps, and an unwrapped EPIPE is a panic. So a verb whose whole purpose is to be piped into jq, grep or head printed a Rust backtrace the moment anyone did.

Why a harmless bug was worth a morning

Nothing breaks. What it costs is that a panic stops meaning anything: one that turns up during ordinary use teaches a reader to scroll past the next one, and this binary prints real ones.

The measurement that changed the work

The issue prescribed the repro: skin --list | head -5. Taken at face value it would have produced a one-line fix and a one-case test, and the test would have been green on most of the bug.

The second finding was worse, because it produces a test that looks like it is working. A table-driven gate over "every headless verb" reads as thorough. It is not, because most of these verbs never write to the stream the gate is watching.

Where the restore is placed

This is the one judgement in the change with a real downside if it is wrong. Restoring the default disposition is right for a process that prints and exits. It is not obviously right for the window, which lives for days and writes to a compositor socket and to the pseudoterminal of every pane.

Why the roster moved

The gate needs a list of verbs, and this file already had four, kept in step by hand. They were not in step. Nobody had done anything wrong; a hand-copied list is simply a list that falls behind, and the cost lands on whichever test was supposed to be watching.

The new table carries one field the old lists could not: what happens to a verb when its reader walks away. It is an enum with no neutral value — either the arguments that make the verb stream, or a written sentence saying why the gate cannot run it. A blank sentence fails a test. Adding a verb therefore costs one sentence of thought at the moment the author still has the context to write it, and an exemption can never be silent.

The assertion that would have been backwards

How the gate was checked

The fix was deleted and the gate went red on all four paths

measured Removing the single call produced 4 of 4 printing paths mishandle a closed reader, each naming its own stream and carrying the panic text from the issue. The test reports every failing path rather than stopping at the first, because "one path regressed" and "all four did" want different repairs.

The deletion was confirmed in the diff before the run

measured A mutation that silently fails to apply reads exactly like a dead guard. The diff was checked for the edit before the suite was trusted to have proved anything.

Each case proves it writes before it is asked to survive a closed reader

measured Every case runs twice. The first run, with the pipe open, asserts the stream under test received bytes. Without it a verb that stops printing becomes a passing case forever, and that is not hypothetical here — nine of ten verbs are already in that state.

Two test failures on this machine are pre-existing and unrelated

measured paneident::tests reads the machine's process tree and is red on any box with agents running. Confirmed by checking out pristine main and running the same two: identical failures. They are already tracked as separate issues.

What this does not prove

Declared gap

inferred Nothing here demonstrates that the running window never receives SIG_DFL — only that the branch deciding it returns the right answer for every launch shape. Proving the process itself would mean opening a window in continuous integration. The risk if the branch were wrong is not a crash in a test; it is a window dying silently mid-session, which is why it is named here rather than left to be discovered.

Not measured

inferred The test drops the pipe's read end immediately after spawn returns, relying on the child still having an execve and process startup ahead of its first write. That margin is large and it held every run here, but it has not been exercised a hundred times on a loaded continuous-integration box. If this file ever flakes, this is the line to suspect first.

Yours to settle

Does the roster hoist belong in this pull request?

It is real scope beyond the bug: one table replacing four hand-copied lists, and two stale tests quietly widened. Recommendation: keep it here. The gate needs a verb list, and adding a fifth hand-maintained copy to fix a bug about a list nobody maintained would be the wrong lesson. Splitting it means two reviews of the same file.

Is a written reason enough for the nine ungated verbs?

Each carries a sentence saying why the gate cannot run it, and a blank sentence fails a test — but a sentence is not a test. bindings and probe could both be gated with a fixture. Recommendation: leave them. The fix is a process-wide signal disposition, so one gated path proves it for all of them; more cases would buy coverage of the argument parsing, not of this.

Should the unproven GUI placement become a follow-up issue?

Recommendation: no issue, keep the note. A follow-up wants proof it is real, and there is none — the branch is tested and correct. Filing a ticket for "we cannot test this in CI" adds a row to a list of two hundred that nobody can close. Say the word and I will file it anyway.
