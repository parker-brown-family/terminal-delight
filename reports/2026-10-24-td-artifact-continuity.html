Terminal Delight · 0.5.0 development · 24 October 2026

Artifact continuity

An agent hands you a document. You close its pane, the file changes, and later you return to the review. This work extends TD’s existing artifacts so you can find that handover, open the captured version, and recover the words behind your notes. The examination also exposed an indefinite wait when ending a terminal; its owner now performs bounded cleanup.

Original TD implementationDesign informed by HumanLayer

1 After the Pane

TD already had artifact cards, handover history and document notes. The gap appeared after the work moved on: the live rail depended on panes still being present, a pathname could point at rewritten bytes, and a Markdown note’s short anchor could point at different words.

HumanLayer offered useful comparisons: separate durable work from its running session, preserve review context, and make process completion observable. We kept TD’s conversation records and terminal ownership model, then implemented the missing behavior in Rust.

2 Evidence Beside the Record

A background worker captures an eligible local file and records its content hash beside the existing handover. Opening Archive rebuilds the list from those records, including conversations with no open pane. The searchable archive opens in your browser.

Repeat declarations capture changed revisions without duplicating shelf cards. Identical bytes share a saved copy. An unknown conversation gets an explicitly unbound record; only the same recorded event can later acquire a known origin.

3 The Words You Reviewed

Once a file can change independently of its handover, a note needs to say which document it described. New Markdown notes capture the passage, neighbouring text and document hash when created. Saving later never substitutes newer evidence.

Small wording changes need substantial shared wording and a matching neighbour. Ties and missing passages appear among notes without a clear passage. Old notes retain their anchors with evidence marked unavailable. Concurrent saves retain one another’s edits.

4 Ending the Terminal

The document survives its pane because it has a durable owner. Processes need an owner too. Previously, a terminal that ignored hangup could leave cleanup waiting indefinitely. The process holding the PTY now controls the close sequence and reports what happened.

The owner retains its child through the last group signal so a recycled PID cannot become a target. Jobs in the same Unix session use pidfds, kernel handles to particular processes. Inspecting the terminal no longer keeps its master open after its owner closes it.

5 Running It

That ownership boundary determines how the update reaches your current session. Replacing the window activates artifact and review changes while the existing host keeps your agents running. Hosted cleanup changes take effect when the host starts from the new build.

The current TD window is running these changes. The guarded swap preserved all 36 live terminal identities, the existing host, 32 exposed panes, and the saved layout and split document. Artifact capture and review evidence are active. Hosted cleanup takes effect after the existing host restarts.

The final daily integration passed 2,840 tests and strict linting. The feature’s two terminal-core suites and five restricted-command OS tests passed; the exact production executable captured two file revisions and recovered a moved note with its original quotation and hash.

Captures preserve the bytes the background worker reads, with capture time recorded separately from handover time. They cover regular local files up to 16 MiB. Remote links and linked assets are not copied. Saved revisions have no automatic expiry. Markdown stores advance to format 2 on save; older builds refuse to overwrite that format.
