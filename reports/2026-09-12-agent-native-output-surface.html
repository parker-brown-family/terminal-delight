Presented Output

Terminal Delight · research brief · 2026-09-12 · difficulty 8/10

measured on 90 sessions research only — nothing built

Prose a person reads is one to three percent of a transcript; tool results alone are half of it. Every one of ninety sampled sessions produced something worth keeping, and the median one sank under 233,000 characters of churn before it ended. Nothing here records less — the job is to give that one percent somewhere to be read other than the bottom of the ninety-nine.

Terminal Delight reads every agent's own JSONL transcript today — mcp_tail.rs pulls structured tool calls out of it, and toolprop.rs turns that stream into the face on the pane's tab. doc.rs went further and wrote down the next step in its own module docs: "an agent's own transcript is the natural second implementation, and needs none of the recovery below." That sentence has been sitting in the tree since 31 August. This brief is the case for cashing it, plus the two things it does not cover: what the blocks are called, and where they go.

The shape of the answer

Derive everything the transcript can already tell you, for free and retroactively. Add one verb for the intent it cannot carry — the difference between a paragraph and a decision. Render both into a right-hand artifact rail that mirrors the left bar, with the raw scroll kept underneath as the drill-down and every block carrying a back-reference to the turn that made it. Nothing in the terminal gets replaced; a layer gets added above it.

A ratio, not a volume

The first version of this argument was that transcripts are noisy, which invites the answer "record less" — and recording less is wrong, because the churn is what makes a finding checkable. One percent prose against half a transcript of tool results is a different complaint with a different fix. A rail changes nothing about what gets written down. It gives the one percent a place to be read that is not the bottom of the ninety-nine, and leaves the ninety-nine one click underneath every row.

Four architectures

Each of these has been built by somebody. The question is which one fits a gpui terminal with a CRT post-pass, an MIT licence and a client-server split.

A

Read the grid harder

Extend the painted-row heuristics. Detect headings, tables, fences and Links tables the way link_at() and is_copyable_command() already detect URLs and commands, then draw them properly.

Genuinely better at: working with agents we will never control — a codex pane, an ssh session, somebody's TUI. No protocol, no cooperation, days not months.

Cost: it reads a rendering to recover the source, which is the exact failure doc.rs was written to end. It can tell a table from a paragraph. It can never tell a decision from a description, because that distinction was never in the pixels.

recommended

B · Derive, then declare

Promote mcp_tail from a tool-event tap to a second DocumentSource yielding typed blocks. Then add one verb — present — for the intent a transcript cannot carry.

Genuinely better at: starting from something. The derived half costs no agent cooperation and runs backwards over the 865 sessions and 1.1 GB already on this disk, so the rail has content on day one, for work that finished last month.

Cost: two mechanisms, and the seam between them has to be drawn and held or it rots. The declared half only pays if agents actually call the verb — which is an assumption to test in week one, not a thing to find out after the catalog is frozen.

C

Rewrite the scroll as blocks

Warp's model: an ordered list of typed blocks, terminal blocks and rich views side by side, boundaries taken from shell integration escape sequences.

Genuinely better at: making the scroll itself the modern surface, which is the literal thing the mockup asks for. Warp has shipped it to a lot of people, so it is demonstrated rather than theoretical.

Cost: it re-architects alacritty's grid, which is what makes this a real terminal. Every full-screen TUI — vim, tmux, the agents themselves — lives outside the block model. And gridwire.rs runs in both halves of the split, so the encoder change lands on the host, which only upgrades by dying.

D

Embed a webview

Ship HTML views the way MCP Apps does: ui:// resources rendered in a sandboxed frame talking back over postMessage.

Genuinely better at: reach. It is a live spec with production support in Claude, ChatGPT, VS Code and Copilot as of January 2026, so agents already know how to target it and the whole web component ecosystem comes along.

Cost: gpui has no webview. Adding one means a second renderer with its own font stack, theme and input model, and the CRT pass cannot reach inside it — TD becomes the one window on the desktop that does not match itself.

Read these five closely

  1. 1

    The noise ratio is measured, and it is worse than it feels

    What: tool results alone are 51–59% of transcript content. Tool inputs, images and persisted thinking take machine payload to 83–92%. Prose a person reads is 1–3%.

    Why it matters: the case for this feature does not rest on taste. Fourteen tool calls land between one human turn and the next, and a person opening a pane is looking for the one percent.

    What it would take: nothing — the scripts run in five seconds. An earlier draft said 86% churn and 7.6% prose; that count measured extracted strings against serialised ones and had no bucket for images, and a second count from a different angle caught it. Two sessions and five samples now agree. Re-run before Gate 2 anyway.

  2. 2

    doc.rs already specified half of this

    What: the document model separates what the text is from how a surface lays it out, quarantines all guessing in one function, and names an agent transcript as the natural second DocumentSource.

    Why it matters: the expensive architectural argument was had in August and won. A transcript source needs none of the grid recovery, and every VisualRow already carries the document position behind it — which is the drill-back this feature needs.

    What it would take: one impl of an existing trait, plus a block layer above DocLine. The reader renders it for free.

  3. 3

    The catalog is doctrine, not invention

    What: six of the ten proposed block kinds are already mandatory prose formats in ~/.config/agents/AGENTS.md — the falsifiable issue, the Links table, the difficulty score, the gate document, the three-paragraph commit, the sticky note.

    Why it matters: a component catalog is the part that gets frozen. Freezing one that agents are already forced to produce in prose costs no new training and no new argument about what a block should be.

    What it would take: writing the schemas.

  4. 4

    Zed's renderer is on the disk and cannot be used

    What: the pinned checkout carries crates/markdown with mermaid and HTML support, crates/ui, and the whole ACP implementation. All GPL-3.0-or-later. Only gpui is Apache-2.0, which is why TD can be MIT.

    Why it matters: the fastest-looking route on the board is closed, and finding that out after writing the Cargo edit is a bad afternoon.

    What it would take: pulldown-cmark (MIT, already the parser Zed's crate wraps) and TD's own gpui elements. More work, no licence change.

  5. 5

    Test whether the verb gets called before freezing the catalog

    What: the declared half assumes agents will call present. There is evidence both ways on this machine already: leave_note — a tool with a schema, no hook — was called 195 times across the sample, while the Links-table rule needs a hook re-injected every single turn.

    Why it matters: if the verb does not get called, path B collapses to its derived half and the catalog was wasted effort.

    What it would take: ship one kind behind one verb, wait two weeks, count. The invalidation criterion is written into the slice plan.

What the research found

measured

The first count of the noise ratio was wrong, and it failed in a way worth naming

This brief originally said 86% churn and 7.6% prose. A peer session declined to repeat a number that carries an argument without a second count, so it got one — a different parser, a different unit, a different sample — and they disagreed. Two sessions and five samples later the corrected figures hold: tool results 51–59%, images 17–27%, thinking 7–14%, tool inputs 6–10%, assistant prose 1–3%.

The two defects were one defect. Summing text.length against JSON.stringify(input).length made the categories incommensurable, and having no bucket for image made an unmeasured category read as zero. Both are "unknown is not zero" landing somewhere nobody applies it, because a percentage always looks complete — the numbers sum to 100 whether or not anything is missing, and the total is the thing a reader checks. Any denominator built by adding up categories has this failure mode available to it.

The original is kept rather than patched out because it is the specimen. A correction that erases its own evidence teaches nothing; this one teaches where to look next time.

measured

The rail will never be empty, because every session already fills one

All 90 sampled sessions produced at least one deliverable block, 13.5 on average. The median session wrote 26 distinct files and 11 doc-shaped ones; .md leads at 1,612 writes, .html is fourth at 710. Agents on this machine are already producing exactly the artifact inventory the mockup's right-hand panel shows. Nothing collects them.

measured

A tool with a schema gets used; a rule in prose gets remembered

mcp__terminal-delight__leave_note was called 195 times across the sample with no hook forcing it. The Links-table rule has a UserPromptSubmit hook re-injecting it every turn and lands on 700 of 1,302 human turns. That 54% is a floor, not a failure rate — plenty of turns should not carry a table — but the asymmetry is the design input: the format wants to be a tool call, not a style guide, because a schema validates and a memory does not.

measured

The structured channel is already load-bearing in the UI

toolprop.rs reads the transcript and repaints the pane's logo as the tool the agent is holding, against a vocabulary derived from 9,320 real tool calls across 84 transcripts. The wire from transcript to pixel exists, is tested, and ships. This proposal widens it; it does not lay it.

measured

A full transcript parse is cheap enough to do on every change

vitals.rs deliberately parses whole files rather than tails: the biggest transcript here (33 MB) takes ~250 ms and the seventeen-agent fleet 560 ms, on a background thread. The two scripts written for this brief did 652 MB in 3.1 s. Block extraction has no performance argument against it.

inferred

The unit is the artifact, and the terminal becomes its provenance

The mockup shows sessions in the middle and artifacts on the right, and the artifacts are what a person clicks. A session is a container with a lifetime; an artifact is a thing with a name that someone acts on, and it has to outlive the pane that made it. That is also why the transport should be a file rather than a byte in the PTY.

measured

Inline-in-the-scroll pays a tax the other surfaces do not

The CRT barrel distortion is a pixel post-pass, so anything drawn over a pane must be pre-warped through the same map — sticky.rs documents the recipe and says plainly that the earlier cut-a-hole approach cost a visible seam. Add reflow on resize, and an encoder change landing on a host that only upgrades by dying, and inline blocks are the last surface to build, not the first.

measured

The rail arrives after the skin layer, which changes how it gets built

Shape became a themeable axis on main this morning — app/src/skin.rs, three skins in app/skins/, and an element vocabulary of panel(), bar(), row(), chip(), rule_h() and ring(). Six always-visible surfaces were converted; the overlays and the theme tray were not, which is the open seam. A rail is a panel of rows and chips, so it is the vocabulary's natural next tenant — and building it means never writing a literal corner into it, rather than converting it later. Corners and rules do not take the UI scale; lengths do, and there is a test holding that.

inferred

Every block needs a source range, or the noise stops being drillable

VisualRow already carries doc_line and doc_col0 so selection survives relayout. The same discipline generalises: a rendered block points at the transcript range, grid range or file that produced it, and clicking it lands there. Without that the presented layer is a summary, and a summary that cannot be checked is the thing this codebase keeps refusing to ship.

inferred

A block TD cannot classify renders as unclassified

Assistant prose with no structure is 84% of blocks. Most of it is honest commentary — "let me check X" — and typing it as a document would be the same mistake slot.rs refuses when a subscription with no collector draws a bar of length zero. The Reading enum there is the precedent: absence is a variant, decided before the colour ramp is consulted, with a test per state.

Why fixed rather than free-form

Google's A2UI ships both: a dynamic schema where the agent invents the layout, and a fixed schema where the component tree is authored ahead of time and the agent only streams data into it. The fixed one is described as the faster and more reliable of the two, because no model has to generate a valid schema at runtime. A terminal with one visual language and a CRT pass has more reason to prefer fixed than a web host does — an agent that can invent layout will eventually invent one that does not belong in this window.

A file, watched. It survives the pane that wrote it, which an artifact has to; it works from any agent that can write a file, which is all of them; it crosses the client-server split without touching gridwire; and there is no version negotiation on a hot path. The MCP tool td_present and a terminal-delight present CLI are both front doors that write that same file — one format, three writers, and a skill that makes the verb the path of least resistance.

An escape sequence was the tempting alternative and it is the wrong pipe for this payload: the thing being carried is durable and the PTY is not, TUI agents repaint and would re-emit, and the encoder lives in both halves of the split. OSC 133 is still worth taking, for the other job — prompt and output boundaries in plain shell panes, which is cheap, standard, and gives block edges to all the output that has no agent behind it to annotate anything.

The tracer bullet

One artifact, one verb, one rail row, one drill-back. Everything after it is more kinds.

  1. Slice 0 · the count that could kill it. Extend the two scripts to answer: how many presented artifacts would a session actually have, and would any of them be worth a row? Invalidate: if the median session yields fewer than three rail rows, build only the reader upgrade and drop the rail.
  2. Slice 1 · one kind, end to end. links only. The verb writes the file, the watcher reads it, the rail draws one row, clicking it opens the target, and a back-reference lands on the transcript turn that produced it.
  3. Slice 2 · the derived half. mcp_tail becomes a DocumentSource yielding diff, run and unclassified from the transcript, with no agent cooperation and running backwards over history.
  4. Slice 3 · the reader renders blocks. pulldown-cmark plus TD's own elements, above DocLine, no GPL crates.
  5. Slice 4 · the remaining kinds, and the skill. Invalidate: if agents call the verb in fewer than one session in four after two weeks with the skill installed, the declared half is not earning its catalog — keep the derived half and stop.

What is yours to decide

Four, all with prerequisites already settled. Nothing below is waiting on anything above it.

1 · Is the unit an artifact or a session?

The mockup shows both — sessions listed in the middle, artifacts on the right. They imply different data models and different lifetimes, and picking both means building an index of sessions that nobody asked for.

Recommendation: the artifact. A session is a container with a start and an end; an artifact is a thing with a name that someone acts on, and it has to outlive the pane that made it. Sessions are already visible as tabs and tree rows. Adding a second list of them competes with the left bar for the same glance, which is the problem the left bar was built to end.

2 · Does the rail live in the window, or in a second app?

The panes are already client-server and outlive their window. An artifact store is the same kind of thing, and a separate reader app could serve a phone.

Recommendation: in the window, as a right dock. The left bar proved the vertical axis works and its rules are already pure functions with unit tests. A second app is a second install, a second theme and a second thing to keep alive — and the moment the rail is not beside the pane, the drill-back stops being one click. Keep the store on disk so a second reader stays possible later without redoing this.

3 · Does present replace the Links-table rule, or feed it?

The rule costs a hook every turn and lands on roughly half of them. A verb with a schema would be more reliable, and it would also be one more thing for an agent to remember.

Recommendation: feed it, and keep both. The Links table is how the output reads in a terminal that is not this one, over ssh, in a log, in a paste. Make the rail the render of kind: links and let the table stay the fallback — the same degradation every other block kind needs anyway. Dropping the prose form would make TD the only place the work is legible, which is a worse failure than a missing table.

4 · How much of the 84% do we try to type?

Bare unstructured prose is 4,948 of 5,867 assistant blocks. Some of it is real content that simply was not formatted; most is running commentary. A classifier could guess.

Recommendation: none of it, in the first cut. Render it as unclassified — visible, plain, and clearly not claiming to be anything. A wrong guess here is the "unearned zero" failure in a new costume: a confident label, cheap to produce, identical in appearance to a real one. Revisit only once the typed half exists and there is something to compare a guess against.

Deliberately not proposed

  • A webview. A second renderer in a window whose whole identity is one visual pass.
  • A markdown dialect of our own. pulldown-cmark, MIT, the parser Zed's GPL crate wraps.
  • A block-model rewrite of the scroll. The grid is alacritty's and every TUI depends on it.
  • An escape-sequence payload. Kept for OSC 133 boundaries only, where it is standard and cheap.
  • A classifier over unstructured prose. See the fourth question above.
  • Anything in the fork this session started in. That tree is 100+ commits behind and points at td-glyph; the live main is the cutover worktree, which is where this brief was researched.

Method

Two scripts, 90 sessions, 652 MB

The correction, first

The first count reported 86% churn and 7.6% prose. It was wrong in two ways. It summed extracted string fields — b.text.length, JSON.stringify(b.input).length — rather than the serialised size of each content block, which mixed units between categories. And it did not count image blocks at all, which turn out to be 17–26% of everything. Both defects shrank the denominator and inflated prose roughly fivefold.

It was caught by a deliberately dissimilar second count: jq instead of node, serialised block length instead of extracted characters, and the twenty most recently modified files instead of the largest. That pass put tool_use at 10% where the first said 45%, and surfaced two categories the first had no bucket for. The disagreement was the finding.

The sample, after the correction

865 JSONL transcripts totalling 1.1 GB live under ~/.claude/projects. The split is measured over five samples chosen by opposite rules, by two sessions running different scripts: 90 largest (811 MB) and 90 newest (313 MB) here, sharing 34 files; 40 largest and 40 newest independently, sharing 5; plus the 20-file jq pass that found the defect. Burial depth uses the 90 largest, because a session has to be long enough to bury something.

What is counted

Every object inside message.content, by the byte length of its serialised JSON, bucketed by its type: text, thinking, tool_use, tool_result, image, with human text split out and system-reminder and slash-command wrappers excluded from it.

Confounds, named

  • These are shares of message content, not of the file. The JSONL also carries attachments, file-history snapshots and per-turn metadata. On disk the machine share is higher.
  • Thinking is sample-dependent — 8.7% in the largest files, 13.1% in the newest, and 0.1% by the first pass's method. Recent sessions persist it and older ones do not, so it measures a storage policy as much as it measures reasoning.
  • Two burial numbers, two meanings. 1.33 MB is the serialised record written after the median deliverable. ~233K characters is the subset that is rendered text and therefore actually scrolls past a person — images and base64 payloads occupy the file but no screen rows. The screenful conversion in the body uses the smaller one and assumes full rows, which real terminal output is not.
  • "Deliverable" is a shape test, not a judgement. A block counts if it has a heading, a markdown table, a Links table, or runs past 1,200 characters. It will catch a long apology and miss a good two-line answer. The direction of the bias is unknown.
  • Both samples are size- or recency-selected, so neither is a random draw from the corpus. Their agreement rules out a unit bug; it does not make either one representative of a typical session.
  • One machine, one operator, one agent product. Nothing here says anything about how other people's transcripts look.

Reproduce

Three scripts in this session's scratchpad — the node split, the jq cross-check, and burial — each running in three to five seconds. They read only, and print JSON. Run at least two of them before quoting any of these figures again.

The catalog

Ten kinds, plus the honest default

Shape

Every block is one JSON object with a fixed envelope and a kind-specific body. The envelope is where the drill-back lives, and it is the part that must never be optional.

{
  "v": 1,
  "id": "01JG7X…",            // sortable, generated by the writer
  "kind": "decision",
  "title": "The reader renders from the source",
  "session": "602112e3-…",     // which conversation
  "task": "chrome/skin-tokens",// which tab, when known
  "created": "2026-09-12T18:04:11Z",
  "source": {                  // the drill-back. never omitted.
    "transcript": "/home/parker/.claude/projects/…/602112e3.jsonl",
    "range": [14820, 14833],   // record indices
    "files": ["app/src/doc.rs"]
  },
  "confidence": "measured",    // measured | inferred | hunch | unknown
  "body": { … }                // kind-specific, below
}

Bodies

decision — { question, options: [{name, case, cost}], chose, because }. Exactly one option is marked chosen; two is a schema error, which is the rule the brief format already enforces by hand.

finding — { problem, proof, reproduce, verify, invalidate, done_when }. The falsifiable-issue template, field for field, so a block can become a GitHub issue without a human rewriting it.

plan — { difficulty, gates: [{name, state, doc}], slices: [{name, state}] }. state is an enum with an unknown variant, because a gate nobody has looked at is not a gate that failed.

report — { path, sections: [{heading, anchor}], budget_minutes }. The rail shows the heading list; the reader opens the file.

links — { rows: [{target, what, primary}] }. One row may be primary, which is the rule the Links table states in prose and cannot check.

run — { command, cwd, elided: false }. elided is not a hint; a true value means the chip is never offered, matching is_copyable_command's refusal to chip a line containing an ellipsis.

diff — { file, hunks, applied }. applied is a three-state, because a proposed edit and a rejected one are not the same thing and neither is an unread one.

status — { headline, detail, needs_you }. Ten words, per the sticky-note skill, and it drives the tab badge TD already draws.

question — { question, options: [{label, what_happens}], recommend, answer }. answer is null until someone answers, and null is not "no".

table — { columns, rows, sort }.

unclassified — { text }. Not an error state. It is what most output honestly is, and it renders as plain text with a visible marker saying nothing was claimed about it.

Two rules that are not negotiable

Absence is a variant, everywhere. Not a zero, not an empty string, not a false. This is the slot.rs Reading pattern applied to a wire format, and the reason is the same: a default that fills in for a missing measurement produces a confident wrong number that looks exactly like a real one.

Degradation is part of the schema, not an afterthought. Every kind defines its plain-text rendering, which is what a non-TD terminal, an ssh session and a paste into an issue get. The Links table is the worked example: it already exists as the plain-text form of kind: links.

Transport

Four routes from an agent to the rail

A file the window watches — chosen

$XDG_STATE_HOME/terminal-delight/artifacts/<session>/<seq>-<kind>.json, one block per file, watched with inotify. Durable past the pane, writable by any agent or script, invisible to gridwire, and there is nothing to version-negotiate on a hot path. It is also the only route where an artifact from last Tuesday is still there on Thursday, which is the whole point of calling it an artifact.

Costs: no positional anchor into the scroll, so inline rendering would need the source range to do the work instead. A naming convention to hold. And a directory that will need sweeping.

An MCP tool

TD already runs an MCP server with a write path behind two separate opt-ins, and leave_note proves agents reach for it — 195 calls in the sample. This is the right front door, and it should write the file above rather than being a second channel with its own state. An agent not connected to TD's MCP server still gets the CLI.

An escape sequence — declined for the payload

It travels the PTY, survives ssh, and knows where in the scroll it belongs, which is genuinely better than a file for anything inline. Against it: the payload is durable and the PTY is not; a TUI agent repaints and re-emits; big payloads in OSC are unpleasant and need chunking; and gridwire.rs runs in both halves of the split, so carrying it means an encoder change landing on a host that only upgrades by dying.

Taken anyway, for a different job: OSC 133 prompt and output marks in plain shell panes. Standard since FinalTerm, implemented by wezterm, contour, VS Code and tmux, and it gives block boundaries to output that has no agent behind it to annotate anything.

Wrapping the agent's stdout

Claude Code's --output-format stream-json emits newline-delimited events covering session start, tool calls, results, partial messages and permission requests — everything the catalog wants, already typed. Declined because it changes how the agent is launched and takes away the interactive TUI, which is the thing being used. The same data is available after the fact in the transcript, which is what path B reads.

Surfaces

What each one costs in this codebase

1 · The artifact rail

Mirror of the left bar on the right edge, scoped to the focused task. The pattern to copy is tree.rs and slot.rs: the row list, the roll-up and the scope rules are pure functions over plain ids with no gpui, so every rule is a unit test rather than a screenshot. LEFT_BAR_W is 208 with a 132–420 drag range; the rail should match rather than invent.

Every element goes through skin.rs: panel() for the dock, row() per artifact, chip() for the kind marker, rule_h() for the separators. No literal rounded_sm(), no px(9. * s), and no branching on which skin is active — if a call site needs to know, a strategy is missing a value and the fix belongs in skin.rs. Widening the always-visible-chrome guard test to cover the rail keeps it that way.

The selected row is a solved problem, and the solution has a trap in it. The ink token is select and the strategy is Emphasis — fill, underline, bracket, rail or glow, chosen per skin. If the rail's own emphasis needs to read differently from a selected left-bar row, that is a token question, not a call-site one. The test no_state_ink_collapses_onto_the_accent_in_any_builtin_pairing refuses any colour that collides with the accent or with live — deco.toml carries the comment about the pairing where "running" and "selected" would both have come out mint. That collision was shipped and caught within the hour; the test is there so it is not shipped twice.

Do not copy a metric out of one skin's TOML. Console's leading rail is 3.0 and deco's is 2.0, and the difference is not taste. Console sets boundary = "none" — no panel edges anywhere, regions separated by space — and its own comment says why the number had to grow: "at 2px against no other lines it reads as a scratch rather than as a marker." Deco can afford 2 because deco is full of lines for it to be read against. A metric is only meaningful against the ink density it sits in. The same argument governs the phosphor ring's bloom and every other tuned constant in those files.

That matters here specifically, because an artifact rail is a low-density surface — a column of short rows with almost nothing else on it, much closer to console than to deco. It should expect to want the larger values, and a 2 carried over from the wrong skin will look like a rendering bug rather than a wrong constant, which is the expensive kind to chase.

Watch out for: the mother bar is already a one-row layout where a stray flex gap moved the tabs 16 px off the terminals. A second dock changes the horizontal budget for every pane, and the left bar's own history says the tree yields to the slot in a short window, not the other way round.

2 · The reader, promoted

The FOCUS modal already renders a Document through a pure width-driven layout() that reports the document position behind every visual row. Adding a transcript DocumentSource needs none of from_grid_rows's recovery, which the module docs say explicitly. The block layer sits above DocLine, so selection and copy keep working.

Watch out for: the reader currently mirrors a pane and routes keys back to it. A document with no pane behind it has no obvious Esc target, and Esc is the key sticky.rs already warns about swallowing.

3 · A document leaf

A leaf in the tiling grid holding a report rather than a PTY. This is the surface that makes the window stop reading as a terminal, because the split you make can be the thing you are reading. It needs the leaf model, the state file, the client-server pane claim and the tab strip to all stop assuming a PTY behind every leaf.

Watch out for: a pane id that claims no terminal, in a system where a duplicate pane_id claim already produced a blank tab shadowing a live terminal.

4 · Inline in the scroll — deferred

Three costs, each independently sufficient to defer it. The CRT barrel distortion is a pixel post-pass, so an inline element must be drawn pre-warped through the same map — sticky.rs made that work and records that the earlier punch-a-hole approach cost a visible seam. Reflow on resize has to move blocks the grid knows nothing about. And the encoder that would carry block positions to the client lives in gridwire.rs, which runs in both halves, so it lands on the host.

Prior art

Five systems, and what each one settles

A2UI — the closest match

Google's agent-to-UI specification, Apache-2.0, with CopilotKit as launch partner. An agent emits JSON Lines referencing components from a catalog the host advertises, and the host renders them with its own native widgets — the same payload becomes React on web, Flutter on mobile, SwiftUI on iOS, each client mapping abstract types through its own registry. The UI paints progressively as lines arrive rather than appearing at the end.

The registry model is exactly what a gpui host needs, and the fixed-versus-dynamic finding is the part worth stealing: CopilotKit ships both and describes the fixed schema, where the component tree is authored ahead of time and the agent streams only data into it, as the faster and more reliable of the two.

MCP Apps — the spec that already reaches the agents

SEP-1865, landed January 2026, with production support in Claude web and desktop, ChatGPT, VS Code with Copilot, Microsoft 365 Copilot, Goose and Postman. Servers declare UI resources under a ui:// scheme, associate them with tools through metadata, and the host renders them in a sandboxed iframe communicating over postMessage.

The iframe is unavailable to a gpui window, but the tool-to-view association through metadata is the right shape for saying "this verb produces that kind of block", and it is the shape agents will increasingly expect.

AG-UI — the event stream

An event-based protocol where every agent-to-frontend communication is a typed JSON event, about sixteen types, with bidirectional state synchronisation and the ability to pause mid-execution for approval before proceeding. That last property is why question belongs in the catalog as a first-class kind rather than as prose an agent hopes someone reads.

ACP — the tool taxonomy, from the same house as gpui

Zed's agent-client protocol, stdio JSON-RPC, published August 2025. Content blocks are markdown-first with images, audio and resource references; tool calls arrive as tool_call and tool_call_update notifications carrying status, content and locations so the editor can follow along; tools are categorised read, edit, delete, move, search, execute, think and fetch.

Two things transfer. The eight-way tool categorisation is a smaller, better-tested vocabulary than inventing one. And the locations field is the same idea as this brief's source range, arrived at independently by people who had already built the UI.

The implementation is in crates/acp_thread in the pinned checkout and is GPL-3.0-or-later, so it is a reference to read rather than a dependency to add.

Warp — the one that rewrote the scroll

A BlockList of typed blocks: terminal blocks wrapping a command with its output, and rich content blocks hosting an arbitrary UI view, in one ordered list. Boundaries come from shell integration scripts emitting escape sequences, and each block carries the command string, stdout and stderr, exit code, working directory and timestamp.

Worth knowing: Warp also carries agent notifications over OSC 777, which travels the wire like any other terminal byte, so an agent running over ssh still fires them. If inline blocks are ever built here, that is the precedent for the transport — but it does not change the case for a file today.

Slices

If this becomes work

Gate mapping

Scored 8/10 at the top of this brief, which buys all four gates. This document is Gate 1 with enough of Gate 2 to make the seams visible. Gate 2 proper is the catalog frozen and the transport signed off; Gate 3 is the module boundaries — where the block type lives relative to doc.rs, and whether the rail is a peer of tree.rs or a tenant of it.

Slice 0 — the count that could kill it

Before any code: extend the two measurement scripts to simulate the rail. For each session, count how many rows it would have had under the derived rules alone, and eyeball twenty of them.

Invalidate: a median under three rows per session means the rail is decoration. Build the reader upgrade and drop the dock. Confirm: a median at or above three, with at least half the rows naming something a person would click.

Slice 1 — one kind, end to end

links and nothing else. The CLI writes the file, inotify picks it up, the rail draws one row, clicking opens the target, and the row's source range lands on the transcript turn behind it. Every later kind is the same path with a different body.

Done when: a rail row opens a file that an agent named ten minutes earlier in a pane that has since scrolled 200,000 characters.

Slice 2 — the derived half

mcp_tail gains a DocumentSource impl yielding diff, run and unclassified. No agent cooperation, and it runs backwards over 865 sessions already on disk, which is the slice that makes the rail non-empty for work nobody presented.

Slice 3 — the reader renders blocks

pulldown-cmark above DocLine, drawn with TD's own gpui elements. No GPL crates, no second renderer. Headings, tables, fences, and the block chrome around them.

Slice 4 — the rest of the catalog, and the skill

The remaining kinds, the MCP verb, and a skill that makes calling it the path of least resistance rather than a rule to remember.

Invalidate: fewer than one session in four calls the verb after two weeks with the skill installed. Keep the derived half, delete the declared one, and write down why — that result would say something worth knowing about every prose rule on this machine.

What this does not touch

The grid, the PTY, gridwire's encoder, the host process, the theme system, the skin axis, and every existing pane. If a slice starts touching any of those, it has grown past this brief.
