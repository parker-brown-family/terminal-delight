Floating Square

This morning you approved ten slices for opening documents inside Terminal Delight’s panes, and by this evening seven of them are merged and installed on your launcher. It started with the first one. Alt+click the path of a picture in any pane and the picture opens in a square beside the line that printed it; Escape puts it away. Before anything else was stacked on top of it, one question needed a number rather than a belief. A square you open and close all day holds a decoded picture and a texture on the graphics card, so does closing it give that memory back?

What you can do today

The square opens just below the line you clicked, or above it when the line sits near the bottom of the pane. It wears the glow every menu and modal in Terminal Delight wears, and it bends with the glass, because it is drawn inside the screen rather than laid over it. Typing still reaches the shell beside it; Escape is the only key the square takes.

Where a picture’s memory goes

gpui, the toolkit Terminal Delight draws with, decodes a picture once and keeps it. The pixels stay in its cache for as long as the program runs, and the texture stays on the graphics card until something asks for it back. For an icon that is the right trade. For a 4K screenshot it is 33 MB twice over, and a day of opening screenshots would carry every one of them until the window closed. The program design listed this among the decisions it was least sure of, at up to 61 MiB per closed brief if it went wrong.

So the square owns its picture. It asks gpui to decode the file, takes the result straight back out of gpui’s cache so nothing else holds it, and registers a hook that runs when the square is dropped and hands the texture back to the graphics card. Escape drops the square, and so does closing the pane, closing the tab, or the window rebuilding a pane after it loses its connection to the session. Each of those runs the same hook, so none of them has to remember to.

A hundred squares

No test in the suite can see a texture, so the proof runs a live window. A script starts Terminal Delight on a hidden workspace, where nothing appears on your screen and focus never moves, and drives it through the control socket: open a 4096-pixel square picture, wait for the window to report that it drew it, close it, wait for the release, and read the window’s graphics memory from nvidia-smi. Then again, a hundred times.

The failing build matters as much as the passing one. A script that could not see a leak would draw a flat line whatever the code did, so the same run was pointed at a build with the release removed, and it failed the way it should. The window’s ordinary memory rose 15 MiB across the hundred cycles, under a quarter of one decoded picture. That is recorded as measured, not as zero.

Each later slice ran the same test on what it added. A Markdown file holding a 4096-pixel picture grew 2 MiB over a hundred cycles. The tallest brief in the archive, drawn by Chromium as fifteen tiles, was opened, scrolled top to bottom and back, and closed a hundred times, and grew 2 MiB against an 8 MiB tile, with never more than four tiles on the card at once.

Where the ten slices stand

Slices that touched different files were built side by side, each landing as its own pull request once its checks passed, and the build went onto your launcher three times: after the square’s controls, after the split, and after HTML. The notes are what is left, and they are the careful part, because they write into your briefs.

To try it, press Ctrl+Alt+T for a fresh window, which starts from the launcher, and run scripts/doc-demo.sh in it: it prints the gestures and a handful of pictures, Markdown files and briefs to click. Your main window keeps its old build until you restart it.

The size answers are on main too. A program that asks a pane how big it is in pixels now hears the size the pane is now, where it used to hear the size the pane was when it started, and that closes the stale-size issue you had open. The agent that built it found one more gap on the way: colour queries go unanswered in every pane. That is filed as its own issue rather than fixed on the side.
