The workbench composer

terminal-delight · 2026-09-21 · branch fix/the-second-click-backs-out-to-your-branch · app/src/pane/bench.rs, app/src/workbench.rs, app/src/benchdraw.rs

The verdict

The box you type into on the bench is not a text editor. It is a pipe to the agent's own line editor with a drawing of a line beside it, and that drawing knows three things: a string, one caret, and one bit that says the whole thing is selected. Every complaint you raised is the same fact arriving from a different direction.

Up-arrow does nothing locally because there is no second row in the model to move to. Nothing grows past a third of the pane because that ceiling is a constant. There is no mouse-drag highlight because a highlight needs two numbers and the model holds one boolean. Ctrl+C interrupts the agent because the bench hands the keystroke to the pseudoterminal before the window's copy handler ever runs.

So the decision in front of you is not a list of fixes. It is where the boundary sits between our editor and the agent's — and the answer decides whether the other twelve gestures are cheap or impossible. There are three honest placements and I recommend one of them.

the one sentence

The mirror can only stay in step with the agent for edits it can express in arrows, backspaces and literal characters. Every gesture outside that set — up-arrow, shift+enter, a click into a selection — silently puts two different strings on the two sides, and nothing in the product tells you it happened.

Read first

  1. 1 Up-arrow moves the agent's caret and not ours

    measured line_edit returns None for up, down, pageup and pagedown in all twelve modifier forms, so the mirror never moves. cursor_key_bytes still sends ESC [ A down the pseudoterminal, so the agent's caret does move — or its history recall fires and its whole line changes.

    Cost to fix: small. The mechanism already exists — bench_click turns a pixel into a column with TextLayout::index_for_position and walks the far end there with caret_move. Up-arrow is the same operation with a different target.

  2. 2 Shift+Enter empties the box and the agent keeps the draft

    measured line_edit has no shift parameter, so shift+enter resolves to Edit::Submit. Applied to a 31-character draft it leaves zero characters. Meanwhile keystroke_bytes sends a literal \n, which is the one byte that makes a multi-line prompt in Claude Code.

    Cost to fix: one line, if the model stays single-line — and the real fix is rows, which is item 3.

  3. 3 A thousand words does not fit, and there is no way to make it fit

    measured At your tiled pane width, 968×1080: the composer grows to 356px, 27 rows at 9.5pt, and then stops. A 1,000-word prompt is 5,600 characters; 2,427 of them — 43% — are off-screen, reachable only by scrolling. Halve the pane height and it is 73%.

    Cost to fix: medium. Growing further needs a rule for what the composer is allowed to cover, which is a design decision and the fourth question in the grill.

  4. 4 Ctrl+C interrupts the agent, and Ctrl+Shift+C cannot reach the copy handler

    inferred bench_key is called at pane.rs:4662 and every path out of it ends in stop_propagation. The window's copy, cut and find handlers are at 4787, 4772 and 4779. On the workbench face they are dead code. Already filed as the composer copy issue.

    Cost to fix: small once there is a selection to copy. Without one there is nothing for the chord to do.

  5. 5 Ctrl+A then a click leaves the two sides holding different text

    measured Line::apply(Edit::Right) clears the selection bit. Line::seek — which is what a click calls — does not. Select all, click at column nine, type one character: the mirror holds "X". The far end received a caret walk to column nine and then a kill-to-end, so it is holding "alpha betX".

    Cost to fix: one line today; structurally it is the selection model, which is item 3 of the standard below.

Collisions

The workbench face is not a layer over the terminal. It is the same pane and the same key handler, and bench_key runs early and ends every path in stop_propagation. Anything it does not explicitly decline is taken, whether or not it has a use for it. That has already stranded one set of chords — the window's alt keys, fixed by adding window_chord above the gallery — and the same shape is live for the clipboard.

Three placements of the boundary

Every fix above is cheap or impossible depending on this one choice, so it is the only thing that has to be decided before work starts.

recommended

A · Widen the mirror, express every edit in arrows

Keep the pipe. Give Line rows and a selection range, and route every keystroke through one function that returns both the local edit and the bytes that make the far end do the same thing — using only arrows, backspace and literal characters, which is the set every line editor on the far end agrees on.

The mechanism already exists and is already trusted: bench_click turns a pixel into a column with the text system's own layout and walks the far end there with caret_move. Up-arrow, shift+motion and a selection replacement are the same operation with different targets.

What it costs you: it does not fix drift the agent causes on its own — a history recall, a completion accepted with tab. Those stay invisible, and the only honest repair for them is to read the agent's echo, which is a much bigger piece of work. It also depends on one unverified fact: that a left-arrow at column zero of the second row moves to the end of the first row in Claude Code's editor.

alternative

B · Own the draft; send it once

Nothing is typed through while you compose. The composer is an ordinary local document with rows, ranges, undo, the lot. On send, the whole draft goes down the pseudoterminal in one bracketed-paste write followed by a carriage return.

Zero drift, by construction — there is no second model to drift from. Every row in the standard table becomes an ordinary implementation job with no protocol question attached.

Genuinely better at: correctness, and the things that only work when you own the buffer — undo, a real find-in-draft, rectangular selection. What it costs: slash-command completion menus and history recall stop happening as you type, because the agent is not hearing you. Those are the two things the mirror was built for, and getting them back means asking the agent for completions over a side channel that does not exist.

alternative

C · Two modes, one expand gesture

The pipe stays for short lines. A gesture — the expand you are already asking for — opens a full local editor over the pane, which composes offline and pastes on send. The short path keeps completion; the long path gets the standard.

Genuinely better at: shipping. It needs no protocol work at all, and it directly answers the thousand-word case. What it costs: two editors with different rules for the same box, which is the exact thing this codebase's comments keep warning about — one table, one function, so the conventions can be asserted. A person will learn the short-mode rules and then be wrong in long mode.

Findings

The type-size ladder has never fired

measured COMPOSER_STEPS is [8.5, 7.25, 6.25] and COMPOSER_MIN_PT is 9.5. The floor is applied after the pane's gauge, so at the default gauge all three steps render as 9.5pt. The three-step shrink that exists to buy rows before scrolling buys nothing until the pane's text size is above 112%.

The floor is right — it is a claim about what the eye receives, and it survived the halving of the ramp deliberately. The steps are what is now wrong: they were halved to answer “smaller!” and halved past the floor that was meant to catch them.

Invalidation: if composer_pt(5600, 670, 356, 1.0) returns anything below 9.5, the floor is not being applied last and this is wrong. It returned exactly 9.5.

The caret follows the end of the draft, not the caret

measured follows(caret, len) is caret >= len. Edit at the end and the box scrolls to the bottom; edit anywhere else and it does not scroll at all. In a draft with 2,427 characters above the fold, editing paragraph one means typing at something you cannot see.

The comment defending this is about not yanking the view under a hand that scrolled deliberately, which is a real concern and a different one. Both are satisfied by scrolling to the caret's row rather than to the bottom.

Invalidation: if the composer's scroll container is already caret-driven somewhere outside composer_follows, this is fixed and the finding is stale. Grep for wb_slots.scroll — there is one writer.

Right-clicking the composer opens the terminal's copy tray

inferred The bench's mousedown branch is MouseButton::Left only, so a right-click falls through to ctx_menu = Some(pos). The tray that opens offers Copy and Paste, and its Copy calls copy_selection, which reads the terminal grid's selection — the face you are not looking at.

Invalidation: right-click the composer with text selected on the terminal face behind it. If the tray does not appear, or its Copy copies the draft, this is wrong.

Four of these are already filed, and one is stale

measured The rollup carries the copy chord, the home/end drift, the missing selection, the hidden-character count and the caret-above-the-fold case. The missing-selection one says Ctrl+A is unbuilt; it was built on 2026-09-18. Retitle it rather than closing it — the shift-motions and the copy half are still true.

What is yours to decide

1 · Where does the boundary sit?

A, B or C above. Everything else follows from it: under A the standard table is about fifteen small changes, under B it is one large one, under C it is both and a mode switch.

Recommendation: A. It keeps completion and history, the mechanism is already proven by the click path, and it converts a bug class into a function signature. Revisit if the multi-line arrow question below comes back wrong.

2 · Who wins ctrl+c on the workbench face?

Copy and interrupt both have a legitimate claim. Today interrupt wins silently, and copy has no gesture at all — not even ctrl+shift+c, because the bench consumes it before the window's handler runs.

Recommendation: copy wins, both forms. The interrupt keeps the strip's stop verb, which is visible and already built, and gains an explicit chord. An interrupt you have to aim at is better than a copy that cannot be performed.

3 · How far may the composer grow, and on whose say-so?

The ceiling is 33% so the box cannot eat the conversation it is replying to. That protects the resting state and punishes the case you raised. The choices: raise the constant, grow on demand with a gesture, or grow automatically while the draft is long and shrink back on send.

Recommendation: grow on demand, to 75%, released on send or escape. A constant cannot be right for both a two-word reply and a thousand words. An automatic grow moves the conversation under your eye while you are reading it, which is the complaint that produced the 33% in the first place.

4 · Is a thousand words in the composer the shape you actually want?

The alternative is that a long prompt is a document: opened in an editor, saved to a file, and sent as a path or a paste. The bench already accepts dropped files and pasted paths. This is the question upstream of every fix above, and it is the only one I cannot answer from the code.

Recommendation: both, and the composer first. The composer has to hold a long draft without losing it whatever else exists, because it is where the draft already is when it gets long. A hand-off to a real editor is the second thing, not the substitute.

Why a selection is two numbers

workbench.rs · Line::marked

What the boolean can say

Exactly one thing: the whole draft is selected. The comment in the source is honest about why — “there is no mouse drag over the draft and no shift+arrow here, so a range would be three states wide and only ever hold two of them.” That was true when it was written.

The cost shows up the moment a second gesture exists. A range has an anchor and a head, and the anchor is what makes shift+arrow repeatable: press it five times and the selection grows from the same place each time. A boolean has nowhere to put the anchor, so the fifth press cannot know where the first one started.

Why replacing a selection is the hard half

The far end also has to forget the selected text, and it has no idea a selection exists. Today's trick is elegant and narrow: ctrl+a has already moved the far end's caret to column zero, so one ctrl+k kills the rest and the replacement lands in the right place. It works because the caret position is known, not guessed.

A range generalises it without guessing: walk the far end's caret to the range's start with caret_move, then send (end - start) deletes. Arrows and deletes are the two things every editor on the far end agrees on, which is the same argument caret_move's own doc comment makes for not using home and end.

The one-line bug underneath

Line::apply clears the mark for every edit but the three that use it. Line::seek, left, right, home and end are public and do not. bench_click calls seek directly, which is how a click into a selection leaves the highlight up. Routing the click through apply fixes it and removes the second way to move a caret.

Why the composer is a mirror

the reasoning, and what it bought

The decision

From the source: “Everything else straight through, byte for byte. The echo comes back from the agent itself, which is why this needs no local editing model at all.” And beside it, the reason: “Slash commands complete, history works, ctrl+c interrupts, because the agent's own line editor is doing all of it. This is the difference between a text box that imitates a terminal and a person typing at one.”

That is a good decision and this brief does not argue with it. Typing /mod into the bench raises Claude Code's own completion menu, and nothing on our side had to know that menu exists.

What it already admits it cannot mirror

Two things, both handled deliberately and both worth noticing as precedent:

  • A pasted image. The agent writes [Image #7] — a number this side cannot know. So the mirror holds a count beside the text rather than inventing the string, and the composer draws a chip.
  • A dial change mid-draft. Sending /model opus would land on the end of your sentence. So aside_bytes erases the far end's line, sends the command, types the draft back and restores the caret — and it explicitly gives up on restoring a pasted image, because no retyping brings one back.

Both are the same move: where the mirror cannot be exact, say so in the model rather than guessing. The gestures in this brief are cases where it guesses instead, or does nothing and lets the far end move alone.

What would make the mirror exact

Reading the agent's echo and reconciling against it. The bench already scrapes the pane's screen for other purposes, and the mirror could be corrected from the line the agent actually drew. That is the honest fix for history recall and completion, it is well beyond the scope of these complaints, and it is the reason option A is recommended with its limit stated rather than sold as complete.

Method and limits

what this did not establish

What the method was

Source reading, plus the pure decision functions extracted by line range from workbench.rs and compiled standalone with rustc so they could be driven with a real corpus. That is the technique that turns “up-arrow probably does nothing” into “returns None in all twelve modifier forms”.

What it structurally misses

Nothing here was run in the app. No window was opened, no agent was launched, no key was pressed. Every claim about what the far end does with a byte is an inference from the protocol and from the agent's documented behaviour, not an observation.

Four things not established

  • Multi-line caret motion across the far end's newline. Option A assumes a left-arrow at column zero of row two moves to the end of row one in Claude Code's editor. If it does not, arrow-based caret walking cannot cross a line break and option A needs a different byte for that one case. The check: type a two-line prompt with shift+enter, press left at the start of line two, and watch where the block lands.
  • Whether gpui fills key_char under ctrl. If it does, ctrl+shift+c inserts a stray C into the mirror as well as interrupting. The talking branch checks only for control characters; types_a_character, which would have refused it, is not called on that path. The check: TD_KEYDEBUG=1 and press it.
  • IME and dead keys. No composition path was found and none was tried.
  • Whether the 33% ceiling is what you are hitting. It is the ceiling in the code and the arithmetic says a thousand words overflows it, but your pane's actual height was not measured. The check: the “N more characters above” line appears exactly when it overflows.

A confound worth recording

The first run of the geometry probe modelled the rail as 30% of the pane width, which is what RAIL_SHARE says. It is clamped to 208px, so at 968px the rail is 208 and not 290 — the composer is 670px wide, not 588. The first numbers were 7 points too pessimistic on the hidden fraction. Re-run with rail_fit's real clamp.

Extract and run

The decision functions are pure, so they can be lifted out and driven without building the app. From the repo root:

S=app/src/workbench.rs
sed -n '489,772p'   $S   # struct Line + impl Line

Concatenate those with a main that asserts the claims, then rustc -O --edition 2021. The whole probe compiles in about a second because it imports nothing.

What each claim's assertion is

  • Arrows: line_edit(k, ctrl, alt).is_none() for up, down, pageup, pagedown across the three modifier forms.
  • Shift+enter: line_edit("enter", false, false) is Edit::Submit, and the function takes no shift parameter — so no call site can distinguish them. Apply it to Line::holding(..) and read chars().
  • Click into a selection: mark_all(), then seek(9), then insert("X"). Read text().
  • Geometry: composer_hidden(5600, 670.0, 356.0, 1.0).
  • The dead ladder: map COMPOSER_STEPS through (s * 1.0).max(COMPOSER_MIN_PT).

In the app instead

The end-to-end harness runs the binary without a window and the bench smoke rig can only stage shells, so none of this can be photographed today on an agent pane. Both are open follow-ups. Until then the standalone probe is the only mechanical evidence available, and it covers the pure half.
