The agent channel

Decoupling the workbench from the terminal view · 2026-09-21 · built while you were AFK, in ~/Work/td-decouple on plan/workbench-decouple-async · every decision here is yours to overrule, and each one takes a note.

The workbench no longer reads the screen and no longer types keystrokes. It talks to the agent process through two journals in the pane's mailbox. A question now reaches the bench whole, before any picker paints, and is answered without one — measured against Claude Code 2.1.274 on this machine. The composer is a document: ctrl+c copies, shift+enter breaks a line, and SEND is one bracketed paste.

Verdicts

your crux

“Directly to the process” is a real difference — but not the one that first appears

The bytes reach the process down the same pipe either way: the pane's byte stream to the host, the only road to a pseudoterminal this architecture has. Nothing bench-related crosses the host wire (0 of 22 message variants, measured).

What changes is the unit (a message, not a key), the owner (the channel, not the key handler) and the record (a journal line, not a screen echo). Each was a defect: 51 grid-read sites and 14 pty-write sites in the bench, now one keystroke left (the image-paste chord).

recommended

The third cost: option 3, with the one impure verb kept and journaled

A question travels through a hook, whole. The answer travels back as a file the hook is waiting for, and the picker never paints. Where no hook is waiting, the same keys as before go through the same gate — and every one is a keys line in the journal with its bytes and its reason.

Cost: the boundary keeps one named impurity. Option 2 would have taken a working gesture away; option 1 alone would have kept the screen as the truth.

Findings

  • measured A PreToolUse hook can pre-answer AskUserQuestion in Claude Code 2.1.274. Driven under a pseudoterminal from this pane; the picker never painted and the model received the last option. The public hooks reference does not document this; the SDK's user-input page describes the same updatedInput.answers shape. Invalidation: if a later Claude Code paints the picker despite updatedInput.answers, the file road fails closed to keys and the journal shows released:answered followed by a screen cursor.
  • measured Nothing bench-related crosses the host wire. 22 message variants in hostproto.rs; none carry a surface, a question or a bench state. The channel therefore needs no host upgrade. Invalidation: a Request or Push variant naming the bench.
  • measured The old composer's divergences were structural, not bugs. 51 grid-read sites and 14 pty-write sites in the bench; line_edit took no shift; a click sent arrows. All three Gate 1 divergences (#614, #615, #540) are unreachable now because there is one copy of the draft.
  • inferred A multi-select answers with its labels joined by ", ". From the tool's own description of its result; not driven. Invalidation: a live multi-select round where the model reports a different join.
  • inferred A TD-launched agent presents its response before its Stop hook fires, so the hook's reply is dropped rather than doubled. Measured on one run's ordering; not across every harness.

Decisions that are yours

1 · Keep option 3 with the journaled keys road?

Gate 1's "third cost" had three answers. I chose the expensive one because the hook made it cheap, and kept the impure verb because taking a working gesture away in the name of purity is the wrong trade when the impurity can be made visible.

Recommendation: keep. If you want the pure boundary instead, the keys road is one match arm and the cards already draw when they are on it.

2 · ctrl+g as the composer's interrupt chord?

Readline's abort, unbound on the bench, one hand. The strip's stop control is the primary path; the chord is a convenience. Alternatives: alt+c, or no chord at all.

Recommendation: keep ctrl+g until a press tells you otherwise. It cannot end a session: it is one interrupt, journaled.

3 · Hold the picker only while the bench is the face on screen?

Switching tabs mid-question releases the hook inside four seconds and the picker paints; the card keeps working by keys. The alternative holds an agent's menu for a bench nobody is looking at.

Recommendation: keep. If you find yourself wanting a hidden bench to hold a question, it is one boolean in bench_beacon.

4 · Keep the hooks installed?

They are in ~/.claude/settings.json now, on five events, with a timestamped backup beside it. Every one exits 0 on any error; the only wait is gated on a fresh marker, and no running window writes one yet, so today they only journal.

Recommendation: keep. To take them out: scripts/install-agent-hooks.sh --uninstall. Your own askhook.log logger on the same matcher was left alone.

5 · Take the symlink to the new build?

The release is installed beside the current one and the symlink still points at td-7d41cb5-main, so nothing you open while away runs unreviewed code. The swap and the undo are each one line, in the install modal.

Recommendation: open one pane on the new build first, press ctrl+c in the composer, then swap.

6 · Next: move Bench out of the pane, after the tenancy key lands?

Frame D in figure 02. The 124 self.bench sites become one accessor over a window-level map keyed by the tenancy pane's ConvKey. It is the “decoupled workbench VIEW” in the structural sense, and it is mechanical now that the bench neither reads the grid nor types.

Recommendation: yes, one pane, after workbench-follows-the-agent merges — not before, or two agents are on one struct.

Why, in depth

Why files, not a wire

and why the host is untouched

The tempting pipe is the one already under the agent: the pseudoterminal. It is the wrong pipe for a record. A full-screen agent repaints, so anything carried in band arrives several times a second; the grid encoder runs in both halves of the client-server split, so an in-band change is a host change; and a host only upgrades by dying — on a machine with twenty live agents, that is the day.

The pane's mailbox already exists, every agent already knows its address from the environment the host stamped, and a hook is the agent's own child so it inherits that address for free. Two append-only journals, one answer file, one marker: everything an agent process and a window need to say to each other, with no version to negotiate on a hot path and nothing for the host to learn.

What a wire would have bought is latency: the sweep is one hertz, so a question reaches the bench up to a second after the hook writes it, and an answer reaches the hook up to 250 ms after the bench writes it. Both are inside what a person notices when choosing an option.

Method and limits

what this pass could not establish

  • The gpui key path was not driven end to end. The harness runs the binary without a window (#497, #586), so the composer's new keys are proven at the Line and line_edit level, and by the absence of any byte-writing call in the talking branch (a source scan), not by a photograph of a press.
  • One harness, one version. Claude Code 2.1.274 was driven once; Codex and Gemini were not driven at all.
  • The multi-select answer shape is inferred, not measured.
  • Nothing here was run inside your live window. The running build predates this work; the new build is installed beside it and not selected.
  • The hooks read a marker any process running as you could write. The threat this defends against is a dead window, not a hostile process; the mailbox was already writable by anything running as you, and this changes nothing about that.
