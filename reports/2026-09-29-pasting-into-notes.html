Pasting into Notes

A field on the note

the alternative to question 2

The note would carry "pictures": ["/home/parker/.local/state/…/pasted-1.png"] beside its text, title and ts. Old readers keep it: TD's reader carries fields it does not know untouched (the comment on NoteRef in notes.rs), and notes.js stores and writes back whole note objects.

The cost is that every reader has to learn it. A browser draws only text, so the picture vanishes there until notes.js changes, and it changes in agent-skills, then again in TD's two vendored copies. A note that is only a picture has empty text, which notes.js refuses to add and TD's reader has to special-case. And TD's map would print a picture line the browser's map does not, until both learn it, where today they match byte for byte and the fixtures hold them to it.

The line in the words asks nothing of any reader. Its costs are that it is text standing in for structure, and that a person can type one. TD draws only lines that point into its own folder, so a typed one stays words unless it names a real pasted picture.

Method and limits

what this page did not establish

Nothing here was built or run in a Terminal Delight window. The paste behaviour in figure 01 was read in the source of the current main branch (commit 53f476d) and not reproduced in a running window; slice one's pane test is where it gets reproduced. The key ladder's own test states the intent it breaks: a note being written takes every key "and not to the shell under the square, while the window's and the pane's chords still work". Ctrl+Shift+V is the one pane chord that writes into that shell.

Not tested: whether Claude Code turns a picture path inside a pasted map into an [Image #n] of its own. The plan does not depend on it; the agent opens the path with its Read tool either way.

Not measured: the local storage limit and whether every file opened from disk shares one storage. Both are how Chrome is understood to work. If either is wrong, option C's storage cost changes and its size cost does not.

The sizes in figure 05 are one machine's files: Parker's reports and screenshots. A different desk will have different medians.
