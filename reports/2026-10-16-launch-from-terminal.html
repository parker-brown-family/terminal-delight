Terminal Delight · Launch from this pane

Alt+A opens the same launcher.

Pick the agent from your terminal. TD prepares its instructions and starts it through the launch flow the Workbench already uses. The terminal stays in view.

One launcher, on either face.

Alt+A and the new ⌁ AGENT header button open the existing project, harness, model, effort and reach picker. Claude, Codex and configured local agents use the same briefing and execution code.

01Both controls join the existing flow

The new controls ask the workspace to open its launcher. That workspace still owns preparing the seed, quoting the command and starting the program.

02The prompt follows the face

Opening the launcher preserves the face you were using. When a brief later sends comments back, the terminal receives them as a prompt draft; the Workbench receives them in its composer. Press Enter when you are ready to send.

At a known shell prompt, the agent starts in that pane. If a program is running, or TD has not classified the pane yet, the existing launcher opens a new terminal tab. Unknown never means an empty shell.

03What was checked

Both complete Rust suites pass: 2,291 tests with the default core, 2,244 with the fallback core; eight existing tests are ignored in each. Formatting and lint checks pass on both cores. The two new launch regressions pass, and this page’s notes save and export at desktop and mobile widths.

The pane test presses Alt+A and clicks the rendered button on TERM and BENCH. It checks one shared event per gesture, the originating pane, unchanged faces and no Alt+A text reaching the PTY. The launcher now remembers the clicked pane before taking focus, so closing the picker returns typing to it.

Does this put launch where you expect it?

Use Alt+A, or ⌁ AGENT beside TERM/BENCH. Keep the shared picker and let the selected face decide where returned comments appear.
