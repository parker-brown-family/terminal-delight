Client-server split — Gate 2

The architecture is drafted and ready for your call: one binary, a per-session PTY host, and a GUI that becomes a mortal client driving a replica of the terminal it shows. Two of three judge lenses picked this shape; the third's objection dissolved under source verification. Five questions remain — they're at the bottom.

Read first

  1. 1

    The trunk

    A gpui-free host process per session owns the PTYs, the authoritative terminals, and all scrollback; the window attaches to it. Close a pane or tab and its processes die — that's intent. Close the window and nothing dies. One installed binary for both roles.

  2. 2

    The grid seam, cut where you asked for care

    The cut is at term::Session construction, not across the render path: all 33 grid-lock sites in pane.rs stay byte-for-byte today's code, running on a client-side replica. The host's grid is read at exactly one new point — the attach-time snapshot — and a divergence guard turns any encoder bug into a loud re-snapshot instead of a silently wrong screen.

  3. 3

    The race a judge caught, and the three-line repair

    The metric judge found a real byte-loss race in the attach splice and voted against the trunk over it. Verification against the vendored alacritty source settled it: FairMutex::lease() taken in the same order as the PTY reader closes the race without touching the stock event loop. The dissent conceded the flaw was repairable; it now is.

  4. 4

    What was refused as unfunded

    Unifying write-gating across all surfaces, closing the push-feed gap, retiring per-pid sockets, server-side layout — all proposed by the losing sketches, all cut because the metric never asked for them. Layout stays a client-owned versioned blob, which keeps the left-bar overhaul (#319) free to grow without a wire break.

  5. 5

    The five questions

    Second-attach policy, the numbers that gate the default flip, tear-off semantics in v1, host supervision, and whether MAX_PANES stays a GUI constraint. Each carries a recommendation; nothing else in the doc waits on you.

Your call

1 · Second attach to a live session: steal, refuse, or allow N?

Two explicit $TD_SESSION launches, or a relaunch racing a half-dead previous client. Refusal can block the headline kill-relaunch case behind a stale connection; allowing N quietly ships unpoliced multi-attach.

Recommendation: steal, tmux-style — the new attach wins and the host drops the old connection. Keeps multi-attach a one-line policy change later.

2 · What numbers gate the default flip?

The two unmeasured bets above need pass marks, set now rather than negotiated at the flip.

Recommendation: input-echo p99 within 1 ms of today; no visible lag at 8 panes under a cat-flood; survival script green at N=20 cycles including the host-kill leg. You sign the measured numbers, not a promise.

3 · Tear-off keeps today's respawn semantics in v1?

A torn-off pane would still respawn-and-type in its new window, losing that pane's scrollback at the moment of tear — exactly as today. Attach-by-id tear-off becomes clean once pane ids exist.

Recommendation: yes for v1 — taking it now widens the riskiest slice for a case that already behaves acceptably.

4 · Host supervision: bare setsid in v1, systemd --user later?

The metric needs nothing beyond setsid — lingering is already enabled, so hosts survive logout today. A socket-activatable user unit would add boot-start and restart-on-crash.

Recommendation: setsid for v1; the unit is a follow-up worth having and not worth coupling to the flip.

5 · Does MAX_PANES=8 stay a GUI constraint?

The cap is a window-layout constant. A host session need not share it, and tabs-as-tasks (#319) may want more panes per session than one window shows.

Recommendation: yes — the host takes only a generous sanity cap, 8 stays client-side. Costs nothing now and keeps #319's shape free.

The architecture in full

02-architecture.md · docs/plans/client-server/ · live tree

Processes

One installed binary. terminal-delight serve --session <id> is a gpui-free, setsid-detached host, one per session: it claims the session flock via the existing instance::claim_in for its lifetime, owns PTY masters and child trees (spawn code moved verbatim from term.rs), runs stock alacritty EventLoops over an authoritative Term per pane, runs the 800 ms mode watcher and session::capture where the PTYs live, and is the single TOML writer — shrink guard, .last-good, rotated backups intact. GUI windows, scratch/demo/seeded windows, and the six headless verbs are unchanged in kind; scratch windows keep the serverless spawn_in path, which is never deleted.

The seam

attach_in beside spawn_in: a SocketPty adapter implements alacritty's public EventedReadWrite/EventedPty traits, so the stock EventLoop drives a client-side replica Term over the socket. styled_lines, hit-testing, selection writes, scroll_display, and the FOCUS generation-keyed cache remain today's code on the replica. The host grid is read at one new point — gridwire.rs, the attach-time snapshot encoder (scrollback + screen + cursor + modes + alt screen re-emitted as VT bytes), pinned by round-trip property tests over the existing headless VTE matrix before any GUI wiring.

Attach atomicity — the lease repair

Verified against the vendored crate: alacritty's pty_read holds a FairMutex lease (next-slot) for its whole cycle and leaves zero unparsed bytes at every non-error exit. A handler using plain lock() can therefore lose bytes read before tee-registration but parsed after the snapshot — the race the metric judge caught. The repair: the attach handler takes lease() then the data lock (the same order as pty_read, so no deadlock), snapshots, registers the tee, releases both. Every byte is then either in the snapshot or tee'd — never neither, never both. The invariant is documented as the tripwire re-verified on any alacritty upgrade; a host-owned drain loop is the named fallback if the divergence guard ever fires in anger.

Wire

$XDG_RUNTIME_DIR/terminal-delight/session-<id>.sock, 0700 dir, flock-guarded — stale-socket and pid-recycling hazards structurally gone. NDJSON control verbs (hello with proto version, list/spawn/attach/resize/close-pane, save, shutdown, mode/exit pushes) with truthful per-target outcomes; one raw byte-stream connection per pane; resize never rides the byte stream; SO_PEERCRED at accept and nothing else. The dozen verbs live as a one-page versioned contract under docs/protocol/, conformance-tested against the document. A protocol-version break degrades gracefully: host checkpoints and exits, TOML recovery runs — exactly today, once, deliberately.

Ownership and recovery

The host's live pane table beats the TOML. resolve_session gains a first-ranked tier: a live host socket with no attached GUI — "your work is still running" is what relaunch finds. Any live pane the loaded layout doesn't claim is adopted into a new tab on attach, so a checkpoint-stale layout can never lose a running pane (pinned by a test). SavedNode gains pane_id: Option<u64> — absent means pre-split file; unknown is not zero. Host crash lands on today's respawn-and-type path, proven by the harness's host-kill leg.

The seven grafts

  1. #314 dispatch allowlist + pinning-test rewrite as slice 0 — ships alone, kills the phantom-window class immediately.
  2. The written protocol contract under docs/protocol/, conformance-tested.
  3. The survival harness built at the opt-in stage: sentinel scrollback + live vim and htop, kill -9 the GUI, relaunch, assert everything, N cycles, losses = 0.
  4. A host-kill leg in the same harness — recovery must be exactly today's.
  5. The divergence guard: grid hash host-vs-replica at generation quiescence; mismatch forces a loud re-snapshot.
  6. Schema-versioned layout envelope (#319-proof), idle backoff on detached hosts, and ctl resolution reading TD_PANE_ID before the /proc walk (shrinks #215).
  7. The generation-stamped grid.frame read-verb shapes filed as the named post-v1 door to presenting beyond a classic terminal UI — addable on the authoritative Term without re-cutting the seam.

The seven forks

divergence only — agreement is on the main page · full record: research-gate2-panel.md

A · The grid seam

Replica Term (minimal motion) vs server-side Term behind frame pulls (protocol first) vs styled-content deltas (state first). The replica keeps all 33 read sites untouched at the cost of a second Term per pane and a new snapshot encoder; frame pulls have the fewest places to lose a byte but reroute the whole render path onto unmeasured pull latency; deltas avoid the per-frame wire bet but put damage-to-history bookkeeping on the hot path forever — the confident-wrong-screen failure mode. Judges 2–1 for the replica, and the dissenting objection was the race settled in fork B. The failure polarity favours the replica: its bugs show a wrong screen loudly and re-snapshot; a rerouted read path fails everywhere at once.

B · Attach atomicity

A factual dispute, not a taste one — all three judges were partly wrong about the fix, and the synthesis settled it by reading event_loop.rs and sync.rs in the vendored crate. The lease repair (see the architecture modal) closes the race in ~3 lines with the stock EventLoop kept; the two harsh repairs the judges proposed (host-owned read loop, abandoning the stock loop) are unnecessary and stay named as fallbacks.

C · Daemon granularity

Per-session hosts vs one per-uid daemon. One host crash loses one session to the TOML floor; a daemon crash holds every session. No judge defended the singleton on metric grounds; discovery stays simple because the socket is keyed by session id and guarded by the flock.

D · Binary shape

One fat binary with a serve verb vs a client/server pair. The pair lets a stale GUI never kill sessions — and doubles the stale-artifact skew class that caused the phantom-window morning. One binary, serve string-matched before the flag gate, version-checked at hello.

E · Write-gating scope

The losing sketches fold the ctl/MCP gate unification (#308) into this feature; the restraint lens scores that as scope the metric never asked for. The new surface adopts truthful per-target outcomes; existing surfaces keep their policies; #308 stays its own ticket.

F · How much cleanup rides along

Push-feed closure, per-pid socket retirement, server-side layout — all unfunded by the metric, and server-owned layout is the one option that grazes the binding "#319 must not get harder" constraint. Kept as gaps, filed as follow-ups at tie-off. One item grafted anyway because every lens asked for it: the written contract doc.

G · Second attach

The panel split between silently allowing N attaches and refusing with the holder named. Neither is right — one ships unpoliced multi-attach, the other can block the headline relaunch on a half-dead connection. Became decision question 1, with steal recommended.

Method, limits, migration

what this page's claims rest on

Method

Three sketches written blind to each other from different priors, each required to cite real files and answer the recon's 11 questions; three judges, each scoring all sketches through one lens (metric fit, migration risk, reuse/restraint); one synthesis that collapsed agreement, expanded disagreement, and re-verified load-bearing claims against the live tree and the vendored alacritty 0.26 source — the 33-lock-site count, the public trait seam, the FairMutex lease semantics, and the instance.rs contracts were all checked fresh during synthesis rather than trusted from the recon.

What the method misses

  • No code ran. The two performance bets (dual-Term cost, input-echo latency) are named, bounded, and deferred to slice-3 measurement — not estimated.
  • Judges scored prose, not prototypes; a sketch can be persuasive and wrong. The property tests and divergence guard exist precisely because gridwire.rs is new, defect-prone code.
  • The synthesis settled fork B by source reading; that reading is itself the kind of claim a Gate 3 reviewer should re-derive before the attach handler is written.

Migration slices (Gate 4 will refine)

  1. Slice 0 — #314 allowlist + pinning-test rewrite. Ships alone.
  2. Seam prep, zero behaviour change: SocketPty, attach_in, gridwire + round-trip tests, SavedNode.pane_id.
  3. The host: serve verb, pane table, socket, verbs, lease-fenced snapshot-then-tee, headless integration test, contract doc.
  4. GUI attach behind TD_SESSIOND=1 — harness built here, measurements taken here.
  5. Persistence redirect + orphan adoption.
  6. Default flip, gated by the harness numbers Parker signs.
  7. Tie-off: follow-up issues for the push feed, #308, tear-off attach-by-id, per-pid socket retirement, the grid.frame door.
