Named Orgs

The selected pane’s response currently fills the side of Warroom. Remove that panel and give the chart a name, with controls to create another org and choose its panes.

The chart gets its space back

Your screenshot shows compact pane cards beside a full agent response. Selecting a card should leave room for the org itself. The response panel disappears; selection keeps a highlight and a short action row.

The name belongs to the org

An org can contain panes from different projects. A project or tab rename does not rename the org. Choose an org, then add available panes to it. Search still finds panes across every org and offers Open org beside a match elsewhere.

Being in an org grants no access by itself. The lines you draw continue to say who can see, read or ask whom. Removing a pane uses the current unseat behavior, which removes its connections and returns it to the available list.

Choose the membership rule

I recommend one org per pane for this first version. That gives each pane one place to find its connections. A shared pane appearing in several orgs would need a rule for which chart owns those connections.

Approve the named-org layout?

Recommended: remove the context panel, add create and rename controls, use one org per pane, and preserve the current chart as an unnamed org.

The build will cover saving and reopening orgs, membership, global search, and the existing connection controls. No implementation code has changed yet.

Implementation order: remove the panel → add orgs and labels → verify restore and connection rules. Implementation plan.
