Why one file and not a directory

The directory form (<root>/<seq>/surfaces/*.json + turns.jsonl) was designed so a surface re-presented under one id could be overwritten in place. That buys one thing — a smaller store when an agent updates a card many times — and costs three: a loader that walks segments, a record split across files that can disagree, and a conversation you cannot hand to anyone as one object.

In the file form a re-presented surface is a new said line with the same id, and the loader keeps the latest per id — the same rule load already implements across segments. Size is bounded by the same retention slice 6 owns. A conversation is one file: cat, tail -f, jq, a phone, an issue attachment.

What the file form gives up: nothing measured. The mailbox stays the wire; the agent side is unchanged; the twenty store tests re-target the file with the same assertions.

Why system notifications are kept

Claude Code fires UserPromptSubmit for automated turns too — task notifications, wake-ups — and the hook cannot tell them from a person's message; both arrive as prompt. Your own mailbox (surfaces/attention/4/inbound.jsonl) holds a <task-notification> recorded at 12:55 as a prompt.

Two wrong fixes: drop them (a transcript with holes, and the agent's next reply answers a prompt the file never saw), or show them (an overview of turns that reads like a log). The file keeps every record and marks kind: person by default, system when the text opens with the harness's own envelope. The overview draws only person; the card still shows the reply. A prefix rule is crude, so it is a table in one place with a test per envelope, and an unrecognised envelope reads as person — the safe direction is to show too much rather than hide a question you asked.
