Truth rules

Shell is not idle agent

Classify pane kind separately. A shell, a known agent, and an unknown pane are different observations.

Unknown is visible

A known agent with unknown state receives a neutral unclassified row. It never becomes an idle dot.

Evidence has an address

Every item carries a reason, source, and observation time. If any are absent, the row says so.

Counts stay narrow

The red count covers decision, failure, and finished-unseen rows. Unclassified has its own neutral marker.

Review does not guess

No authoritative diff, check, or artifact source means unavailable. It does not mean zero.

Open preserves the wall

The normal interaction overlays the panes. Reserving width is an explicit pin action on a wide display.

Challenge these

Where does “project” come from?

Tab groups exist; an authoritative project label may not. Inferring from a path can be wrong.

Proposed: explicit metadata when present; otherwise show unknown project.

How should unknown affect the edge?

Counting it as urgent creates noise. Hiding it recreates false confidence.

Proposed: a neutral unclassified marker, separate from the red handoff count.

When is finished work review-ready?

The bell proves unseen completion. It does not prove a diff, checks, or artifacts exist.

Proposed: finished-unseen enters the queue; the tray exposes only evidence backed by a named source.

How long does “seen” live?

The current finish acknowledgement is enough for the tracer bullet. Restart persistence is a separate product choice.

Proposed: reuse current acknowledgement first; revisit only after observed misses.

Prospective contracts

Planning signatures only

Pane truth

enum PaneKind { Agent(AgentKind), Shell, Unknown }
enum AgentState { Working, Blocked, Error, Finished, Idle, Unknown }

Origin

struct Origin {
    project: Option<String>,
    group: Option<String>,
}

Attention projection

enum AttentionKind { Decision, Failure, ReviewReady, Unclassified }

struct AttentionItem {
    pane_id: PaneId,
    origin: Origin,
    kind: AttentionKind,
    reason: String,
    observed_at: Option<Instant>,
    evidence: Vec<EvidenceRef>,
    seen_at: Option<Instant>,
}

Optional fields stay optional through the model. Rendering decides whether they appear as “unknown” or “unavailable.”

Version-one boundary

Read-only attention surface

Inside

  • Observe live pane and bell state.
  • Project handoff rows in a fixed order.
  • Show compact origin, reason, time, and evidence availability.
  • Focus an existing pane and open an existing evidence surface.

Outside

  • Sending prompts or answers.
  • Retrying or stopping agents.
  • Creating worktrees, merging, shipping, or managing tasks.
  • Risk scoring and a standalone provenance explorer.
  • A full diff renderer in the narrow rail.

Measurement protocol

Same events, two navigation methods

Fixtures

Prepare one two-pane and one eight-or-more-pane session. Seed decision, failure, finished-unseen, working, idle shell, known-agent/unknown-state, and unknown-pane-kind observations. Keep event order and timestamps fixed across both runs.

Control

Use current Terminal Delight. Start from the same tab and identify the next pane requiring judgment by manual visual sweep.

Candidate

Use the collapsed spine and expanded queue. Start from the same tab and identify the same pane.

Record

  • Milliseconds to the correct pane.
  • Unrelated panes opened.
  • Known attention events missed.
  • False attention rows.
  • Unclassified observations.
  • Whether the visible project:group was sufficient.

Decision

Ship only if known attention remains lossless, unknown remains explicit, the overlay preserves pane geometry, and unrelated pane openings fall. Preserve the raw results; do not coerce missing measurements to zero.
