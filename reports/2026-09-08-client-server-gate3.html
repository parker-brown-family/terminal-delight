Read first

  1. 1

    The shape of the design

    Two new modules carry the split — host.rs (the session host runtime) and hostproto.rs (the wire, shared by host and client) — plus gridwire.rs for snapshots and the divergence guard. term.rs splits its spawn in two without deleting anything; pane.rs gains an attach constructor; the render path is untouched.

  2. 2

    The vim-eater, caught on paper

    The drafted snapshot encoder claimed a "verified" trick for reading the hidden primary grid under vim. The existence verifier read the vendored source and proved the opposite: one encode would have erased vim's live screen on the authoritative terminal. It's redesigned — read-only by type, healed by a re-snapshot when vim exits — and this brief exists partly so you see the process catching real bugs before code does.

  3. 3

    The wire, in one glance

    Nine NDJSON verbs, every write answered with a truthful per-target outcome, one raw byte stream per pane, uid check at accept and nothing else. The protocol lives as a one-page versioned document that the tests are run against — the document, not the implementation.

  4. 4

    The metric is a script before it's a feature

    The survival harness includes a self-test: run against today's build it must report losses == cycles, or the harness itself is broken. The host-kill leg proves "degrades to exactly today" by field-for-field diff against a recorded control, not by argument.

  5. 5

    Eighteen least-confident decisions, numbered

    The honest tail of the design — each one a call worth challenging now, while changing it costs a sentence. Two are yours and appear below; the rest are engineering bets with named fallbacks and the tests that decide them.

What verification changed

contradictedThe alt-screen encoder, redesigned

The draft reached vim's hidden primary grid by flipping alacritty's screens twice and called the flips neutral, "verified against source." The verifier's reading: the mode bit toggles unconditionally (term/mod.rs:732), so the second flip runs the destructive branch and its reset erases the live alt grid — a running vim wiped by the act of attaching to it. The redesign takes the terminal by shared reference (mutation impossible at the type level), paints only what is readable at attach, and heals to full scrollback the moment the pane leaves the alt screen, with the divergence guard as backstop. Nothing is ever lost host-side; the trade this makes is question 2 below.

measuredFour regression classes gained tests

The coverage verifier found four binding behaviours no test asserted, each now named in the plan: the host really is its own session leader (kill -9 sends no SIGHUP, so a setsid failure would pass every other test and die on a real logout); a CLI hello never steals the window's attachment (every launch probes with CLI-kind — if it stole, every launch would detach the live window); vim's terminal queries get answered exactly once with the generation counter still advancing; and detached hosts back off their polling so a fleet of headless sessions isn't the new battery drain.

measuredNo graft drops between gates

The design now carries a follow-ups section committing the deferred work to falsifiable issues at tie-off — the structured-read door for presenting beyond a classic terminal UI, the push-feed gap, the write-gating unification, tear-off attach-by-id. Refused as unfunded stays refused; forgotten is no longer possible.

Your call

1 · Approve Gate 3?

The signatures honour every Gate 1–2 decision including cap-4 with legacy layouts loading whole, and the two adversarial passes have already been folded in. Approval opens Gate 4: the slice plan, then code.

Recommendation: approve. The riskiest mechanism in the design was falsified and repaired before a line of it exists — that is the gate doing its job.

2 · Attaching to a pane that's inside vim: accept the delayed scrollback?

After a GUI kill, a pane sitting in vim reattaches showing vim perfectly — but the scrollback behind it stays empty until vim exits, at which point it heals in full. The alternative is forking the vendored terminal crate to expose the hidden grid.

Recommendation: accept for v1 — nothing is lost, visibility is delayed for exactly the panes that can't show scrollback anyway, and it keeps alacritty stock. The fork stays available if the heal feels bad in practice.

3 · The window that loses a steal: freeze or auto-close?

When a new attach supersedes an old window, the loser's replicas go dead and its saves go inert. The product gate said no new UI, so the design freezes it — but tmux-style steal arguably feels like the old window should close itself.

Recommendation: freeze in v1, judge it in the flesh at the Gate 4 demo — auto-close is a one-line policy change once you've felt both.

4 · Straight into the slice plan on approval?

Gate 4 is the slice plan (the migration ladder from Gate 2, refined against these signatures: slice 0 ships the phantom-window fix alone), then one slice at a time, each proven before the next.

Recommendation: yes — draft 04-slices.md immediately on approval and bring it with the slice-0 diff ready to go.

The wire's verbs

hello (proto version + kind — only a GUI-kind attach can steal) · list-panes · spawn-pane · attach-pane · resize (never on the byte stream) · close-pane (SIGHUP, the intent verb) · save (opaque schema-versioned envelope — #319-safe) · shutdown — plus mode/exit/detached pushes. Every write reports a per-target outcome; a garbage line gets an error reply, never a fall-through.

Call stacks specified

Attach (resolve → probe → hello → per-pane fenced splice), keystroke (client → byte stream → host PTY), close-pane, app-quit (disconnect only), host-crash recovery (TOML floor), and slice-0 dispatch — each written top to bottom with real function names in the doc.

The test plan, grouped

~100 tests named before any exist · full list in the doc

Slice 0 — dispatch

Six tests: known verbs dispatch, an existing directory reaches the window (the reserved open-here), an unknown positional exits 2 (the #314 pin, rewritten), flags unchanged, a typo'd verb leaves no window AND no disk writes, serve without a session id refused.

Wire conformance

Round-trips, additive-within-major versioning, version mismatch naming both sides, the protocol document's own examples deserializing, and a schema assertion that no verb carries identity — auth stays in the transport.

Host integration

Spawn-and-tee round trip, env stamping visible in /proc, the splice-under-flood test that keeps the judge-found race dead, steal drops the previous holder, SIGHUP kills truthfully while disconnect kills nothing, the opaque-envelope save preserving unknown future fields, shrink-guard honesty, checkpoint with zero clients, flock-ordered teardown, the two-serve race, session leadership (setsid), CLI-never-steals, backoff.

Gridwire properties

Round-trips over plain scrollback, SGR/wide/zerowidth extremes, the alt-screen heal path end to end, encode-touches-nothing (read-only at the type level), the 100-iteration fence property (no byte in both, none in neither), re-snapshot convergence, NotYet is not a mismatch, query replies answered exactly once with generation still advancing.

GUI attach + persistence

Live-unattached host beats newer TOML, explicit session wins every tier, orphan panes land in a new tab, dead pane ids fall back to respawn recipes, legacy over-cap layouts load every pane while new splits enforce 4, saves route to the host and never write locally when attached, stamped seat resolution beats the /proc walk.

Harness + flip gates

The echo-latency bench (p99 within 1 ms, flood at 0 and 8 panes), gui-kill × 20 cycles asserting pids unchanged and sentinel scrollback found, the floor-control self-test (today's build must read losses == cycles or the harness is broken), the host-kill leg diffing recovery against a recorded control, and the legacy 8-pane flood stage.

Method, limits, open bets

what this page's claims rest on

Method

Four domain drafts written in parallel against the live tree and the vendored alacritty 0.26 source, each required to cite file:line for anything it builds on; one integrator resolving cross-domain signature conflicts to a single vocabulary; then two adversarial passes — existence (22 checks: symbols, traits, line numbers, compile-plausibility) and coverage (23 checks: every binding decision and every Gate 2 graft traced into design and test plan). The run survived a usage-limit interruption and a session restart mid-flight; the resume replayed the finished agents from cache, so the verifiers ran over the identical integrated text.

What the method misses

  • Nothing has compiled. Signatures were checked for plausibility against real types, not by rustc — least-confident 10 (the polling-crate registration) is flagged as exactly the first thing the attach slice must compile.
  • The two performance bets are unchanged from Gate 2 — dual-Term cost and input-echo latency — measured at the opt-in slice, gating the flip on numbers you sign.
  • The verifiers checked the design against the source; they did not run vim. The alt-screen heal's visible flash is unmeasured until the attach slice exists.
