Terminal Delight · overnight security tests · 25 October 2026

Permissions after change

An agent asked a question, then its relationship was removed. The old build still handed back the stored answer. The new tests reproduce that failure and check that the answer stops at the changed permission.

MeasuredDevelopment release 0.5.0

01What crossed the boundary

The War Room gives each pane a seat and grants communication through directed relationships. A copy is a separate read-only agent started to answer a question from an existing conversation. Testing permission changes found five defects: stored answers survived a removed relationship; organisation moves retained copies and permission cards; a queued write trusted an old “own pane” flag; a negative target ID redirected a note to the caller; and a queued search used a revoked relationship to read scrollback.

The fixes use the existing permission system. Organisation moves clear requests in both directions. Relationship edits cancel copies for that direction. A consumed bypass still pays for its one admitted question, while current global policy and pane identity remain binding. Read-only agents can still answer questions. Queued searches now carry the verified caller and check its current read permission before reading the grid; the original snapshot still limits which results may be returned.

02What real callers could do

The next check launched six synthetic agents in a hidden native window and sent requests through the public MCP stdio relay and Unix socket. Each pane printed a distinct canary. Successful writes were checked on the receiving pane; denied writes were followed by a read to establish that the note had not changed.

Two further windows ran simultaneously for six manual cross-window assertions. Spoofing the other session’s environment did not redirect the relay. Forging the other window’s pane identity did not grant a write, and the original notes remained intact. All twelve mock agents and both windows exited after the probes.

The native run also found the target-ID bug. JSON parsing had collapsed an invalid value into absence. Both note and deliverable tools now reject an explicit malformed ID before mutation; omission still selects the caller’s pane.

03The retained checks

45 native assertions passed. Rio: 2,852 tests passed. Alacritty: 2,799 passed. All five separately invoked OS-isolation tests passed. Formatting and strict Clippy passed for both cores. The normal suites each report 17 ignored tests; five of those were exercised separately.

Six new automated tests cover the failed boundaries, late completions, pending approvals, unchanged positive controls, directional cancellation, spent bypasses malformed targets and queued searches after permission changes. Full-suite runs cover Rio and Alacritty, the two terminal engines the app supports. The separate Restricted tests exercise the operating system boundary against actual files, sockets, processes and network attempts.

The pre-fix tests fail at the retained-answer, retained-copy and stale-own-flag assertions. The malformed-ID regression panics if the invalid request reaches mutation. The queued-search regression proves that a real PTY canary remains readable after the snapshot’s grant is removed on the old code, then is withheld after the fix. These are the checks to run first if disputing the findings.

04What this establishes

The changes target dev/0.5.0 through the communication-permission fix; its checks and merge status are recorded there. The daily window has not been restarted: its saved layout omits recoverable panes, so the preservation guard remains in force. Testing a candidate, installing it for a later launch and activating it in the daily window are separate steps.

This battery checks the implemented MCP and War Room paths with synthetic processes. It does not establish that an unrestricted process running as your Unix user cannot read your files directly. These runs did not call real Claude or Codex models, so they do not settle whether a Codex copy’s helper agent inherits its sandbox. They also do not qualify several conversations hosted by one agent process, or the unfinished feature for assigning tasks to existing agents. Those existing follow-ups stay open.

The copy revocation prevents subsequent result delivery. It cannot take back an answer already read, and it does not terminate a copy that was already running. The release still needs sustained daily use and its planned candidate hold. The retained tests make these particular failures repeatable when the code changes again.

The test design uses OWASP’s authorization guidance for repeated permission checks and OWASP’s MCP guidance for untrusted tool arguments. No outside runtime or copied implementation was added.
